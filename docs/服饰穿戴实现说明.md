# 服饰穿戴

## 入口与功能

- 外层图片创作的“模特换装”改为“服饰穿戴”，保留 `model-outfit` 技能标识及原地址，旧任务可读取。
- 商品工坊 → 内容创作增加“服饰穿戴”，与图文、视频切换。中间是任务列表，右侧是独立操作栏。
- 最多 6 张服装、鞋包或配饰图片，横向排列，支持上传和素材库选择。
- 模特库已导入公开目录的全部 25 张基准模特图，保存在本地，校验格式、尺寸和 SHA-256。另有 AI 生成和自定义上传入口。
- AI 基准模特支持性别、年龄、外观、体型及额外描述。生成单独报价，完成后由用户选择，不自动发起穿戴请求。
- 支持 7 种预设场景、自定义场景、多选及每场景 1–4 个不同姿态；数量明确计算为场景数 × 姿态数，受系统批量上限约束。
- 支持 3:4、1:1、9:16 及 1K、2K，依照启用模型的实际配置展示。
- “AI 推荐”仅在图片生成提示词中优化机位、灯光与搭配，不隐含调用其他分析服务。

## 数据与真实执行

新增 `wear-draft`、`wear-job` 文档。外层使用 `global` 草稿空间，商品工坊按商品 ID 隔离。每次接单保存所选服装、模特、场景、姿态、要求、模型及商品修订快照。

两阶段都复用已有价格服务、余额检查、幂等接单、媒体 Worker、供应商任务查询及费用补查，没有新增模拟完成分支：

- `model`：使用现有真实图片生成技能制作单张人物基准图。
- `outfit`：使用现有换装技能，每项只传所选商品图和一张确定模特图，按场景和姿态输出独立图片。

接单前核对草稿与商品修订，篡改或过期计划拒绝提交。提交不明时保留原幂等凭据，禁止自动重发。普通技能草稿、图文草稿、视频草稿均不被穿戴任务覆盖。

基准人物、服饰细节和姿态的生成一致性需要根据实际成品检查，不承诺与参考服务的专有模型效果完全相同。

## 接口

| 接口 | 功能 |
|---|---|
| GET `/api/wear/library` | 本地模特与预设场景 |
| GET / PUT `/api/wear/:scope/draft` | 按修订读取、保存独立草稿 |
| POST `/api/wear/:scope/plan` | 基准模特／穿戴计划与真实报价 |
| GET `/api/wear/:scope/jobs` | 分页任务与素材 |
| POST `/api/submit` | 复用真实接单，扩展可选 `wearContext` |

## 资源维护

执行 `npx tsx scripts/import-wear-models.ts` 可重复同步公开系统模特目录。脚本不会访问用户私有收藏，不携带登录凭据，不调用参考网站的付费生成服务。内部来源与校验清单保存在 `resources/wear-models.json`，前端只展示“模特 XX”。

## 验证记录

- 7 项穿戴测试覆盖全部模特的本地导入、逐场景姿态与输入映射、独立人物生成、快照与幂等、无效／过期输入、会话与修订，以及真实 Worker 的输入格式和结果保存。
- 媒体 Worker 联调使用隔离测试传输与文件，不代表已进行付费供应商出图验收。
- 浏览器在独立端口、独立数据目录检查 1280／1440／1920 布局、模特库加载、AI 生成表单和商品内容类型切换；回到穿戴后原要求与所选模特正确恢复。
- 前后端生产构建输出到独立临时目录，不覆盖运行中主服务的构建产物。
- 截图保存在 `output/playwright/wear-*.png`。隔离验收环境没有供应商密钥，余额查询返回未配置状态，生成按钮保持禁用。
