# 算力统计页面重构

2026-10-29。按用户提供的截图重构 `/usage`，使用现有深色侧栏、靛蓝主题、统一字体和 shadcn/Radix 组件。页面以实际操作为主：进入即可看到整个账户消费趋势和明细，不需要先选模型、密钥或点击查询。

## 已实现

- 全局顶栏常驻账户共享算力余额，带手动刷新及统计页入口。余额来自供应商 `/v1/skills/balance` 的 `balance`；密钥额度与余额分别处理，不跨密钥求和。
- 页面只有一张每日净消费曲线、一张消费明细表；支持近 7 天 / 近 30 天切换，期间消费、调用次数及已退款信息行内展示。
- 明细默认每页 10 条，展示提交时间、模型、供应商任务号、状态、净消费与退款；支持翻页、复制任务号及导出本页 CSV。
- 单把密钥的额度、权限与详细配置移至系统设置的“API 密钥信息”。任务和模型查询可选择四把已保存凭据，前端只收到已配置状态。
- 账户余额、曲线和表格每 30 秒自动刷新，重新聚焦窗口和任务状态变化后刷新。隐藏窗口暂停定时刷新。失败保留上次可用结果并提示更新失败，缺失费用保留待确认状态。

## 数据与实现

账户接口使用固定 `scope=user`，包含同账户全部 API 密钥，按北京时间自然日统计。浏览器不能通过指定模型或凭据缩小此范围。认证使用本机一把已配置的账户密钥，凭据仍只在后端解密。

新增 GET `/api/account`、`/api/account/usage?days=7|30` 和 `/api/account/records?days=7|30&limit=10&offset=0`。后端短期合并并发查询；余额缓存 2 秒、消费缓存 10 秒。曲线先完整分页读取再按日汇总；超过 2000 条记录时改查逐日完整汇总，不从被截断的第一页画图。未知费用是曲线缺口，不推断为零。

账户余额包含网页端及其他密钥动账；消费接口仅含开放 API 记录，页面注明这一口径。供应商的 `cost` 已扣除退款，不再次减去退款金额。曲线表示每日消费，不推算无法核实的历史余额。
