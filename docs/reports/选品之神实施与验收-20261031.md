# 选品之神实施与验收

日期：2026-10-31。范围：商品工坊新增商品研究工作区、抖音采集助手与既有生成器连接。

**状态：核心功能已实现，真实研究与方案编排已完成；真实抖音采集和新增媒体成品尚未验收。最终构建和222项测试通过，前后端已重启；独立修复复查结论见第5节。** 本报告不是完整生产可用性认证，也不证明销量、转化率或进货价值。

## 1. 已实现的行为

| 环节 | 当前实现 |
| --- | --- |
| 商品入口 | 商品内导航为“选品之神／产品编辑／内容创作／爆款复刻”；通常进入商品默认打开研究区，明确指定的原工作区直达链接保留目的。浏览和采集完成均不自动付费分析。 |
| 快速分析 | 自有商品图由用户选择；同行采用稳定 ID 的纯图片分组，没有名称、备注输入。至少一组、每组至少三张不同图片；存在不完整组时明确拒绝，需补齐或移除。后端按文件内容检查组内重复。 |
| 深度分析 | 链接按同行归组；使用 MV3 插件采集内容、媒体、评论和可访问的商品承接资料。至少一条有内容的已完成／部分完成采集记录才能分析；允许没有评论。 |
| 证据与洞察 | 自有资料、同行图片、正文、视频及评论带证据 ID；输出区分用户确认、来源声明、图片可见、反馈样本和创意假设。可用标签多选，依据单独打开，来源声明保持待核实；不存在的证据编号不能通过解析。 |
| 方案编排 | 按所选可用标签执行三次策划，保存最多三套完整方案，展示套图、A+、图文和视频的逐项提示词。套图固定七张、图文六至十二页、视频为一条完整短片；没有新增媒体比较或版本管理 UI。 |
| 制作连接 | 四种交付默认不选；明确选择生成模型、比例、时长后查询真实报价，再确认配置并生成。套图／A+连接商品制作器，图文／视频连接现有内容创作器；视频使用普通完整视频路径。 |
| 执行与恢复 | 原制作草稿在确认后备份，修改冲突不覆盖；已有接单项保留，部分失败只继续未接单项，结果进入原制作页与全部任务。研究步骤及费用可查，提交未知不自动重发，预算暂停保留已完成步骤。 |
| 本地保存 | 研究输入使用带 revision 的本地后端草稿；标签按商品及分析结果保存，方案、交付勾选、模型、比例、时长和不加文字开关按研究范围保存在浏览器。新结果使用新的控制范围，交付初始不选。 |

当前输入硬限制：自有商品图最多 16 张、同行最多 10 组、每组图片最多 24 张、采集记录最多 20 条。图片分析每批最多四张；文字按长度拆批，超过单项或模型输入限制时明确报错，不静默截断。

资料变化后保留旧结果，同时显示其保存时间及旧资料范围，阻止直接使用旧方案查询制作报价。商品 revision 的变化也由后端制作接口再次校验。后台刷新失败保留已有页面并显示“重试更新”，首次读取失败使用既有错误工作区。

## 2. 安装与使用

快速分析：进入商品的“选品之神”，选择自有商品图，添加同行图片组并补齐每组三张不同图片；选择分析方式，查询费用并确认。完成后选择标签、查看依据，再查询并确认“三套创作方案”费用。选中一套方案，展开逐项内容检查后，勾选交付、选择可用生成模型及参数，查询制作报价；确认后到制作页或全部任务查看。

深度采集需要人工安装插件：

1. 在深度分析区下载插件 ZIP，解压；在 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions` 开启开发者模式，选择“加载已解压的扩展程序”，选中含 `manifest.json` 的 `douyin-research` 目录。
2. 在工作台建立同行组并添加一条抖音链接。点击“获取配对码”，打开插件，填写实际本地工作台地址（默认 `http://127.0.0.1:4310`）及配对码，点击“配对工作台”。配对码五分钟内单次有效；失效后重新获取。
3. 在安装插件的同一浏览器、同一用户配置中登录抖音官方网页。插件刷新任务并“打开该素材”，在目标页面执行“检查当前页登录”。只有检测到明确登录标记且没有登录／验证阻断才启用“开始／继续采集”；页面或标签变化需重新检查。
4. 采集时保持浏览器打开；可以暂停。遇登录、验证或中断时保留检查点，用户处理官方页面后重新检查并继续。完成后返回工作台核对数量、素材、停止原因与缺项，再主动查询分析费用。
5. 商品承接未取得时可手动打开目标商品面板，再使用“补采当前商品首屏”。核对截图确为目标商品；受限媒体可以在工作台补充图片。缺失内容不能视作已采全。

每条素材最多 100 条不同一级评论，二级回复关联已采集一级评论且不递归第三级；达到上限、明确到底、连续无新增或操作上限会记录停止原因。连续无新增不冒充“已到底”。商品首屏仅截取目标前台标签的实际可见页面；截图不冒充高清原图，封面不冒充视频。内容评论称为互动反馈，不自动称为买家评价。

插件仅向本机 HTTP 工作台配对；独立插件令牌、扩展来源和任务归属校验限制导入接口，配对可撤销。媒体上传进行大小与格式检查、按内容去重。登录在抖音官方网页完成；插件不向网页提供模型密钥，报告不记录配对码、令牌、Cookie 或会话秘密。

## 3. 模型、费用与接口

| 分析方式 | 证据读取 | 综合洞察及方案 |
| --- | --- | --- |
| GEM（默认） | GEM 3.8 flash | GEM 3.8 flash |
| TT | TT-6.1 sol | TT-6.1 sol |
| 双模型 | GEM 3.8 flash | TT-6.1 sol，使用 GEM 的证据结果 |

本模块的分析方式不修改系统其他页面的默认模型。TT 研究暂不直接接收视频，需改选 GEM／双模型，或补充关键帧与文字；不会暗中改用 GEM。GEM 视频仍受既有分析器的文件与时长限制。模型已启用、凭据及能力可用不等于已覆盖所有真实素材，仍需核对返回内容。

分析预估覆盖分批读取和汇总调用预算，实际按 token 结算；方案编排单独报价三次调用。媒体生成按所选制作器真实报价，整组上限为各项相加。已增加整组余额检查：报价界面与提交前均比较剩余整组金额和当前可用算力，避免“单项均可负担、合计却超额”时先接单一部分。确认提交仍会重新检查报价、商品及草稿修订；费用变化需重新查询。

主要接口（均在现有本地 API 下）：

| 用途 | 路径 |
| --- | --- |
| 读取与保存研究草稿 | `GET /api/catalog/products/:id/research`、`PUT …/research/draft` |
| 分析预估与提交 | `POST …/research/estimate`、`POST …/research/start` |
| 步骤、续作、结算 | `GET /api/research/:id`、`POST …/retry`、`POST …/billing` |
| 方案报价与编排 | `GET /api/research/:id/strategy-estimate`、`POST …/strategies` |
| 交付报价与接单 | `POST /api/research/:id/delivery-quote`、`POST /api/research-deliveries/:id/submit` |
| 插件 | `/api/research-extension-package` 下载；配对、任务、进度及媒体导入走限定的 `/api/research-extension/*` 接口 |

实现位置：`packages/research.ts` 为契约与提示词；`apps/server/research.ts` 为证据、分批任务与恢复；`research-extension.ts` 为配对与导入；`research-generation.ts` 为既有制作器桥接；`src/components/catalog/research.tsx` 为工作区；`extensions/douyin-research/` 为插件。

## 5. 视觉系统与复查

按既有界面扩展处理：沿用语义 CSS 颜色变量、现有字体、shadcn 基础控件、素材选择器、媒体大图及居中加载／错误工作区。没有借“选品之神”另创视觉身份，没有新增根目录 `PRODUCT.md`、`DESIGN.md` 或设计令牌副本。

研究区复用主阅读区＋右侧操作栏。默认侧栏 520px，宽度不超过 1400px 时 480px，至少 1800px 时 560px；主区与侧栏各自滚动，底部查询／制作按钮保持可达。1050px 以下转单列，底部操作采用 sticky。动效保持轻量状态过渡，并在 `prefers-reduced-motion: reduce` 下关闭研究区过渡与转圈动画。现有桌面三个尺寸有浏览器证据；窄屏布局仅有实现，未据此声明移动端已验收。

初次 finish review 的 disposition 为 **fix**，三个发现为：制作控制状态刷新后丢失、修改资料后旧结果范围不清、后台刷新失败缺少反馈。相应代码已补控制持久化、旧资料范围提示与制作阻断、保留旧结果并提供重试入口。最终独立 verdict pass 为 **ship**：上述三项均评为 resolved。复查证据为 `restored-1440.png`、`stale-scope-1440.png`、`refresh-error-1440.png`及浏览器断言；此结论仅覆盖原修复清单，不扩张为全系统或线上抖音验收。

Impeccable 的 context／detect 启动器因引擎 0.1.14 下载失败未完成，不能声称检测器通过。此次文档检查范围为上述研究契约、后端、组件、研究 CSS、插件及现有验收 JSON；不扩大到全站设计审计。
