# 服装创作工作台：完整 UI / UX / 动效评审

日期：2026-10-29。目标：`src/Workspace.tsx`、相关全站页面与组件，运行界面 `http://127.0.0.1:4310`。

## 结论

当前系统已经有统一视觉外壳、服装相关技能、素材映射、真实账户与报价，以及可靠的草稿保护基础。主要缺口是：**界面仍围绕技能、批次和接口记录组织，而用户已经确认要围绕一款商品连续做出一组成套图。** 缺少跨技能商品上下文、成套结果选优和明确交付终点，使用户反复上传、切页、记忆、比较。

继续缩小字体、压缩间距或添加装饰动画，都不能独立解决这条任务链。建议保留用户指定的深色侧栏、靛蓝主色、紧凑桌面布局、中文及 shadcn/ui，优先改任务组织、结果审查与状态连续性。

**生产能力须单独处理：当前媒体生成仍是模拟执行。** 账户/报价/AI 辅助已有真实接口，不代表图片、视频生成链路已真实接通。`apps/server/engine.ts` 在接单时写入 `simulated: true`，worker 从输入或示例复制媒体文件。界面已有模拟标识，不能删除这些标识来伪装接通。本项是生产闭环阻断，不能归因于配色或动效。

## 设计健康评分

评分为专家启发式评估，不是用户实验或转化率指标。所有十项适用于本工具，0–4 分，4 分代表优秀。主审在 A 的 27 分基础上，根据 B 实测的焦点恢复、焦点对比与交互一致性问题，将控制、一致性各减 1 分。

| 项目 | 分数 | 主要依据 |
|---|---:|---|

## 产品辨识度与优点

产品特异性中上。商品多角度图、对标图、模特、详情屏和白底辅助已经体现服装业务；普通 AI 工作台式卡片与输入框仍占据主要结构。无需为了差异化推翻用户提供的视觉风格，应把辨识度进一步落在素材关系和成套交付上。

1. **素材角色已有业务结构。** 一键对标逐目标显示商品参考数量、替换对象、逐图要求与结果，明显优于把全部图片塞进同一上传区。
2. **付费和采纳保护有基础。** 首次生成有预览与费用上限；AI 辅助先给候选，插入/替换才改草稿，新输入不会被旧结果直接覆盖。
3. **用户投入受到保护。** 自动保存、后台继续、原尝试保留、覆盖草稿确认、仅重试保存等设计值得保留。小图标仍有 tooltip/可访问名称，排序也有上/下移替代路径。

## 五项优先问题

### 1. [P0 · 生产能力] 真实查询与模拟媒体混在同一生产感知中

**证据：源码确定。** `apps/server/engine.ts` 的接单与 worker 标明模拟并复制媒体；结果卡和预览已有“模拟素材/不调用模型”说明。账户与报价是真实数据，主界面却同时展示可用余额、预计费用与模拟结果，使用者容易把“账户接通”理解成“生成接通”。

**影响：** 无法完成用户预期的真实图片产出。即使操作顺滑，也无法交付真实新图。本轮没有证明发生真实媒体扣费。

**建议：** 接通真实媒体执行、任务号、最终费用与原文件保存闭环后再做生产验收。在此之前保留准确标识；模拟结果不计入真实成品统计，也不混入真实消费。费用页可继续展示真实消费。此项需媒体后端实施，不应作为纯 UI 动画修复冒领。

### 2. [P1 · UX] 一款商品的素材、版本和交付没有连续上下文

**证据：浏览器实测及源码。** 各技能独立草稿；结果按尝试平铺，单张预览只显示当前图；没有明确的“采用版本”。全部任务先显示供应商查询和 AI 辅助表，再显示创作批次。批次靠短 ID、技能和时间识别，完整绑定仍显示素材 ID。见 `src/Workspace.tsx`、`src/components/results.tsx`、`src/App.tsx`。

**影响：** 做同一款卫衣时，从白底到换装再到详情，需要重新定位商品与要求；比较 v1/v2 时记忆原图和差异；最后还要人工整理哪张可交付。

**建议：** 在不合并技能专属草稿的前提下，提议共享商品资料上下文；结果按同一出图条目聚合版本，比较时带原图、参考图和参数差异，增加“采用此版本”。历史先展示带商品名、缩略图、数量、状态的创作记录，供应商查询放高级入口。采用图再进入图片合集/详情长图交付。资料边界与交付标准待 Q2/Q3 回答，不能直接创建新项目数据结构。

**对应命令：** `impeccable shape` / `layout`。

### 3. [P1 · 信任与操作一致性] 费用确认、保存与状态的约定不统一

**证据：** 首次生成先 `/plan` 再确认；结果卡“重新生成”直接创建新尝试，后端虽会核价，前端没有先展示新费用（`results.tsx`）。顶栏 active 统计遗漏 queued、waiting_dependency，可能出现卡片在排队、顶部却显示“后台队列就绪”（`App.tsx`，源码条件，未新建任务复现）。报价每 30 秒刷新时，`isFetching` 使已显示报价和可提交状态暂时失效（`generation-quote.ts`，源码风险，未测量实际闪动）。参数矩阵改动立即保存；部分设置需按钮保存；排版关闭没有未保存保护。

**影响：** 用户不能稳定判断“这次点击是否会付费”“关闭是否撤销”“任务是否已结束”。这是比按钮形状更重要的交互可信度。

**建议：** 新的付费生成统一显示新报价并确认；仅保存重试明确无新模型调用。入口命名统一“预览生成 → 确认生成”。后台刷新保留上次报价与更新时间，提交前强核价；参数变更立即使旧报价失效，不能把旧参数价格继续当成可提交价格。队列分执行中、排队、等待依赖。统一明确的即时保存提示；会丢失编辑的弹层提供保存/放弃/继续编辑。

**对应命令：** `impeccable clarify` / `harden`。

### 4. [P1 · 可访问性] 关键焦点和状态文字不够清楚

**证据：浏览器实测。** 完成状态 `#059669` / `#ecfdf5` 对比 3.58:1，小字未达 4.5:1；侧栏品牌副标约 4.00:1。主输入去掉 outline/shadow，父层只留浅色 1px 边框，对背景约 1.87:1。参数矩阵与任务详情 Escape 关闭后，焦点落到 BODY，虽弹层内部焦点循环正常。见 `styles.css`、`common.tsx`、`results.tsx`。

**影响：** 键盘用户需要重新定位；低视力用户更难读状态、判断当前编辑位置。不能把“有 Radix”当成完整可访问性已经通过。

**建议：** 给主输入容器恢复高对比焦点环；区分状态文字与状态图标 token；关闭弹层回到触发按钮。关闭名称中文化，状态变化采用低打扰的可访问通知。小控件优先扩大命中区，24px 与 44px 适用标准分别判断，不把所有小于 44px 一律宣称 AA 违规。

**对应命令：** `impeccable harden` / `colorize`。

### 5. [P2 · UI 密度] 创作与审图同时争用视口

**证据：浏览器实测。** 1280×720 中创作框约占 38% 视口高度，含两类素材、四个快捷要求及八组以上参数/操作。页面有底部留白补偿，滚动后能看到完整图，属于持续占空间而非永久遮挡。见 `creative-composer.tsx`、`styles.css`，截图 `a-image-generate.png`。

**影响：** 输入阶段方便，审查全身服装、版型和长图时却降低有效画布。继续缩小字号会恶化可读性。

**建议：** 保留常用比例、清晰度、数量；次要控制放高级参数。增加显式“收起创作框/继续编辑”，收起后保留商品摘要、草稿状态及必要报价。用户开始输入时展开，查看结果时可主动收起；不在用户输入或选图时自动跳变。

**对应命令：** `impeccable distill` / `layout`。

## 动画分析与建议规范

**动效目标：解释编辑、预览、接单、排队、结果之间的关系，并保持当前任务定位。** 操作型产品不需要整页入场、卡片依次飞入或常驻装饰循环。

**确认的实现缺口：** Dialog/Sheet 写有 `animate-in/out`、fade、zoom、slide 等 class，但浏览器计算样式为 animation none、duration 0s。当前不是“侧栏滑得太慢”，而是实际上没有 keyframe 动画。只改 JSX 里的 duration 不会修好。Select 即时展开本身合理，不必强制加动画。见 `src/components/ui/dialog.tsx`、`sheet.tsx`、`tooltip.tsx`，以及 CSS 动画定义/依赖缺失。

| 场景 | 当前 | 建议（待实施） | 中断/减弱动态处理 |
|---|---|---|---|
| 按钮与图标反馈 | 约150ms | 100–150ms color/border/opacity，操作立即发生 | 不等待动画再响应；禁用不跳位 |
| 图片 hover | 500ms、scale1.04 | 取消缩放或缩至160–220ms；保留预览按钮提示 | focus 同等可见；减弱动态取消缩放 |
| 参数弹窗 | 实测无 keyframe | 180–220ms opacity+极小位移；退出140–180ms | Escape可随时打断，不延迟关闭；恢复触发焦点 |
| 任务/分析侧栏 | 实测无 keyframe | 220–280ms translate+opacity；退出140–180ms | 连续开关不闪回；不保留阻挡点击的透明遮罩 |
| Select与菜单 | 即时 | 保持即时或80–120ms轻淡入，避免大位移 | 键盘立即可用；Escape回trigger |
| 输入区收起 | 当前无此模式 | 若采纳，180–220ms；保留摘要及固定锚点 | 只响应明确操作，不在输入中自动收起 |
| 配置/计划折叠 | 多为条件挂载 | 默认即时；若动画，150–180ms并同步箭头 | aria-expanded/controls对应；长列表不逐项编舞 |
| 报价/余额刷新 | 有loading状态 | 保留可读数值与更新时间，用局部提示表达刷新 | 不移动主按钮；价格失效明确；减少动态保留文字 |
| 任务完成 | 轮询更新状态 | 原卡原位更新，一次短状态强调；不强滚到结果 | polite通知；用户正在输入时不抢焦点 |
| 拖动排版 | 未实测 | 贴手跟随、明确占位与落点；结束短过渡 | 上/下移按钮同功能；减弱动态直接定位 |

统一建议 token：fast 120ms、normal 180ms、panel 260ms；进入可用 `cubic-bezier(.16,1,.3,1)`，退出用快速收束。上述是提案，不是当前实测值。优先 transform/opacity，明确 transition 属性，减少 `transition-all`。无需为了弹窗引入大型动画库。

当前有全局 reduced-motion 规则与余额刷新停转处理，是正面基础。后续应实际模拟验证：去掉位移/缩放，保留必要的即时状态文字；不依靠 spinner、颜色或动画表达唯一状态。未发现证据支持“全站动画掉帧”，不能虚构 FPS 或把 blur/shadow 直接等同性能问题。

## 认知负担、情绪旅程与人群

认知负担手工检查：单一焦点、一步一决策、最少选择、跨屏记忆、渐进披露五项存在缺口；分组基本成立，视觉层级部分成立。按评审 checklist 属高负担，主要发生在多版本选图和输入/结果并行阶段。这里不是说菜单超过四项就必然不能用；问题是用户必须同时协调素材、模型、比例、清晰度、数量、差异、绑定和结果。

旅程：进入时连接/余额让人安心 → 素材角色帮助理解 → 参数和白底依赖增加迟疑 → 预览与费用带来确定感 → 后台继续降低等待焦虑 → 完成后缺少比较/采用造成选择疲劳 → 导出与历史没有清晰商品终点。最值得优化的是后半段“选好这一套并交付”。

- **熟练运营 Alex：** 能批量生成但需逐卡比较与操作；缺成套选优、批量导出和商品资料复用。
- **首次使用 Jordan：** “确认发送”实际打开预览，与详情的“预览生成”不一致；商品图/参考图/目标图/白底辅助的边界需在使用处说明。
- **键盘与低视力用户 Sam：** 弹层内部键盘基础良好，但关闭后丢焦点、主输入定位弱、完成状态对比不足；目前不能宣称全流程读屏通过。

## 整改顺序与可验证交付

1. **生产真实链路单独验收。** 已配置真实执行时，每次生成有供应商任务号、来源、最终费用和保存原件；真实与模拟历史可区分。禁止以新视觉样式作为接口接通的证据。
2. **先修操作可信度。** 新生成/重新生成均预览本次价格；仅重试保存不触发新生成；刷新不造成无意义按钮闪动；排队状态一致；弹层焦点回原处；文字对比达到相应标准。
3. **再按 Q2/Q3 改成套流程。** 同商品从白底、换装到详情可追踪来源；版本与参考可同看，明确采用图；历史能找回；交付包含用户确认的产物。不同技能要求不相互覆盖。
4. **最后补目的明确的动画与密度调整。** 实际观察入退场动画及快速开关；不产生布局跳动或透明遮罩；减少动态偏好下仍清楚显示状态。

验收使用用户这款亨利领卫衣及明确允许的测试数据：桌面1280/1440/1920，每种工作区执行“资料→要求→报价→预览→确认→状态→比较→选用→导出→历史找回”。另做键盘Tab/Shift+Tab/Escape、200%缩放、失败与迟到结果、价格变化、未保存退出、断网恢复、减少动态测试。需要新付费调用时按届时授权执行，本轮未代为执行。

衡量项：完成成套图所需跨页次数、重复上传次数、比较版本时离开当前上下文次数、费用确认路径一致性、意外覆盖次数、关键状态可识别性。先记录基线，再对比方案；不预先承诺效率提升百分比。
