# AI 创作工作台：线上部署

## 目标与边界

私有 GitHub 仓库只保存源码。可用的工作台地址需要一台持续运行的容器、HTTPS 域名和持久化数据卷。工作台通过 HTTP Basic 密码保护页面、媒体和 API；分享链接的人仍需输入访问凭据。单个实例只供受信任的使用者共享，尚不提供独立用户账号与权限隔离。

## 容器部署

1. 在托管平台连接私有仓库，选择 Dockerfile 构建；部署单个实例，不启用多副本自动扩容。
2. 创建持久化数据卷并挂载到容器的 /data。SQLite 数据库、媒体、导出文件和加密凭据都放在这里；不要只使用临时容器磁盘。数据卷需留足素材和后续生成结果的容量。
3. 生成 HTTPS 公网域名，将以下变量配置为托管平台的私密环境变量：

   | 变量 | 用途 |
   | --- | --- |
   | STUDIO_PUBLIC_ORIGIN | 工作台精确地址，如 https://studio.example.com，不带路径或末尾斜杠 |
   | STUDIO_ACCESS_PASSWORD | 随机生成的 20–200 位访问密码；不可提交 Git |
   | STUDIO_ACCESS_USER | 可选，默认 studio |
   | STUDIO_DATA | /data，Dockerfile 已设置 |
   | PORT | 平台注入的端口，默认 4310 |

   可在可信的本机终端用 openssl rand -base64 36 生成密码。不要将它写进文档、截图或命令历史；直接保存到平台的密钥配置。
4. 使用容器健康检查路径 /healthz。此路径只返回 ok，其他页面和数据均要求密码。配置域名和变量后再开放公网访问。
5. 在浏览器打开 HTTPS 地址，输入工作台用户名和密码；进入「模型配置」添加供应商 API Key。GitHub 源码仓库不包含任何本机密钥。

默认 Docker 构建包含本地视频处理所需的 Python 依赖和 Whisper 模型；若部署资源不足，可设置构建参数 WITH_VIDEO_RUNTIME=0，此时远程供应商的视频生成仍可用，但本地视频反推、剪辑等处理不可用。不要把该降级版本当作完整功能验收。

## 现有数据迁移

如果要保留本机的商品、任务和媒体，需要在**停止本机服务后**，通过托管平台的安全文件传输方式，把 data/ 中的 studio.sqlite、media/、video-remakes/ 和 private/ 一起迁入线上数据卷。迁移前单独备份原目录；不要把它提交到 Git。private/master.key 必须与 private/credentials.json 同时迁移，否则已有 API Key 无法解密。不要复制运行时的 server.lock、server.flock、SQLite 的 -wal、-shm 或临时文件；数据库须在停止服务后完成检查点，再复制主库。线上启动前核对文件权限与容量。

如果选择空白环境，无需上传任何本机数据，首次启动会创建数据库；之后在工作台重新配置供应商密钥。

## 验收

通过 BrowserOS neo 的可见界面，检查未登录时需要凭据，登录后页面与模型配置能正常操作；上传一张测试图，刷新页面确认素材仍在；重启单个容器后再次确认素材和配置仍在。付费生成测试应先确认供应商密钥、余额和预估费用。访问链接与密码通过不同渠道分享。
