# 全站测试与 UI/UX 评审

测试日期：2026-11-03。文档整理日期：2026-11-05。验证状态：**部分验证（partial）**。

本报告记录 11 月 3 日实际打开并操作的页面，不把随后新增的电商设计页面和提示词工作台算作已测。11 月 5 日源码已继续变化，下面未关闭的问题需要在当前版本复核后再决定修改。它是一次逐页评审及改进建议，不是全站无缺陷或生产发布合格证明。

## 2. 总体评价

深色导航、浅色工作区、卡片、底部输入台与管理页面已经形成视觉体系。普通图片、视频、图像编辑都在使用底部输入台，问题主要集中在同类控件的差异、参数命名、素材角色识别和异常恢复，而不是三页完全使用不同布局。

目前最影响完成任务的，是视频草稿出现空模型项且报价失败时缺少明确修复路径。其次是同一个商品套图/详情创作，在独立工作区与商品详情里需要不同的操作习惯；商品来源、SKU、模型价格等数据密度较高的页面也缺少面向运营人员的整理。

不建议用大量装饰插画填补空白。先统一控件、主操作位置、结果密度与错误处理；少量功能示意图用于说明素材角色、镜头或流程，完整教程集中到帮助中心。

### 通用操作、视频生成、图像编辑应如何统一

| 交互部分 | 11 月 3 日观察 | 建议的统一方式 |
| --- | --- | --- |
| 页面结构 | 三页都有结果区与底部输入台 | 保留共同骨架，不重做三套工作台 |
| 数量 | 图片/编辑的数字步进与视频的长下拉不同 | 统一为同一控件。建议常用数量＋可输入步进；若采用该建议，应同步修订现有“输入台数量统一下拉”的规范，不能把建议当作现行规定 |
| 素材 | 相同加图图标隐藏了不同角色 | 上传入口文字直接写“参考图”“待编辑原图”“首帧”；多角色时显示标签及已选数量 |
| 模型与价格 | 控件位置相近，但失效草稿缺少可理解的状态 | 固定显示模型名称、分组、倍率、计价单位；无效项写“请重新选择模型”，并提供入口 |
| 业务参数 | “高级参数”打开“参数矩阵”，存在命名跳变及多图差异入口重复 | 外层和弹窗同名；一个参数只保留一个主入口，快捷控件与弹窗共享同一值 |
| 编辑快捷项 | 图像编辑页分散在上下两处 | 集中在提示词附近，以可撤销的选中状态表达，不静默追加无法识别的文字 |
| 主操作 | 都有提交动作，但错误时不易定位 | 固定“生成/开始编辑”及数量、费用摘要；点击后先持久化任务，再进入后台进度；失败保留草稿并定位字段 |
| 结果 | 小卡片与大空白并存 | 单结果给更大可检查预览，多结果用固定比例网格；预览不裁商品，详情保持按需展开 |

复杂智能体与普通输入台可以不同。用户需要统一的是相同动作的名称、控件、状态与结果行为，而不是每个页面都强制采用同一种栏数。

## 6. 确认问题与处理优先级

以下问题的复现条件均为 11 月 3 日桌面视口及已有数据。新版本需先复核，不应按旧截图直接修改。

### F01 · P1：视频草稿空模型与报价失败缺少恢复入口

- 复现：打开已有视频生成草稿，查看底部模型控件和费用区域；打开模型菜单核对。
- 实际：模型控件只露出图标与箭头，费用显示“报价查询失败”，无法直接理解应修复哪项。
- 影响：用户无法可靠确认将要使用的模型、分组与费用。
- 期望：失效模型显示明确名称或“模型已不可用”；提供“重新选择模型”，重新选择后只重算费用，不自动提交。
- 状态：已确认可见现象；当时未定位根因、未修复。
- 证据：[局部截图](ui-ux-audit-20261103/evidence/issue-video-model-empty.jpg)。

### F02 · P2：A+ 组数标签被拆成两行

- 复现：打开详情设计，查看屏列表标题旁的组数控件。
- 实际：“组数”在充足桌面空间仍竖排断行，标签与输入区关系变弱。
- 期望：标签保持单行，数字区域有最小宽度；空间不足时整组换行。
- 证据：[局部截图](ui-ux-audit-20261103/evidence/issue-aplus-count-wrap.jpg)。

### F03 · P2：商品来源快照展示原始 JSON

- 复现：商品资料→来源快照与变更→滚动到商品参数和颜色。
- 实际：数组、`origin`、内部 ID 等直接出现在业务对比表中。
- 影响：用户无法快速确认哪些业务值发生变化，整行变得很高。
- 期望：参数名/值成对展示，颜色显示可读名称；差异突出，原始数据留在高级详情。
- 证据：[局部截图](ui-ux-audit-20261103/evidence/issue-source-json.jpg)。

### F04 · P2：设置离开时静默丢弃修改

- 复现：视频并发 1→2，不保存→帮助→返回设置。
- 实际：没有离开提醒，显示值恢复为 1；本次未改变服务器设置。
- 期望：明确选择保存模式；若显式保存，修改时显示未保存状态并提供离开确认；若自动保存，显示保存中、成功与失败并保留失败稿。

### F05 · P2：同类创作操作在不同入口中的位置不一致

- 复现：依次进入普通三页、独立套图/A+、商品详情中的同类功能。
- 实际：数量控件不同；高级参数与参数矩阵同物异名；相同业务主操作有右侧固定和长表单末尾两种位置。
- 期望：复用字段与业务状态；统一相同功能的参数顺序、摘要与主操作；复杂流程仍允许独立布局。
- 状态：体验一致性问题，不将所有结构差异判为错误。

### F06 · P2：调研说明中的模型名称与配置脱节

- 复现：进入商品调研，比较页面固定文案与当时已配置模型。
- 实际：说明仍写 GEM 3.8，而配置已为 GEM 4。
- 期望：显示实际选中的模型或使用不绑定版本的能力说明；费用与能力来自同一配置。

### F07 · P2：交付入口发现成本高

- 实际：交付页可直接访问并正确勾选，但侧栏无清晰入口。
- 期望：结果操作提供“加入交付”，导航可到交付清单；入口上的数量反映实际选择。

## 7. Token01 视频加载问题：独立修复记录

此项是用户随后明确要求处理的功能故障，已做修复与同一既有任务的恢复验证，不属于单纯审美建议。

Token01 任务查询返回数值类型的内部 `data.id`，同时在 `data.task_id` 返回公开任务号。原适配器错误地要求两个 ID 都与本地任务号一致，导致上游已经成功的视频未被本地保存和显示。

- 修改：[Token01 适配器](../apps/server/token01.ts)以 `task_id` 为准，缺失时才兼容字符串 `id`；[媒体 Worker](../apps/server/media-worker.ts)接单记录同样优先使用 `task_id`。
- 回归：[Token01 测试](../tests/token01.test.ts)覆盖数值内部 ID、公开任务号不匹配、字符串 ID 兼容及原凭据查询；没有重新提交付费生成。
- 结果：既有任务恢复，MP4 已保存；通过可见预览播放到约 10.125 秒，下载入口可用。
- 证据：[恢复后的页面](ui-ux-audit-20261103/evidence/31-token01-recovered.jpg)、[播放局部](ui-ux-audit-20261103/evidence/token01-playback-recovered.jpg)。

此修复关闭的是特定任务标识兼容故障，不代表所有视频模型、分组、超时和媒体 URL 均已验证。

## 8. 动画、流程与状态反馈

源码当前有 160ms、240ms、320ms 与 180ms 的动作时长令牌，并有 `prefers-reduced-motion` 规则；可见弹层的逐层 Esc 关闭已操作。没有做帧率、实际耗时、低性能设备或系统减少动态效果实测，不能据源码判为动画验收通过。

建议统一如下：

| 场景 | 交互要求 | 动画与反馈 |
| --- | --- | --- |
| 按钮、选项与勾选 | 点击即有选中或提交反馈，重复提交受控 | 约 120–180ms 的颜色/边框变化；避免整张卡缩放影响阅读 |
| 菜单、提示与素材浮层 | 键盘可进入、Esc 关闭、关闭后回到原触发点 | 约 160–200ms，短距离淡入；不得只靠 hover 才能操作 |
| 对话框与侧栏 | 同类入口的方向一致，主操作位置稳定 | 建议不超过约 300ms，使用透明度与 transform；已有 320ms 令牌如调整应全局同步 |
| 上传 | 展示真实上传阶段、失败项及重试 | 有真实字节进度才用百分比；完成后原位替换，不让输入台跳高 |
| 生成 | 区分排队、提交、上游生成、保存和待核实 | 未知进度显示步骤或等待，不能制造逐渐递增的假百分比 |
| 临时拥挤 | 保留任务与模型，提示稍后重试或排队状态 | 不等同于离线；“本地服务断开”“上游繁忙”“模型不可用”分别显示 |
| 播放失败 | 已生成但媒体加载失败时提供重新加载/下载 | 不把生成成功改为失败，不因播放器出错自动重新付费生成 |
| 费用变化 | 模型、分组、数量变化后重算 | 数值就地更新；未知价格明确说明，不能显示为 0 或免费 |
| 减少动态效果 | 保留状态表达与焦点提示 | 去掉位移、缩放及持续装饰动画，不能靠动画本身传达关键结果 |
