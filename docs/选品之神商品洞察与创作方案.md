## 1. 运营判断

这个方向成立。它解决的核心问题是：采集商品之后，运营仍需要研究同行、找购买理由、确定内容方向，再反复到不同制作页填写要求。把这些工作串起来，可以形成“一份商品资料，多种内容持续制作”的工作流。

但它更接近**商品洞察与创作策划**。仅凭商品图片、同行素材和最多 100 条评论，无法可靠判断市场规模、利润空间、真实转化率或未来销量。“选品之神”可以作为趣味名称，副标题建议用“商品洞察与创作方案”，不要把推测包装成经营结论。

完整闭环：

**准备商品 → 添加同行证据 → 分析 → 选择卖点、痛点与表达方向 → 形成几套方案 → 勾选交付物 → 汇总报价 → 制作 → 查看任务与下载。**

三个运营原则：

- 研究同行的表达和反馈，不把同行的材质、功效和服务承诺移植为自有商品事实。
- 分析必须能回到图片、时间点或评论；资料不足时保留“待核实”，不要用漂亮话补齐。
- 套图、A+、图文、视频围绕同一条购买理由展开，但分别承担展示、解释、种草和动态演示的职责，不重复堆图。

例如：原图能看到宽松轮廓，可以建议“宽松穿搭”方向；“显瘦”属于需要表达与试穿验证的假设；“保暖提升 30%”没有可靠资料就不能进入成品提示词。

## 2. 在商品工坊中的位置

商品内导航建议调整为：

**选品之神｜产品编辑｜内容创作｜爆款复刻**

- 商品库进入商品时默认打开“选品之神”。已有直达链接和明确指定工作区的链接保持原目的。
- 原有基础信息、商品套图、A+详情、SKU、图文、视频和爆款复刻不搬家；新首页负责分析和分发方案。
- 首次进入显示准备区；已有分析时直接显示最后一次成功结果、分析时间及资料状态。
- 不设置“每次进入自动分析”，也不因浏览或重新采集商品而静默扣费。

这里分析的是“如何表达这款商品”。如后续要增加进货决策，另加成本、毛利、履约、供货与市场数据，不混入当前标签结论。

## 3. 两种研究入口

建议保留用户熟悉的“快速分析／深度分析”，补充副标题解释区别。

| | 快速分析：上传图片 | 深度分析：采集链接 |
| --- | --- | --- |
| 商品资料 | 当前商品图片、名称、参数与已确认卖点 | 同左 |
| 同行来源 | 按同行分组上传图片 | 插件采集内容、可见评论及关联商品 |
| 最低要求 | 至少一家同行，且该家至少三张有效图片 | 至少一条有可分析内容的有效采集记录；没有评论也允许分析 |
| 核心价值 | 快速拆解画面表达与差异方向 | 结合动态内容、商品承接页与用户反馈 |
| 结论限制 | 不能声称知道用户评价与实际表现 | 评论仍是样本，不代表全部买家或市场 |

“深度”表示证据类型更丰富，不表示结论天然更准确。两个入口最终进入相同结果结构，深度模式也允许补充图片、文字和手动保存的素材。

### 3.1 快速分析

上方为“自有商品资料”，展示本次选定图片、名称、关键参数和缺失项。商品图片使用现有选择器：当前商品／系统图片／添加外来图片，支持粘贴；不默认把全部商品图片发送给模型。

下方按同行分组，自动显示“同行1、同行2”等编号，采用纯图片输入，不设置名称编辑或备注字段：

```text
同行 1                                      移除
[图片 1] [图片 2] [图片 3] [+ 添加图片]

同行 2                                      移除
[图片 1] [图片 2] [+ 添加图片]

[＋ 添加一家同行]
```

- “一家同行”是研究分组，不假装系统已核实商家身份。
- 同行分组只需添加图片，不要求填写商家名或学习目标；系统分析场景、构图、穿搭和文案等维度，用户在结果阶段选择方向。分组使用稳定的内部标识关联证据，删除其他组不改变已有证据归属。
- 至少有一个三图完整组才能开始快速分析。新增但未完成的分组明确提示补齐或暂不纳入，不静默丢图。
- 重复图片提示并去重计算，不能用同一张图片重复上传满足三图门槛。
- 图片组上下排列，组内横排；支持拖动排序、粘贴、移除和固定外框大图查看。
- 多家多图通过分批分析处理，不把“支持很多图片”解释为一次模型调用无限图片。
- 建议首版界面软提示控制在 3–5 家、每家 3–12 张；真正硬上限结合调用预算与模型限制确定并公开，不静默截断。

### 3.2 深度分析

应用中添加一条或多条链接，分配到同行组，然后“发送到采集助手”。**采集前先引导用户在安装插件的同一浏览器、同一用户配置中打开抖音网页版并完成登录**。插件检查当前页面的可见登录状态与内容可访问状态，通过后由用户开始采集；系统显示每条链接的进度与缺失内容。

登录前置流程：

1. 未登录或无法确认登录状态时，显示“请先登录抖音网页版”，提供“打开抖音登录”入口，采集任务保持等待登录，不自动滚动、点击商品或抓取评论。
2. 用户在抖音官方网页自行登录；返回插件点击“检查登录状态”，确认登录且目标内容可访问后，启用“开始采集”。不只凭用户点击“我已登录”判断成功。
3. 登录检查无法可靠判断时，显示“暂无法确认登录状态”，保留页面与任务，允许重新检查，不将该状态伪装为可采集。
4. 采集中出现登录弹窗、登录过期或访问验证时，立即暂停受影响的采集队列，保留素材、评论去重记录和当前位置；提示用户处理，重新检查通过后主动继续。
5. 登录遮罩不能当作商品半屏截图；被登录弹窗阻断也不能记录成“没有评论”或“评论到底”。恢复后重新检查目标页面，再继续未完成项，不重复采集已完成项。

已确认首版平台范围：Chrome／Edge 桌面浏览器中的抖音图文、视频及可访问的关联商品页。军埔网与 1688 继续复用现有商品采集器，不承诺同一套 DOM 解析适配所有站点。

插件采集分为三包：

| 证据包 | 内容 | 用途 |
| --- | --- | --- |
| 内容表现 | 图文原图、正文、视频文件或可用片段、可见发布时间与指标 | 分析内容开头、结构、镜头与表达 |
| 用户反馈 | 可见评论文本、时间、点赞数、回复关系、排序方式 | 整理提问、认可、异议与使用场景 |
| 商品承接 | 点击商品后的半屏截图，以及可访问商品页的标题、价格、主图、详情、SKU | 分析用户第一眼看到的信息及前后是否一致 |

可见指标保留采集时间；没有播放量、销量或评价数据时留空，不编造。价格保留页面条件，例如规格价、起售价、券后价，不擅自当作统一成交价。

## 4. 插件采集的具体边界

### 4.1 评论停止规则

已确认：**每条同行图文／视频最多 100 条不同的一级评论，采集深度到二级**，不是每家同行共享100条。采集这些一级评论下可访问的二级回复，二级回复单独记录，不占这100条名额；不继续递归展开更深层回复。报告分别显示一级评论数与实际取得的二级回复数，并注明哪些参与分析。不把内容评论统称为“买家评价”。

1. 采集一条就持久化一条，按平台评论 ID 去重；无 ID 时保守去重，不合并真实不同人的相同短评。
2. 达到 100 条时停止获取更多一级评论；不足 100 条但能确认列表到底时，也停止获取一级评论。随后完成已纳入范围的一级评论下可访问二级回复的采集。
3. 页面只展示部分、请求失败、要求登录或连续没有新增时，停止并说明原因，不能假报“到底”。虚拟列表需要保留滚动前后已收集数据。
4. 分别保存一级评论数、二级回复数、排序方式、各级停止原因和采集时间；平台给出的评论总数与本次取得条数分开显示。
5. 不自动切换“热门／最新”凑足条数，不把重复抓取的热门评论当成更多独立意见。
6. 二级回复按所属一级评论分别去重、分页采集，到底即停止；遇到加载失败、访问限制或连续没有新增时，保留已取得内容并标明未完整采集，不循环尝试。保留所属一级评论及页面提供的回复对象关系，不因记录回复对象而继续采集第三级内容。

评论属于内容互动，可能来自未购买用户；商品评价属于另一类证据。报告分别称“正向反馈／疑虑与争议”，只有真实商品评价才能注明“买家评价”。不输出样本之外的“80%用户认为”等结论。

### 4.2 点击商品与第一眼截图

- 点击前后保留来源内容与商品的对应关系；多个挂链商品要求选择目标，不能默认第一个就是当前商品。
- 半屏按实际可见状态截图，记录窗口尺寸、时间及价格条件，作为“第一眼承接证据”。
- 随后采集商品完整资料，区分主图、详情、SKU，保留顺序与关联；不混入推荐商品。
- 页面不支持半屏、只能跳转 App、登录失效或图片无法下载时，展示实际取得的内容与缺项；可人工补充截图、文件或链接。
- 截图里的价格、文字等识别结果必须带截图来源和待核实状态；截图不能冒充原始高清图片。

### 4.3 可实现性与本地连接

浏览器插件可以利用用户正在浏览的页面和现有登录态读取可见内容，但不能保证所有抖音页面、弹层和受限视频均可下载。遇到验证码、访问限制或仅 App 可用入口，交由用户正常处理，不绕过。

采集使用用户已登录的浏览器页面，不新开未登录的隔离浏览器代替。登录由抖音官方网页完成，应用和插件不提供账号密码输入框，也不向本地系统导入登录凭据。

建议采用 Manifest V3 插件，用户主动为当前页面开启采集，按任务串行访问，允许暂停、取消和继续。浏览器关闭后停止页面操作，已保存内容不丢失；暂停后已满足上限的评论不再重复收集。

插件与本地应用需新增明确配对协议：

- 应用生成短期配对码，插件配对后获得限定权限的本地导入凭据。
- 本地服务继续仅监听本机；校验扩展来源、配对凭据、任务归属与请求大小，不开放任意来源跨域访问。
- 不向网页注入模型密钥，不读取或导出浏览器密码、Cookie 数据库；供应商凭据仍由 Node 后端保管。
- 只导入本次采集任务涉及的页面与媒体。昵称头像不是策略分析必需项，默认不展示；评论包保留删除入口。
- 媒体下载、格式校验和去重仍由受限导入服务处理；禁止任意本地文件路径写入、私网 URL 代理或执行网页脚本。

通知系统指“采集包入库并更新状态”。已确认先显示完整度，再由用户启动分析；启动后自动完成约定的分析链路，不逐批要求确认。

## 5. 分析链路：先证据，后策略

不采用“所有素材塞给一个大提示词，直接生成整份报告”。建议拆为可恢复的几个阶段：

1. **资料检查**：有效商品、同行分组、媒体与评论数量，识别缺项与重复内容。
2. **自有商品分析**：可见特征、来源参数、用户确认信息、待核实能力。
3. **逐家同行分析**：主张、画面风格、内容结构、购买理由、承接页信息及用户反馈。
4. **跨同行汇总**：共同表达、差异机会、争议问题，以及自有商品能否实际支撑。
5. **生成标签与策略摘要**：形成可选择、有依据的卖点、痛点、人群、场景和表达方向。
6. **根据用户选择形成方案**：不自动开始媒体生成。

每批最多沿用现有四图限制。超过限制按“同行＋来源内容＋顺序”分批，汇总保留证据 ID，不通过无限缩小拼图掩盖漏读。细节看不清时要求补图或明确无法判断。

视频可用 GEM 原生动态分析；超过现有 30MB／120 秒限制时提示选择片段或使用本地拆解，不静默截断。TT 路线使用明确标注的关键帧、时间点与转写文本，不能把静态帧理解称为等价的原生视频理解，也不能偷偷调用 GEM。

网页、评论和识别文字都是待分析数据，不是可执行指令；其中要求泄露密钥、改写流程或访问其他地址的内容不应触发工具操作。

### 5.1 结论的依据层级

| 类型 | 示例 | 在生成中的使用 |
| --- | --- | --- |
| 用户确认事实 | 用户核实面料、尺码与重量 | 可直接引用，保留范围 |
| 商品来源声明 | 货源页标注“防水” | 显示待核实，不自动升级为已验证性能 |
| 图片可见特征 | 拉链、轮廓、口袋位置 | 描述可见部分，避免推断不可见属性 |
| 用户反馈样本 | 某条评论担心闷热 | 表示疑虑，不证明商品实际闷热 |
| 创意假设 | 用通勤场景解释搭配便利 | 可用于测试表达，不能写成效果保证 |

每条核心结论包含：结论、证据定位、适用商品／SKU、反例或冲突、缺失资料与可用范围。证据不足显示“建议验证”，不用 AI 自造的精确置信度百分比。

- 点击标签旁证据入口可查看原图、视频时间点或评论摘录；选择与查看证据分成独立操作。
- 标签可编辑、排除和补充。需要核实的事实先修正或确认，再进入可对外使用的宣传文案。
- 不把标签云当唯一操作入口，也不靠颜色区分依据类型；提供数量、文字与选中状态。
- “同行正向反馈／疑虑与争议”同时显示来源样本数。同一人、同一内容的重复表达不放大为市场共识。

## 7. 从标签到几套完整方案

用户选择标签后，建议默认生成三套可供选择的方向，例如“日常通勤”“细节质感”“搭配省心”。方案必须在主购买理由、内容角度或视觉表达上真正不同，不只是换几个形容词。

这里的“几套方案”是策划备选，不是图片 V1/V2。无需引入版本管理界面，也不新增媒体比较功能。

选中一套方案，展开四项交付物的完整配置：

| 交付物 | 方案需要保存的内容 |
| --- | --- |
| 商品套图 | 结构、逐张用途、卖点与证据、原图绑定、版式、提示词、比例及模型参数 |
| A+详情 | 模块顺序、逐屏内容、事实依据、原图绑定、统一风格与逐屏提示词 |
| 图文 | 抖音商品图文主题、逐页职责、模板、至少六张互不重复的页要求、是否图片加字、提示词 |
| 视频素材 | 开头钩子、完整动作与镜头脚本、时长、首帧来源或制作需求、提示词及模型输入方式 |

遵守当前制作器的实际规则：商品套图默认至少七张；图文至少六页；A+按所选模块和有效资料组织。缺少尺码、材质或品牌资料时不自动补造相应内容。

方案是结构化配置，提示词只是其中一部分。每张图、每屏、每段视频有稳定输出位置，能对应商品原图和事实依据；不能只生成一大段文本让用户自己复制到四个页面。

方案中建议预填可用的模板与参数，但不能自动更换用户禁用的模型。首次规划未选定生成模型时，显示“待选择”，不要冒充可执行报价。输入数量、时长、比例或首帧模式不支持时，就地提示并允许调整。

### 7.1 视频与现有爆款复刻的分工

已确认：本功能的视频交付默认是**一条完整短视频**，走现有普通视频制作能力；所需脚本、首帧与参数写入方案。图片、评论和商品资料不足以凭空创建可靠的逐镜头动态复刻。

需要逐镜头控制时，用户另行进入现有“爆款复刻”工作区；来源包含视频时，可提供“转入爆款复刻”并携带来源和已分析脚本。镜头拆解、商品首帧、分镜生成与本地合成仍由该工作区负责，不随方案里的“视频”勾选自动启动。

### 7.2 一个服饰运营示例

假设自有商品为一款外套，已确认资料能支持版型、颜色和可见细节；某家同行评论中有人问“通勤怎么搭”，另有人关心尺码。系统不应据此认定自有商品“显瘦、不挑人、尺码标准”，而是形成可验证的内容方向：

| 方向 | 商品套图 | A+详情 | 图文 | 视频 |
| --- | --- | --- | --- | --- |
| 通勤搭配 | 完整穿搭、正背面与搭配细节 | 场景开头，解释版型和搭配 | 六页形成一条搭配叙事，页面职责不同 | 用出门、走动与局部镜头呈现穿着状态 |
| 细节展示 | 已有原图支撑的领口、袖口、口袋 | 外观结构、清晰细节与已核实参数 | 逐页回答“看什么、为什么值得关注” | 用近景与动作展示可见结构 |
| 选择帮助 | 颜色展示、实际尺码资料与不同角度 | 参数、规格和真实试穿资料 | 按用户选购疑问组织内容 | 有实际试穿资料才做尺码解释，否则展示外观与颜色 |

用户选择“通勤搭配”，勾选“商品套图＋图文”，视频与A+仍不制作。执行前会看到套图至少七张、图文至少六页的实际清单与报价，而不是只看到“方案A已开始”。

## 8. 选择交付与执行

四项交付物**全部默认不选**。用户选择一套方案，勾选希望制作的内容；查询报价时显示清单：图片数、详情屏数、图文页数、视频条数与时长、首帧是否需要生成。

- 分析费用、形成方案的文字费用、图片费用、视频费用分别列出。标签筛选是本地操作；“生成创作方案”如需要再次调用 AI，应明确标价并主动触发。
- 如果一项视频必须先生成首帧，将依赖列入清单；在首帧确定、视频报价可核实时再执行下一阶段，不能预报一个无法兑现的总价。
- 提交前校验所有交付物的资料、模型与参数。存在未就绪项时明确列出，用户可以取消该项后继续，不在后台静默跳过。
- 已有手动草稿时，支持保留原稿后载入方案，或取消；不能覆盖尚未提交的编辑内容。
- 用户确认报价后，协调器复用原有任务服务逐项接单，后台继续；一项失败不让成功项重跑。
- 余额检查考虑同账户尚未结算的任务；提交未知只核查，不重新发送付费请求；重启可恢复已知状态。
- 修改商品范围、模型、素材或方案使相关旧报价失效。输入快照在接单时固定，不随用户后续编辑变化。

新生成结果按现行规则更新对应当前内容，历史文件保留在“全部任务”供下载、复制。不新增“采用V1/V2”“查看比较”或一套新的历史管理界面；失败结果不清空现有成功内容。

## 9. 本地保存与重新分析

本地保存商品资料快照、同行分组、采集包、证据索引、分析结果、已选标签、方案、模型及费用关联。媒体文件使用现有本地素材存储。

- 下次进入直接读取最后一次成功结果和未提交选择，显示时间。
- 新采集或手动修改商品资料后显示“资料已更新，可重新分析”；已有结果仍可阅读，不自动扣费重跑。
- 重新分析期间保留旧结果，只在相关区域显示进度；失败或待核实时旧结果仍在。
- 分析结果不自动覆盖基础信息中的商品事实或用户确认卖点；需要明确应用。
- 重新生成方案不改动已接单任务。旧任务继续保留其输入快照，界面不引入版本编号。
- 允许删除同行证据与分析资料；删除对已有任务的引用影响应有说明，不能悄悄损坏已生成文件。

## 10. 模型、任务与现有系统衔接

### 10.1 默认模型

按用户要求，本模块默认 **GEM 3.8 flash**，可切换 **TT-6.1 sol**。建议选择记在模块设置中，不更改整个系统当前 TT 默认值。

当前分析请求尚不支持普通任务独立选模型，需要扩展合法的单任务／模块模型选择，并在接单时保存。两种模型分别校验凭据、图片能力及实际输入限制；不可因失败自动换模型。

开始分析前显示材料数量、预计批次数和费用估算。分析按 token 结算，估算不等于最终费用；支持设置整次分析预算上限，到达上限停止后续未提交批次，保存已完成结果，不承诺精确封顶已在途请求。

#### 可选建议：双模型协作

可以让 GEM 与 TT 串联，按阶段分工；这是一项可选设计建议，尚未替换已确定的 GEM 默认方式。不把“双模型”等同于“必然更准确”，需要用相同商品与证据做实际验证。

| 分析方式 | 素材理解 | 综合判断与创作方案 | 使用建议 |
| --- | --- | --- | --- |
| GEM 单模型（默认） | GEM 分批分析图片／视频，整理评论 | GEM 汇总证据、生成标签及方案 | 日常使用，减少调用与等待 |
| TT 单模型 | TT 分批看图；视频使用明确标注的关键帧与转写 | TT 汇总证据、生成标签及方案 | 用户明确选择 TT 时；遵守其实际输入能力 |
| 双模型协作（可选） | GEM 提取可见特征、画面结构、动态时间点和反馈证据 | TT 对照自有商品资料，整理差异机会、冲突、标签及完整方案 | 多家同行、多类证据，或需要更充分策划时 |

协作流程：

**原始资料 → GEM 分批提取证据 → 结构校验与证据索引 → TT 综合策划 → 用户选标签 → TT 编排完整创作方案 → 用户确认制作。**

- GEM 输出不能只有一段总结，应包含图片／帧编号、视频时间点、评论ID、可见内容、原文摘录、来源声明、未确定项与矛盾。TT同时获得自有商品的原始文字参数，不能只依赖GEM的概括。
- TT每条核心判断必须引用证据，不因第二个模型同意就把来源声明升级为已核实事实。GEM漏读或误读的信息不会被TT自动修复。
- TT认为细节不足时先标记缺证据，用户可以补图或主动选择让TT查看相关原图。此时仍受四图限制及识图验证约束，计入额外调用；默认不让两个模型重复看全部图片。
- “单次处理不了”先按原因处理：数量超限就分批，格式错误就修正，输出结构不完整就保留并提示，费用／凭据／提交未知就停止核查。换成两个模型不能直接解决这些问题，不因失败自动切换或自动重发。
- 用户在开始前选择分析方式，看到GEM与TT的阶段分工、调用估算及合计预算。快速／深度仍按资料来源区分，与单／双模型选择独立，避免把“深度分析”变成强制昂贵模型套餐。
- 每个阶段独立持久化输入、输出、模型与费用。TT阶段失败时保留GEM证据，用户主动重试只重做未成功阶段；已成功阶段不重复收费。
- 结果页显示本次实际方式，例如“素材理解：GEM｜策略编排：TT”；不对用户隐藏协作调用。

效果验证建议：用相同商品、相同同行素材和相同事实资料分别测试GEM单模型与双模型，核对证据可追溯性、事实错误、方案可执行性、内容重复率、耗时和实际算力。双模型的策划收益足以覆盖额外费用后，再考虑推荐给更多场景；不根据模型名称宣称能力优劣。

## 12. 分阶段实施

### 阶段一：先验证策略是否有用

实现快速分析、同行分组、证据化结论、标签选择、三套策略、本地恢复。将选中方案载入现有制作器并查询真实报价；保留明确的生成确认。

用一款真实商品和至少一家三图同行验证：建议是否具体、是否避免编造事实、提示词是否能直接驱动现有输出。不先为大范围采集投入全部开发成本。

### 阶段二：接通深度证据

开发 Chrome／Edge 插件、配对与本地导入，逐项验证抖音图文、视频、评论停止、商品半屏及详情采集。每类能力提供“支持／部分支持／需手动补充”，未验证入口不标成全自动。

### 阶段三：多交付物联动

补齐统一执行清单、依赖阶段报价、失败单项恢复、费用归集和任务跳转。产物仍留在对应制作页及全部任务，不新增成套交付入口。

## 13. 验收清单

- 快速分析满足一家三图门槛，多家及跨批图号、顺序和证据关联准确；没有静默漏图。
- 同行图片组自动编号，无名称编辑与备注输入；添加、移除分组后图片及分析证据不串组。
- 无资料、无评论或仅截图时，如实显示可得信息，不补造销量、用户共识或商品参数。
- 一级评论超过 100、不足 100、虚拟列表、重复评论、加载失败与登录失效均正确停止和记录；二级回复不占一级名额，关联准确、不递归采集第三级，未完整采集时明确标注。
- 内容挂多商品、无半屏、仅 App 链接、受限媒体有明确处理；推荐商品不混入素材。
- 首次未登录、登录检查不确定、采集中登录过期与验证弹窗均先等待或暂停；同浏览器登录并重新检查后可继续，登录遮罩不入库为商品截图，也不误报无评论或到底。
- 上传、采集、页面切换和普通标签勾选不会创建隐含付费任务。
- GEM／TT切换不改变全局设置；TT 不伪装支持原生视频；密钥不出现在插件、页面或日志。
- 如实施双模型协作，开始前明确分工与双阶段费用；证据可追溯、失败只恢复未成功阶段，不隐式回退或重复收费，并用真实资料验证相对收益。
- 四种交付物默认不选；清单、参数、素材绑定、实际报价与真实任务对应。
- 已有草稿不被静默覆盖，重复点击、提交未知、阶段失败和重启不重复收费。
- 新结果替换当前对应内容；历史通过全部任务读取；不新增比较与版本编号。
- 刷新后恢复最后成功分析；重新分析失败不丢旧结果；资料变更有过期提示。
- 1280／1440／1920桌面检查、居中加载、下拉互斥、键盘焦点和固定媒体预览通过。
- 真实接口验收与界面模拟分开记录，交付调用任务号、实际结果及费用，不用模拟素材证明可用。
