# 工作台结果流与输入区交互规范

日期：2026-10-28  
状态：依据用户追加要求补充的定稿规范；尚未实现页面或后端。本文替代旧方案“发送后保留参考图和参数”的约定。

## 1. 普通技能与智能体分开承载

普通技能包括图片生成、模特换装、场景复刻和视频生成，复用同一工作台布局。每个技能的草稿、素材、任务与结果流独立；切换技能只切换视图，不中断后台任务。

```text
┌───────────────────────────────────────────────────────────┐
│ 当前技能名称与一句话说明                    后台状态入口   │
├───────────────────────────────────────────────────────────┤
│ 本技能独立任务结果流                                      │
│ ┌───────────────────────────────────────────────────────┐ │
│ │ 执行状态 · 当前步骤                       打包下载     │ │
│ │ 产物缩略图 / 视频封面 / 未完成占位                     │ │
│ │ 每项：预览提示词 · 复制提示词 · 重新生成               │ │
│ └───────────────────────────────────────────────────────┘ │
│ 更多批次，同样的卡片骨架                                  │
├───────────────────────────────────────────────────────────┤
│ [叠放参考缩略图]  大输入框                                │
│ 上传参考图/视频  模型与常用参数  参数矩阵       确认发送    │
└───────────────────────────────────────────────────────────┘
```

一键对标等智能体**不显示通用底部输入区，也不为其预留空白高度**。进入智能体后使用完整流程页面，在对应阶段上传商品与同行图、设置参数、生成白底、提交替换和查看结果。继续保留已确认的三栏 item，不把智能体的配置强塞进普通输入框。

## 2. 中间区域只承载技能说明、结果和后台状态

技能说明位于页面顶部，简短展示，不在每张结果卡重复。普通任务没有“我的提问/AI 回复”聊天气泡，发送后直接出现后台任务卡。

每次成功发送对应一张批次卡；单张与批量共用卡片骨架。默认只展示：

- 执行状态；批量时可包含已完成/总数及失败数。
- 当前执行到哪一步，例如等待执行、提交生成、上游生成中、保存结果。
- 已保存产物的缩略图；视频使用封面及播放标识。
- 打包下载入口。
- 每个产物 item 的预览提示词、复制提示词、重新生成操作。

参数表、长提示词、原始输入、费用、创建时间、耗时明细、实时日志和技术错误详情通过任务详情弹窗或侧抽屉查看，不在卡片中默认展开。任务详情提供“使用本次设置”，将历史输入填回该技能的新草稿供修改，不执行生成；已有草稿先保留并明确处理覆盖，缺失引用或失效模型须修正后才能发送。失败时当前步骤区域显示一行简短原因，完整内容进详情，不撑高整张卡片。

全局后台状态入口可以汇总其他技能任务，但本技能结果流不混入其他技能内容。状态必须来自后端；没有真实进度就显示步骤，不制造百分比或超时失败。

## 3. 卡片高度与内容密度

单产物卡使用统一基础高度、内边距、缩略图框和操作行；排队、生成、成功、失败共用骨架。建议实现时以 184px 为普通单行卡的初始高度令牌，在桌面稿验收时统一调整，不按每张图片比例改变高度。

- 状态行、媒体区、操作行分别对齐，状态长文单行省略并可查看完整说明。
- 缩略图采用等高容器，图片用 contain 保持完整，空白留底色；点击后看原图，不为适配缩略框裁掉商品。
- 未完成产物使用同尺寸占位，保存成功后原位替换，避免卡片大幅跳动。
- 批量缩略图允许按固定网格增加行，卡片高度按行数增长；同行卡间距一致。多行是有内容需要时的例外，不强行把大量成品塞进单行。
- 长提示词默认不展开。需要编辑、预览或智能体逐项配置时，在弹窗/抽屉中显示多行内容；智能体三栏 item 如需扩展，使用统一的多行间距，不影响普通结果卡基准。
- 卡片不循环播放视频，封面高度与图片一致，视频在预览弹窗内播放。

每次只更新变化的状态和产物，不因 SSE 或刷新重新挂载整个列表。用户查看历史位置时，新结果提示出现，但不强制拉到底部。

## 4. item 操作

| 操作 | 行为 |
| --- | --- |
| 预览提示词 | 弹窗只读展示本尝试的实际执行提示词；尚未锁定提交时明确标为当前待执行稿，不冒充最终执行稿 |
| 复制提示词 | 复制与预览一致的完整文本，不复制截断内容或重新渲染后的最新模板；失败提供可手动选中的文本 |
| 重新生成 | 使用该 item 已保存的输入与提示词快照创建新尝试，显示本次模型和预计点数；绕过旧成品缓存，不重跑整批、不覆盖旧图；失效模型须明确更换 |

同一批不同 item 的最终执行稿可能不同，预览和复制必须绑定具体 item/尝试。正在运行或待核实项不能借“重新生成”重复提交同一次尝试；先处理未知状态或等待当前尝试结束。旧图仍可预览与下载。

修改后再生成沿用 Q6：未提交可保存修改，提交锁定后修改用于新尝试。新尝试显式启动，不能仅打开提示词或编辑器就调用模型。重新生成直接使用历史快照，不依赖已经重置的底部输入区。

## 5. 图片与视频预览

所有上传缩略图和产物缩略图点击可打开统一媒体预览弹窗。图片支持查看原图、缩放和适应窗口；视频使用真实播放器，提供播放/暂停、进度、音量和全屏，不只放大视频封面。

批量媒体可上一项/下一项。关闭弹窗暂停视频，并将焦点返回触发的缩略图。支持 Escape 关闭；预览加载失败可重试，不因此将生成成功状态改成失败。

视频上传后后台/上传处理生成封面，封面尚未就绪时用视频占位图标和真实上传状态，不显示文件名或伪造预览。普通预览不自动播放声音。

## 6. 底部输入区

仅普通技能显示，包含：

1. 大输入框：填写本次提示词或补充要求，作为输入区主要空间。
2. 上传参考图/视频按钮：按技能和当前模型的真实能力动态显示文字、类型和数量限制。
3. 已上传参考素材的叠放缩略图，按商品、人物、场景等角色区分。
4. 模型选择及常用参数控制，例如画幅、数量、分辨率或视频时长。
5. 参数矩阵按钮：弹窗配置该技能提示词特有参数，例如换装范围、差异方式、文案等；同窗可按分区展示模型专有参数。
6. 确认发送按钮：显示本次输出数量与预计点数；点数未知如实显示，不把未知当作免费。

业务参数与模型参数使用不同分区和来源，不能因为都在矩阵里就混成一份任意 JSON。高频且影响素材角色或替换对象的必要字段在当前操作区给出摘要/错误定位，不让用户靠猜测完成必填。一个参数只有一个真实值，输入区快捷控制与弹窗编辑同一份草稿。

参数矩阵是弹窗，不是常驻大面板。打开/关闭弹窗不触发生成；保存参数仅更新本次输入。提交期间显示发送状态，后台接单后恢复输入能力，不等待媒体生成结束。

## 7. 发送成功后重置

**成功指后台已经持久化任务与输入快照，并返回可确认的任务编号，不是开始上传，也不是媒体生成完成。** 后台接单后立即插入结果卡，将底部输入区初始化为当前技能的默认状态：

| 输入内容 | 接单成功后 |
| --- | --- |
| 大输入框 | 清空本次内容 |
| 上传图/视频及角色配对 | 清空当前选择，不删除已保存素材或任务引用 |
| 数量、画幅、时长、模型专有参数 | 回到当前技能及默认模型的合法默认值 |
| 参数矩阵的业务参数、临时提示词覆盖 | 回到已发布技能默认值 |
| 模型 | 回到当前技能配置的默认可用模型；无可用默认时明确要求选择 |
| 上传错误、临时进度、估算缓存、未发送草稿 | 清除，重新计算默认状态 |

当前技能、左侧分类、已有结果流与后台任务不重置。技能和模型的全局设置不改动。此次规则明确替代旧文档“保留参考图与参数，只清空补充要求”的约定。

提交校验失败、后台拒绝或确定未接单时保留全部输入，方便修改重发。网络断线、响应丢失时先用同一幂等标识核实是否已创建任务，不盲目清空，也不换标识重复创建。

重置须覆盖后端草稿，否则刷新会恢复刚刚已经提交的旧内容。任务建立、输入快照保存与对应草稿消费/重置应使用一致的修订检查；延迟自动保存或旧响应不能把旧草稿写回来。提交过程中短暂锁定本次草稿；若允许用户提前输入下一条，则只清除被确认的那版草稿，绝不清除后来新输入。

## 8. 上传按钮自动适配

上传规则由**已发布技能的素材角色定义 ∩ 当前模型已验证输入能力 ∩ 应用文件规则**共同决定。不得从提示词正文里的“多张”或“视频”几个字猜上传合同。

| 条件 | 展示与校验 |
| --- | --- |
| 技能无素材输入且模型也不支持 | 隐藏上传入口，不占大输入框空间 |
| 单张角色 | 单选，只允许该角色类型；已有图可明确替换 |
| 多张角色 | 多选并显示已选/可用数量，不自动截断 |
| 支持参考视频 | 只有技能声明且模型验证支持时才开放视频选择及其时长/大小限制 |
| 多种角色 | 从同一上传入口选择角色，缩略图用中文角色标识；不靠文件名识别角色 |
| 切换到不支持现有引用的模型 | 显示不兼容原因，保留待处理选择，不静默丢图，也不偷偷提交不支持的引用 |

文件选择、拖拽、复制粘贴使用同一规则。最终请求仍由后端校验去重后的真实引用集合。上传中/失败素材不得被当作有效素材提交。

目前 TT Image 2.5 是图片引用；Omni 当前仅确认参考图片能力，不因“视频生成”入口就开放参考视频。新增已验证能力的模型后通过模型定义和技能角色声明扩展，不改一套上传 UI。

## 9. 便利贴式素材叠放

默认显示小型叠放缩略图：最多露出数张轻微错位的卡片及总数量标记，**不显示文件名**，为大输入框保留空间。商品图、人物图等必要角色用短标签或图标辅助区分。

鼠标移入后展开全部缩略图；较多时使用有最大高度的可滚动浮层，不让输入框无限增高。展开方向优先向上，避免遮挡发送按钮。鼠标从叠放区进入浮层时保持展开，不因跨过间隙立即收起。

每张图可点击预览或明确移除；展开不自动播放视频。键盘聚焦与点击素材数量按钮也能展开，浮层内支持逐项操作，Escape 收起。无障碍名称使用角色与序号，例如“商品参考图 2，点击预览”，无需展示文件名。

默认叠放可以有克制的便利贴质感和轻微旋转，但不能遮住数量、上传失败标记、删除控件或角色。展开动效使用现有 120/200ms 刻度并支持减少动态效果。

## 10. 打包下载

批次卡保留打包下载入口，有已保存产物时可用，显示可下载数量。部分完成时允许下载已有结果，明确未完成或失败项没有包含；不宣称整批完成。

打包由后端建立可恢复的导出任务，不让浏览器循环抓图拼 ZIP。重复点击复用同一产物集合的有效打包任务；产物集合变化后可创建新包。关闭页面不停止打包，再打开可下载已完成文件。文件包使用稳定的 item/版本编号命名，界面仍只显示缩略图。

## 11. 组件与验收

普通技能复用 SkillWorkspace、TaskBatchCard、ResultItem、BottomComposer、ReferenceStack、ParameterMatrixDialog、MediaPreviewDialog；智能体共用媒体和状态组件，但使用独立流程布局，不挂载 BottomComposer。这些是拟议组件职责，不代表已有代码。

验收覆盖：

1. 普通四技能都有技能说明、各自结果流和底部输入区；智能体没有通用输入区或残留占位。
2. 单行卡在各状态及横竖媒体下高度一致；批量按网格增行，日志/提示词不默认撑高卡片。
3. 每个 item 可预览实际提示词、完整复制、单项重新生成；旧结果与原批次完成度保留。
4. 图片点击大图，视频点击可播放；弹窗关闭暂停并恢复焦点，加载错误不篡改后台任务状态。
5. 成功接单后文字、素材、模型和参数均初始化；刷新不还原已消费的旧草稿。
6. 发送失败或受理未知不丢输入；幂等重试与延迟自动保存不重复建任务或覆盖下一条草稿。
7. 上传入口随角色、模型能力和容量调整；TT/Omni 不允许未验证的视频参考；不显示文件名。
8. 叠放素材支持悬浮、点击和键盘展开全部；大量素材滚动查看，不挤压大输入框或遮住发送按钮。
9. 参数矩阵弹窗按技能特有参数与模型参数分区，改变值后估算和校验同步更新。
10. 打包部分结果说明范围，打包关闭页面仍执行，重复点击不重复导出同一集合。

历史设置复用、重试分类、素材与磁盘保护及恢复验收按 [可靠性与运营效率补充](首版可靠性与运营效率补充.md) 执行。当前仅完成文档规格；以上浏览器、接口和并发行为在应用开发后测试。
