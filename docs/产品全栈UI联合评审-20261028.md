## 1. 判断

方案适合做成独立的本地创作工作台。首版范围是四个普通技能与一个图片智能体，主要风险不是功能数量，而是素材角色、逐图任务、排队编辑、供应商能力和消耗统计能否使用同一套执行规则。

已确定 React + TypeScript + Vite + shadcn/ui + Tailwind CSS；后端 Fastify + SQLite + 持久化 Worker；Windows 通过 run.bat 启动。当前没有前后端程序或可运行 UI，文档检查不能代替代码测试、Windows 启动测试、浏览器验收或真实生成质量验证。

图片默认 TT Image 2.5，视频默认 Omni Flash，复用现有系统的媒体协议并支持配置新增模型。每技能独立 Markdown；无首版灵感库。抖音链接获取、人工验证码、爆款视频智能体、文本模型反推与提示词收藏后续再做。

## 2. Q1–Q7 最终业务结论

| 决策 | 用户确认的规则 |
| --- | --- |
| Q1 算力定位 | 统计与余额提醒，不强制拦截，不冻结或预占；缺失点数显示未知，不视为免费 |
| Q2 白底范围 | 可选，默认直接使用自有商品原图；需要时主动生成或选择已有白底图 |
| Q3 对标图选择 | 用户勾选需要替换的图，统一替换对象可逐图覆盖；未选不生成、不计点 |
| Q4 消耗时点 | 结果可靠保存后计本机点数，明确失败不计；提交未知、上游成功待保存分别单列；供应商费用另记 |
| Q5 逐图工作台 | 独立“生成白底图”按钮；白底生成期间可点“一键替换”，每图一个 item，等待所选白底成功后自动调度；图片默认 20 并发、可修改 |
| Q6 排队编辑 | 尚未提交模型可保存修改；已提交输入锁定，修改用于用户明确启动的新尝试；批量修改限明确选中的未提交项 |
| Q7 白底失败 | 保留为“等待白底图处理”，用户可重做、改用上传图或商品原图；主动换参考后继续未提交项，不自动降级 |

Q5 的用户回答替代了原先“自动继续还是白底审查”的问题框架：**首版不设置白底审查开关，也不因单独生成白底图就自动创建替换任务。** 只有用户已点击一键替换的 item 才会等待依赖并自动继续。

## 3. 产品经理分析

### 3.1 入口保留，操作重点分清

- 图片生成：按技能要求与商品参考生成独立成品。
- 模特换装：人物身份、穿着展示与替换范围是核心。
- 场景复刻：场景、构图与商品关系是核心，包括挂拍、平铺等非上身展示。
- 视频生成：提示词、参考图与模型参数直接生成视频，不包含视频解析智能体。
- 一键对标：整理一组同行图，逐图配置，后台批量替换为自有商品。

普通技能和智能体复用媒体执行器，不为入口分别维护 API、任务恢复和消耗逻辑。首版不接视觉预检模型；用户判断替换对象与商品资料是否充分，系统只校验格式、必填、数量、参数与依赖等确定规则。

### 3.2 白底准备与批量替换解耦

原稿曾将白底设为必经步骤；Q2/Q5 已修正为独立可选操作。直接使用原图、选择已有白底、绑定正在生成的白底任务，是三条明确路径，不隐式创建额外付费步骤。

替换依赖绑定具体任务 ID，不能绑定“最近一张白底图”。原始商品图作为款式真值，生成白底仅作辅助，不能把重绘误差当成真实商品细节。

### 3.3 完成、质量与新增尝试分开

结果生成并可靠保存即完成，商品细节、文字与场景质量由用户判断，不自动额外花钱重做。再次生成保留旧图、旧输入与原消耗，新尝试单列进度；一项失败不使其他已经交付的结果消失。

不将“完美复刻”作为承诺。后续质量测试用固定样本集记录版型、图案、人物、场景与文字错误，不额外建设审批平台。

## 4. 全栈开发分析

### 4.1 模型合同先于模型名称

原适配器在 imageShape 为 string 时可能只取 refs[0]，新系统必须拒绝不兼容的多引用调用，不能静默丢图。新增模型需声明已验证的参数和协议映射；同协议配置扩展，新协议编写适配器。

TT 当前预设最多 16 张参考。按每个 item 最终引用集合去重并校验：原商品组、当前同行图、可选白底和辅助参考均计入；不能仅限制单个上传区。30MB 编码引用限制与 background 等固定参数也按实际适配器校验。

### 4.2 技能声明形成可执行契约

五份 Markdown 目前只是草稿。开发时需要 Schema、变量校验、提示词分区、操作注册、发布修订和数据库快照。空目标不可提交，已有白底须有效，白底任务须属于可访问创作记录且产物类型匹配；所选模型需支持该步骤最终引用数量与固定参数。

一键对标声明两个操作：prepareWhite 独立单图生成；replaceSelected 批量替换并解析外部白底依赖。引用解析不调用生成接口。单项覆盖稿不改全局模板，模板更新不静默覆盖已排队项。

### 4.3 排队编辑与提交竞态

未提交 item 保存使用预期修订；Worker 原子领取具体修订并锁定提交输入。保存与领取竞争时，只能一个成功；若已进入提交临界区，返回明确冲突，保留本地编辑并提供新尝试入口。不能出现“保存成功但这次用了旧参数”。

依赖成功时只解析已绑定任务的产物引用，不任意更新其他执行输入。白底失败后重绑只作用于未提交且明确选中的 item；已提交尝试不改引用。

### 4.4 持久化、恢复与并发

所有已提交操作由 Worker 执行，关闭页面不取消。图片共享全局活动生成上限，默认 20，可配置，并遵守已知供应商/模型限流；不是每批 20，也不是最多 20 张素材。视频另有上限。等待白底不占活动生成槽，上游正在运行的任务在查询间隙仍占槽。

提交未知项隔离核实，不能盲目重复生成；上游成功后下载失败只重试下载。结果、任务状态、消耗流水和事件在同一事务提交，重复事件不重复应用或计点。调低并发不取消在途任务。

### 4.5 算力不再承担预算门禁

初稿的冻结、预占、余额不足禁用及恢复额度检查已被 Q1/Q4 替代，不作为实施要求。成功保存按锁定规则计点，失败不计本机点数，未知/待保存单列；供应商真实费用独立核对。同一白底被多个 item 或批次引用，不能重复统计全局消耗。

## 5. UI 设计分析

### 5.1 逐图三栏是主操作区

左侧同行爆款图；中间本 item 的模型、参数、商品/白底/辅助参考缩略图和“编辑提示词”入口；右侧状态与结果。素材点击弹窗放大。默认系统提示词可折叠，不要求用户日常阅读长脚本。

普通技能底部浮动输入台以大输入框和叠放素材为主，技能特有参数进入参数矩阵弹窗，常用模型参数留在输入台；成功接单后全量初始化本次输入，失败保留。智能体不使用底部输入台，在完整流程内完成三栏配对与批量提交。

### 5.2 数量与算力分开表达

普通生成显示成品数量；对标图显示每图版本数与成品总数；白底资料数量、替换请求数在相应操作区分开。预计点数在发送前展示，已计与待核实点数进任务详情。不能把 10 张成品加 1 张白底统称“11 张成品”。

### 5.3 状态说明必须支持下一步

区分“等待白底图”“等待白底图处理”“排队”“生成中”“待保存”“完成”“失败”“待核实”。白底失败提供重做和主动换参考入口，不自动改图。全局任务入口区分进行中和待处理，切换技能仍可找到需要处理的任务。

排队项保存反馈与运行状态分开；已提交时说明修改将用于新尝试。页面不能根据等待时间自行认定失败，技术提交与查询细节放日志。

### 5.4 首次设置不制造额外门槛

媒体凭证、实际模型能力和技能可执行性属于必要检查。点数规则或额度未设置只显示提醒，不禁用生成。遵循桌面端规范，验证 1280/1440/1920 宽度与 Windows 缩放；不做手机适配。
