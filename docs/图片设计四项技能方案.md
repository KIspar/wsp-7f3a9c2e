# 图片设计四项技能方案

日期：2026-10-28  
状态：功能方案，尚未实施。本文整理本轮新增需求；标为“建议”的规则是待实施方案，不代表当前系统已经支持。

## 1. 功能结构

图片设计统一整理为四项技能，共用素材、参数、任务、结果和下载组件。

| 技能 | 用户要完成的事 | 主要输入 | 输出单位 |
| --- | --- | --- | --- |
| 通用操作 | 根据商品和文字要求自由创作图片 | 多张产品图、可选单张参考图、提示/要求 | N 张独立成品 |
| 爆款复刻 | 参考一张成熟图片的构图和表达，用自己的商品重新创作 | 多张产品图、单张参考图、额外要求 | N 张复刻成品 |
| 详情图设计 | 围绕同一商品设计一套有顺序的详情图 | 多张产品图、产品名、商品卖点/参数、屏类型 | 每组 M 屏，可生成 N 组 |
| 图像编辑 | 修改已有图片中的人物、文字、元素、风格等 | 待编辑图片、辅助参考、编辑要求 | 每张目标图 N 个版本 |

建议将现有“图片生成”升级为“通用操作”，将“场景复刻”升级为“爆款复刻”，新增“详情图设计”和“图像编辑”。模特换装保留为专用技能，一键对标仍归智能体，视频生成保持独立。

旧批次保留原技能名称、版本和输入快照，历史记录不重写。技能内部 ID 可继续使用稳定 ID；字段升级通过新修订和显式草稿迁移处理，不直接套用旧字段生成新任务。

## 2. 公共输入与生成规则

### 2.1 公共字段

| 字段 | 控件与默认值 | 规则 |
| --- | --- | --- |
| 产品图片 | 多图上传、拖拽、粘贴、素材选择 | 同一商品可上传多个角度或规格；不因上传多张而自动增加生成数量 |
| 参考图 | 单图上传入口 | 通用操作建议可选；爆款复刻必填。替换已上传图片前明确提示 |
| 提示/要求 | 多行文本框 | 支持自由描述，原文进入任务快照；长内容按需展开 |
| 语言 | 自定义下拉，默认简体中文 | 指成品中的文字语言；不强迫用户用对应语言输入提示词。建议提供简体中文、繁体中文、英语、日语、韩语及“其他语言”输入 |
| 比例 | 自定义下拉，建议默认 3:4 | 优先提供 1:1、16:9、9:16、4:3、3:4；其他比例按模型能力提供 |
| 分辨率 | 自定义下拉，默认 1K | 提供 1K、2K、4K，仅启用当前模型支持的选项 |
| 生成数量 | 自定义 NumberInput，默认 1 | 正整数，支持直接输入和自定义加减按钮；上限与后台设置一致 |
| 模型 | 统一模型选择组件 | 只显示已启用、支持对应技能的模型 |

本轮图片设计的数量控件改为输入框，覆盖此前图片输入台采用数量下拉的设计。视频数量控件不在本轮调整范围内。

语言控制成品文案，不要求每张图片都带字。通用操作、复刻、编辑没有文字需求时，不主动添加宣传文案；详情图根据各屏任务组织文字。

比例和分辨率分别保存，1K/2K/4K 是模型分辨率档位，不能一概承诺为 1024/2048/4096 的某个固定边长。结果显示实际像素尺寸。不支持的组合须在提交前说明，不静默降级、裁图或切模型。

### 2.2 素材提示

产品上传入口下展示简短提示，完整说明在帮助浮层中查看：

> 建议上传背景干净的独立商品图。商品角度尽量接近参考图；参考图包含多个规格时，请补齐对应规格的商品图片。

参考图说明：

> 上传你希望参考的图片，可以是商品图、场景图或使用图。

多规格图片需能标注“黑色/L 码”“米色/M 码”等用途，至少允许用户填写图片备注，避免 AI 将不同规格误认为同一外观。多个无关商品建议拆成不同任务；本轮不默认做商品与参考图的全组合。

图片数量、格式、体积及单次请求的总参考数量均以前后端共同校验为准。产品图与参考图共同占用模型的图片配额，不能分别达到上限后再超额提交。

### 2.3 统一任务流程

1. 添加素材、填写内容，系统保存当前技能草稿。
2. 点击预览生成，校验必填项、图片绑定、模型能力和总数量。
3. 预览清楚列出最终提示词、素材角色与序号、输出清单和预计算力。
4. 用户确认后，后台接单并持续执行；已接单任务不依赖页面停留。
5. 每张成品独立展示状态，支持预览、下载、再生成和进入图像编辑。

继续使用现有接单、幂等、单项重试和历史快照机制。成功接单后消费本次草稿；失败或接单结果待核实时保留草稿。

## 3. 通用操作

### 输入

- 产品图片：多张。建议允许纯文字创作时不上传，但必须至少提供提示/要求或一张图片。
- 参考图：最多一张，建议可选。
- 提示/要求：自由输入。
- 语言、比例、分辨率、生成数量、模型：使用公共字段。

### 行为

产品图决定商品真实外观，参考图决定用户指定的构图、场景、风格或人物参照。未指定参考用途时，不把参考图中的旧商品当作新品外观依据。

生成数量 N 表示 N 张独立成品；多张产品图是同一任务的共同素材。默认允许合理构图变化，但不能把多个结果拼进同一张图。用户明确要求拼贴时例外。

### 例子

上传同一外套的正面、侧面图，要求“都市休闲穿搭，午后街景，人物自然行走，不加文字”，数量 3，得到 3 张独立图片。

## 4. 爆款复刻

### 输入

- 产品图片：至少一张，可多张。
- 参考图：必须且只能一张。
- 额外要求：可选。
- 语言、比例、分辨率、生成数量、模型：使用公共字段。

### 复刻规则

优先提取参考图的布局、主体位置、机位、场景、光影和视觉层级，用自有商品重新创作。新品的结构、配色、图案、标识和可见材质以产品图为准。

额外要求是本次明确修改的依据。例如：

- “人物改为男性，保持构图和背景。”
- “换成室外街景，保留主体位置。”
- “把‘夏季新品’改成‘秋日上新’。”
- “删除参考图左上角的品牌 Logo。”
- “只保留场景，不要文案和图标。”

建议增加“参考文案处理”选项，默认“去除旧宣传文案”，可选“保留布局，改用我的文案”“按额外要求处理”。不默认沿用旧图中的品牌、价格、销量、功效和促销信息。产品本体标识与参考图广告标识应区分；用户明确要求去除商品标识时再执行。

生成数量 N 表示使用同一参考图生成 N 张成品，不生成 N 个参考目标。多参考逐图替换继续由现有一键对标承载。

## 5. 详情图设计

### 5.1 输入

| 字段 | 规则 |
| --- | --- |
| 产品图片 | 至少一张，可多张；允许补充细节、规格及尺码资料图 |
| 产品名 | 必填，用于统一整组商品称呼 |
| 商品卖点/参数与设计要求 | 主文本框，可填写卖点、尺码、面料、参数、风格、人物和场景要求 |
| AI 编写 | 根据已上传产品图片、产品名和已有文字，生成卖点及表达建议 |
| 详情图类型 | 有顺序的屏列表；每个列表项对应一张图 |
| 平台 | 默认抖音，首期可只开放抖音，不承诺自动适配未核实的平台发布限制 |
| 语言、比例、分辨率 | 整组统一，默认中文、3:4、1K；作为建议默认值 |
| 生成数量 | 默认 1，界面标明“生成组数”，并实时显示总图片数 |

主文本框可以用“已确认卖点与参数”“视觉要求”两个辅助入口帮助填写，但不要求用户拆成很多必填表单。图片可见信息、用户确认事实和设计建议在 AI 草稿中分开表达。

### 5.2 AI 编写流程

1. 点击“AI 编写”，明确本次使用的产品图片、产品名和已有文字。
2. 返回可编辑的候选内容，采用内联预览或小面板，不直接覆盖原文。
3. 用户选择“插入”“替换”或“取消”；有原文时替换需明确操作。
4. 仅在用户采纳后写入草稿，不自动开始图片生成。

AI 可提炼可见的外观、版型和展示角度，给出文案表达建议。不能从照片推断尺码、成分比例、容量、认证、功效、销量、售后承诺等事实；未知信息标为待补充，不能写进最终成品。用户已有的具体参数应保留原值。

AI 编写需单独接入具备图片理解能力的文本模型，记录调用状态及用量；不能直接把图片生成模型当作文本分析接口。未接入真实模型时按钮明确显示未配置，不返回冒充真实分析的模拟卖点。

### 5.3 详情图类型

将“场景氛国图”规范为“场景氛围图”，“核心实点图”规范为“核心卖点图”。

| 类型 | 内容重点 | 所需依据 |
| --- | --- | --- |
| 首屏主视觉 | 产品、主标题、主要购买理由 | 产品名、已确认的核心卖点 |
| 使用场景图 | 商品在具体生活场景中的使用 | 使用场景和人物要求 |
| 场景氛围图 | 氛围、搭配、风格表达 | 风格和场景要求 |
| 品牌故事图 | 品牌理念、来源和叙事 | 用户提供的品牌信息 |
| 效果对比图 | 有依据的前后或规格差异比较 | 对比素材、条件和真实信息 |
| 工艺制作图 | 做工、结构、制作过程 | 工艺资料；不凭照片编造生产过程 |
| 配件/赠品图 | 包装、配件、赠品组成 | 实际配件及赠品清单 |
| 售后保障图 | 服务政策、承诺和联系指引 | 实际售后政策 |
| 核心卖点图 | 一屏讲清一个主要卖点 | 已确认卖点 |
| 多角度图 | 正面、侧面、背面等 | 对应角度实拍；缺失角度须提醒 |
| 商品细节图 | 面料、缝线、口袋、结构细节 | 清晰细节图或确认描述 |
| 尺寸/容量/尺码图 | 测量示意、容量、尺码信息 | 用户提供的具体数据 |
| 详细规格/参数表 | 规格、成分、型号等信息 | 完整参数原文或表格 |
| 系列展示图 | 多颜色、多规格或系列关系 | 每个规格的图片和名称 |
| 商品成分图 | 材质或成分组成 | 用户提供的成分资料 |
| 使用建议图 | 穿搭、使用、清洁或保养建议 | 已确认的适用方式和注意事项 |

用户按需选择，不能默认勾选全部 16 种。建议初始只选首屏主视觉，可快捷添加“基础详情组合”：首屏主视觉、核心卖点、使用场景、商品细节、尺码/参数；需要资料的屏在提交前提醒补齐。

屏列表允许调整顺序、删除、重复添加同类型，并为每屏填写局部要求。例如两个“商品细节图”分别展示领口和袖口。结构化数据缺失时，阻止该屏生成并定位字段；不要求无关类型填写品牌故事或售后政策。

### 5.4 数量与组的一致性

选定屏列表的长度为 M，生成组数为 N，总成品数为 M × N。

例如选首屏、核心卖点、场景、细节四屏，生成组数 1，提交 4 张；组数 2，提交 8 张，分成两组。界面同时显示：`4 屏 × 2 组 = 8 张`，避免“生成 1 张”与四屏选择冲突。

每组共用商品、语言、配色、字体表达、人物约束和视觉风格。先形成组内创意计划，再展开逐屏任务；这份计划固化每屏标题、内容、视觉要求及关联素材。不能简单对每屏复制同一提示词，也不能保证仅靠提示词就让人物绝对一致；模型支持主体引用时绑定同一人物参考。

每屏独立排队、重试和选择版本。重新生成某一屏不改动整组，已完成图片和原有顺序保留。总数超过系统上限时阻止提交并解释，不截断屏列表。

对参数表和尺码图，建议由结构化事实加确定性文字排版完成；AI 主要生成背景及视觉素材，避免把精确参数完全交给图像模型渲染。预览保留原始参数，便于核对。

## 6. 右侧排版与长图下载

### 6.1 入口与布局

详情图结果按组展示，每组提供“排版”按钮。点击打开右侧 Sheet 排版面板，显示本组屏列表和纵向长图预览，结果页继续保留上下文。

排版面板建议宽 480–640px，受窗口宽度约束，长图在面板内缩放预览和滚动。只在打开排版时占据右侧空间，不长期挤压生成结果。

### 6.2 操作

- 拖动图片调整上下顺序；同时提供键盘和“上移/下移”操作。
- 每屏选择一个已成功版本，可排除不需要的屏。
- 调整长图宽度、图片间距及背景色；默认无缝拼接、等宽排列、保留完整图片比例。
- 展示包含的屏数、预计导出像素尺寸和格式。
- 保存本组排版草稿，点击“下载长图”导出；也可继续下载单图或 ZIP。

这一步是本地排版和拼接，不再调用图片模型、不额外计生成算力。首版不扩展为自由画布、图内文字编辑器或任意叠图工具。

### 6.3 导出规则

按选定宽度对每张图等比缩放，不裁切、不拉伸；长图高度由实际图片尺寸、间距和边距计算。默认宽度建议为选中图片中的最小原始宽度，避免默认放大造成模糊；允许用户选择其他导出宽度并提示放大。

首版支持 PNG/JPG：PNG 可保留透明度，JPG 需指定背景色。格式、色彩与像素尺寸在下载前明确展示。不得在方案中预设未经核实的抖音长图上传上限。

仅成功且素材可读取的图片可参与导出。有失败或未完成屏时，提示“继续生成”或“仅导出已完成的 X 屏”，不静默漏图。全部未完成时禁用导出。

长图导出生成独立布局快照，记录素材 ID、所选版本、顺序、尺寸、间距和背景。重试某屏后不自动替换已选导出版本；用户明确选择后再更新。导出失败保留排版草稿，可重试。

后端使用现有图像处理依赖完成拼接；按总像素和内存预算校验。超大图片给出降低宽度或拆分长图的选项，避免浏览器 Canvas 超限或内存耗尽。拆分仅按完整屏边界进行，不截断商品或文字。

## 7. 图像编辑

### 7.1 输入和图片角色

产品图片/待编辑图片至少一张，可多张；附加参考图片可选。上传后明确标记两种角色：

- **待编辑图**：本次需要输出新版本的图片。
- **辅助参考图**：只用于人物、商品或风格参照，不因为上传就自动生成结果。

需求文本必填。界面提供“改人物、改文案、去元素、改风格、自由编辑”快捷提示，点击只插入可编辑的句式，不自动提交、不锁定用户表达。

语言、比例、分辨率、生成数量仍使用公共控件。图像编辑的比例建议默认“沿用原图”；只在所选模型支持对应处理时启用。模型不支持时，预览前要求选择可用比例并说明画幅可能变化。

### 7.2 图片序号与引用

图片使用稳定编号，例如“图1”“图2”“图3”，同时展示角色。支持在输入框中插入图片引用标签，方便写出明确关系：

- “将图2、图3中的模特改为图1中的同一人，保留各自服装、姿态和背景。图1仅作人物参考。”
- “把图1中的‘夏季新品’改成‘秋日上新’，其他文字和布局保持不变。”
- “去掉图2右上角的图标，补全背景。”
- “将图1改为松弛感的都市休闲穿搭海报，保留商品款式。”

编号绑定到素材 ID，移除图2后不将图3自动改称图2。引用图片被移除或失效时，标记引用失效并阻止提交，避免改错图。新一批草稿可重新从图1编号。

后端为每项编译明确的“目标图片 + 辅助参考 + 编辑指令”映射，并将展示编号转换为模型请求中的实际图片顺序。若用户文字中的图号与角色冲突，提交前定位要求修正。

### 7.3 输出数量与质量边界

勾选的待编辑图片为 K 张，生成数量 N 在此标明“每图版本数”，总输出 K × N。辅助参考不计入输出。模型每次收到当前目标图以及任务明确需要的辅助图；涉及多图对比时可包含其他目标图作为参照，但仍只有当前目标产生本项输出。

优先修改指定元素，其他内容尽量保留。图像模型可能改变局部细节，不能承诺像素级无损修改；精确替字可在后续引入文字层编辑。修改前后支持同屏预览或切换，原图永久保留。

“直接生成某种类型图片”由通用操作承载；图像编辑没有待编辑图时引导前往通用操作，避免两个入口职责完全重叠。

## 8. 页面与公共组件方案

沿用 React + TypeScript + Vite、shadcn/ui 和 Tailwind 语义主题变量。所有可见下拉、数值、勾选、确认与排版操作继续使用自定义组件。

### 通用操作、爆款复刻、图像编辑

复用当前紧凑两行输入台，不恢复大块底部面板：

- 第一行：素材入口 + 提示/要求，图像编辑附图片编号引用入口。
- 第二行：模型、语言、比例、分辨率、NumberInput 数量 + 参数 + 预览生成。
- 素材详细说明与图片列表在浮层展开；低频参数放入参数面板。
- 窗口较窄时参数栏自然换行，结果区底部避让使用实际输入台高度。

### 详情图设计

信息较多，建议采用可折叠的内联配置区：上部商品信息，中部有顺序的屏列表，下部结果组。只保留紧凑的提交摘要，例如“4 屏 × 1 组，预览生成 4 张”，不把完整表单塞进固定底栏。

排版使用右侧 Sheet；屏类型选择使用可搜索的自定义列表，已添加的屏是独立条目，可重复、排序、添加局部要求。

### 建议抽取的业务组件

| 组件 | 职责 |
| --- | --- |
| ProductImageInput / ReferenceImageInput | 组合现有 UploadRole，显示角色、说明、单多张限制 |
| ImageGenerationControls | 语言、比例、分辨率和 NumberInput 数量，共用能力校验 |
| ImageReferenceEditor | 稳定编号、角色与图片引用，不按当前数组下标推断 |
| DetailScreenList | 选择屏类型、排序、删除和局部要求 |
| SellingPointAssistant | AI 编写状态、建议预览和采纳 |
| DetailGroupResults | 按组和屏顺序展示成品，选择版本、单屏重试 |
| LongImageLayoutSheet | 组图排序、排版草稿、预览与导出 |

业务组件组合现有基础组件，不各自实现 Select、数字步进器或弹窗。

## 9. 技术落点与现有系统差距

当前系统是本地模拟版，已有技能加载、素材上传、草稿、计划、接单、后台执行、逐项结果及下载。新增技能不能只增加几份 Markdown 就算完成。

| 范围 | 可以复用 | 需要扩展 |
| --- | --- | --- |
| 通用操作 | image-generate、repeat 批量机制 | 产品/参考分离、语言、分辨率快捷入口、数量输入 |
| 爆款复刻 | scene-recreate、商品外观约束提示词 | 单参考模型、repeat 批量、文案处理、旧草稿迁移 |
| 详情图 | 任务与单图结果框架 | 屏列表、组数展开、组内计划、组/屏标识、版本选择 |
| AI 编写 | 请求状态与用量展示方式 | 图片理解文本模型类别、适配器、接口、候选内容结构 |
| 图像编辑 | 素材、逐目标任务和再生成 | 素材角色、稳定编号、引用解析、编辑模型能力与输入映射 |
| 长图排版 | 图片文件与现有 sharp 依赖 | 排版草稿、组内版本绑定、拼接导出、尺寸与内存校验 |

### 9.1 数据契约

现有 `Draft.fields` 只能保存字符串、数字、布尔值，`batch.mode` 仅支持 repeat/per-target；无法自然表达有顺序的屏列表和组图排版。建议通过新版本契约增加结构化字段，避免把复杂数组塞进 JSON 字符串。

- `imageDesign`：语言、平台和公共业务配置。分辨率沿用唯一模型参数字段，不新增一份冲突值。
- `detailScreens[]`：稳定 screenId、type、order、局部要求、所用参数与素材。
- `groupCount`：详情图组数；与普通 count/编辑 variants 的语义分开。
- `imageBindings[]`：稳定 bindingId、assetId、displayNumber、role、备注。
- `referenceBindings`：编辑目标与辅助参照关系。
- 计划与结果项增加 `groupId/groupIndex`、`screenId/screenType/screenOrder`，保留现有 itemId、variant、attempt 信息。
- `layoutDraft`：组 ID、按顺序的屏及所选 attempt/asset、导出尺寸、间距、边距、背景和格式。

模型能力增加“图片生成、参考复刻、图像编辑、图片理解文本”的可用声明。没有对应适配器或未验证能力时，界面不宣称可真实执行。

### 9.2 接口和后台

继续使用现有 `/api/plan` 与接单接口，在服务端完成新技能校验、组屏展开和编辑引用编译。能力判断采用技能声明和执行器，而非不断添加按技能名称判断的分支。

新增卖点建议、排版草稿保存和长图导出接口；AI 编写与图片生成分开计请求和用量，长图拼接记录本地处理任务，不作为模型调用计费。

模型真实接入需独立完成：生成、编辑和图片理解有各自适配与错误处理。开发阶段可使用明确标注的模拟结果验证流程，但验收“真实卖点提炼”“真实复刻/编辑”必须使用对应真实模型。

## 10. 建议实施顺序

### 第一阶段：统一两项基础图片技能

完成公共素材角色、语言、分辨率、数量输入，升级通用操作和爆款复刻，补齐预览与输入校验。先验证图片配额、数量、提示词、草稿迁移及历史兼容。

### 第二阶段：图像编辑

实现待编辑/辅助角色、稳定编号和引用映射，接入具备编辑能力的适配器，完成逐目标预览、单项重试和前后图对照。

### 第三阶段：详情图组图

实现商品信息、16 类屏、有序屏列表、组数、组内创意计划和单屏任务。同步接入 AI 卖点编写；精确参数屏采用结构化数据与文字排版，不能仅靠图片生成提示词交付。

### 第四阶段：排版与长图

完成右侧排版、拖动/键盘排序、版本选择、布局保存、PNG/JPG 拼接导出及超大长图处理。

各阶段先交付可运行的完整链路，再增加下一阶段入口；不放置点击后无响应的功能按钮。

## 11. 验收清单

1. 四项技能入口与用途清晰，产品、参考、编辑目标各有独立角色。
2. 语言默认中文；比例与 1K/2K/4K 按模型能力校验；图片数量为自定义输入框，默认 1。
3. 通用操作允许无参考图；爆款复刻缺产品图或单张参考图时无法接单，多张参考图不被静默截断。
4. 上传三张产品图、数量 2，普通/复刻技能只生成 2 张，不误生成 6 张。
5. 详情图选 4 屏、2 组，预览与后台均为 8 张；重复同类型屏仍有独立 ID、要求与顺序。
6. 缺失尺码、售后或品牌信息时，仅对应屏提示补充，不虚构内容或阻塞无关类型。
7. AI 编写不会自动覆盖原文或直接出图；失败保留编辑内容；模拟模式不伪装真实分析。
8. 图1辅助、图2和图3待编辑，每图 2 版，得到 4 张；角色和序号与实际模型输入映射一致。
9. 删除被引用的图片会提示失效，剩余图号不漂移，旧任务引用保持可追溯。
10. 排版只操作当前组的已选版本，拖动和键盘均可排序，重新生成某屏不自动改已保存布局。
11. 长图下载顺序正确、等比不拉伸、不漏屏；超大导出和部分失败有可操作的恢复路径。
12. 所有页面复用公共控件，保持当前统一字体及紧凑输入台，1280/1440/1920 窗口无控件重叠。

## 12. 本方案采用的建议默认值

为使后续实现有明确依据，本方案采用以下建议；若后续调整，应同时修改表单文案、校验和数量预览。

- 通用操作：产品图和参考图可选，但提示或图片至少提供一项。
- 爆款复刻：产品图至少一张、参考图严格一张；默认去除旧宣传文案。
- 详情图：默认只选首屏；比例默认 3:4；生成数量表示组数，每组每屏一张。
- 图像编辑：至少一张目标图，辅助图不计输出；数量表示每张目标的版本数。
- 长图排版：首版以纵向等宽拼接为主，不包含自由画布和图中文字重排。

本轮新需求优先于历史文档中“暂不增加爆款复刻”和“仅五项技能”的范围限制。本文是新增功能的实施依据，现有模拟版能力仍以实际代码与验收记录为准。


## 13. 本轮实现状态（2026-10-28）

已完成四项技能表单、服务端校验、计划展开、草稿持久化、结果分组和重试。通用与复刻使用相同公共控件；详情图按屏数 × 组数生成计划；图像编辑保留稳定图号，删除后引用报错，区分待编辑图与辅助图，禁止同一图片同时进入两个角色。

右侧排版可选择每屏的成功版本、拖动或上下移动排序、取消部分屏、保存布局；PNG/JPG 实际等比拼接下载，限制最大宽度 4096px、最大高度 60000px 与 8000 万像素。标题和下载按钮固定，内容独立滚动。默认导出宽度为 750px，放大时提示清晰度风险；背景支持白、浅灰、深色，当前不提供透明背景或边距编辑。

保留旧任务快照。随附旧版技能按已知原始哈希升级，自定义已发布技能不覆盖；旧草稿及技能先归档，新草稿版本递增。历史复用映射旧图片角色，移除已废弃的表单字段并补齐新增默认值。多张旧参考图完整保留，要求用户手动调整为一张后提交。升级前数据库副本保存于 `data/backups/before-image-design-20261028.sqlite`。

当前图片输出仍为明确标识的本地模拟：复制目标或参考图片，不会真实修改人物、场景、文案或分辨率。生成图再编辑会复制所选目标本身，不会替换为其他示例。AI 编写按钮禁用并说明尚未配置图片理解文本模型。真实生成/复刻/编辑适配器、卖点建议审核、精确参数文字排版、编辑前后对照与真实组内视觉一致性验收留待接入真实模型；这些不属于本轮已完成能力。

技术字段以实现为准：`imageDesign` 保存组数、屏、稳定素材号；语言/平台保存在技能字段，分辨率只有模型参数一份；组用 batchId + groupIndex 定位，布局保存确切 attemptIds。没有新增独立 groupId 或 bindingId。
