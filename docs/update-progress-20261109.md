# v0.1.8 更新下载反馈

用户问题：版本窗口只显示「正在下载更新」和转圈，无法判断是否收到数据或正在等待。

## 修改

- 更新子进程测量实际传输字节，按秒发布进度；前端仅在版本窗口或更新面板打开时读取。
- 显示已下载／总大小、百分比、传输速度和预计剩余时间，不为校验／解压伪造进度。
- 区分确认版本、连接下载服务器、下载、SHA256 校验、解压和运行依赖准备。
- 15 秒未收到进度时隐藏过时速度和预计时间，显示等待网络响应；字节流连续 60 秒无数据终止并提示重试。
- 连接 GitHub 最多等待 60 秒；正在持续传输的更新包不再受原 3 分钟总时限限制，上限调整为 30 分钟。
- 超出声明大小、传输不完整、校验失败均拒绝安装。保留后台处理、安装前保存备份与启动失败回滚。
- 旧版客户端必须升级后才具备新反馈，不能给已打开的旧版窗口追补进度。

## 验证

- 更新管理、进度、任务保护和回滚相关 20 项测试通过，覆盖字节统计、上报节流、截断／超大下载、60 秒停滞超时和旧速度失效。
- 生产构建、类型检查通过，`git diff --check` 通过。
- BrowserOS neo 使用隔离数据和本地模拟发布源，经可见点击启动下载。流量使用实际字节计数器测量；校验、解压和依赖阶段由测试夹具模拟。
- 桌面 1440×1000、手机 390×844 检查：百分比、容量和速度可见；模拟网络暂停时显示「等待网络响应」且隐藏 ETA；恢复传输后继续增长；关闭／重新打开窗口保留后台进度。
- 可见界面验证校验、解压及准备就绪阶段；未点击安装、未更改真实数据和凭据。

发布产物沿用 GitHub Actions：四个平台运行环境和完整包、应用更新包、`latest.json`，成功后同步 GitHub Pages。
