# Token01 MiniMax 视频模型

已接入 `MiniMax-H3-Fast`、`MiniMax-H3`。供应商固定为 `https://www.token01.net`，与初和中转站独立保存凭据、调度和计价。

## 配置与使用

1. 打开「模型配置 → Token01」，填写平台的 `sk-` 密钥，点击「保存并同步模型」。
2. 系统自动从中转站提取当前密钥可用、工作台已接入的模型。后续可点击「同步可用模型」刷新；媒体模型和 AI 辅助模型均无需单独填写密钥，自动复用所属中转站的密钥。
3. 在「视频生成」或商品推广的直接视频制作中选择模型。选择 4–15 秒整数时长、画质、比例和图片用途后查询报价并确认。
4. 参考图模式可不带图生成文字视频；带图时最多 9 张。首帧模式需要 1 张图，首尾帧模式需要按顺序提供 2 张图。单图不超过 20 MiB，实际上传还受本地「系统设置」限制。

| 模型 | 画质 | 比例 |
| --- | --- | --- |
| MiniMax-H3-Fast | 480p / 768p / 1080p | 9:16 / 16:9 / 1:1 |
| MiniMax-H3 | 768p / 2k | 9:16 / 16:9 / 1:1 / 4:3 / 3:4 / 21:9 |

Fast 的输入模式、画质和图片数量最终取决于 Token01 密钥分组。1080p 可能输出工作流原生的 1088p，模型档位不承诺精确像素。当前为两款模型共同采用 4–15 秒范围；未接入参考音频或参考视频。

Token01 调用模型以中转站返回的权限为准，附加密钥的查询结果同时列出工作台尚未接入的模型。初和则完整显示密钥已自定义的模型和分组，尚未接入调用的模型及临时拥挤项均标注状态。更换密钥或同步失败会使旧列表失效；同步过程只查询模型目录与权限，不提交付费生成。已有配置会在首次打开模型配置页时自动同步，历史任务保留接单时的凭据版本。

## 按模型选择分组

「模型配置 → 模型与调用配置 → 视频类」点击模型卡片，可分别指定两款 MiniMax 的调用密钥和倍率分组，并选择是否启用。例如，Fast 使用 `default_we`，H3 使用 `2.4折`。分组下拉菜单来自 Token01 公开价格目录，显示倍率和支持的分辨率；分组专价优先于通用倍率。倍率分组同时决定实际渠道、价格与生成能力。

1. 使用一把密钥访问多个分组时，在 Token01 平台将令牌设为 `auto` / `auto_price`，保存到上方中转站统一密钥，并让模型选择「跟随统一密钥分组（含 auto / auto_price）」。具体分组由平台选择。
2. 需要固定倍率分组时，展开上方中转站卡片的「固定倍率分组的密钥 · 可选」，集中保存已在 Token01 平台绑定同名分组的密钥并同步。每个分组保存一次，同组模型自动复用。
3. 在下方点击模型卡片，选择调用密钥和倍率分组，点击「保存模型与分组」。模型设置区不包含密钥输入框；未配置分组时提示前往中转站配置。
4. 配置刷新、重启后保留，启用开关控制该模型是否进入创作选择。选择「跟随统一密钥分组」可恢复统一密钥方式。

截至 2026-11-03，文档中生成接口按模型和令牌分组路由，未公布可供普通生成 API Key 覆盖分组的请求参数。工作台通过选择分组保存的凭据实现路由，不向生成请求添加未经文档确认的 `group` 字段。模型权限可由 `/v1/models` 验证，但接口没有返回密钥实际绑定分组；分组名称需与平台设置一致。一把固定分组密钥不能借此扩大到其他分组。

2026-11-03 再次通过 BrowserOS neo 核对 Fast 文档，平台明确说明分组由 API Key 决定，客户端选项不切换分组；`auto` / `auto_price` 也不保证按素材组合选择生成方式。不能把本地倍率选择声称为一把普通 API Key 的强制切组能力。

固定分组报价只计算所选分组的价格、排除规则及画质，并拒绝不支持的组合。统一密钥更新或同步不会覆盖已选固定分组的模型凭据。切换分组后旧预览必须重新生成；已接单任务继续使用原模型、分组和密钥版本，避免排队期间配置变化影响原任务。

## 报价与结算

公开价格接口 `/api/pricing` 提供公开分组、倍率、分辨率档位、分组专价、排除规则、忙闲时价格与图片计价。报价按请求秒数计算；分组专价不再次乘分组倍率。当前覆盖公开且支持所选输入模式的线路与忙闲时价格区间，并在实际提交前重新读取价格；涨价超过确认上限时中止。

`/v1/models` 用于检查当前密钥对精确模型名称的访问权限。账户余额现通过 User 权限的 `/api/user/self/quota/overview` 查询，登录方式见下文。生成密钥通常没有 User 权限，账户余额与模型令牌额度也不等同，因此生成报价不以其他账户或未确认额度进行准入判断，仍由 Token01 提交时校验。公开区间不是当前密钥专属的精确报价。

Token01 使用人民币「元」，初和中转站使用「算力」，两者不合并、不换算。顶栏和算力统计明确只涵盖初和中转站。Token01 任务费用保持待核对，最终费用与退款以 Token01 使用日志为准，不伪造零费用、已退款或已结算。研究方案同时包含图片与 Token01 视频时，需分别报价与生成。

## 协议与任务恢复

- 图片先通过鉴权的 `POST /v1/uploads/images` 上传，保留完整签名 URL。上传失败时不提交付费生成。
- `POST /v1/video/generations` 使用精确大小写模型名。H3 使用 `size` 与 `metadata.parameters.ratio`，Fast 使用 `resolution` 与 `ratio`；图片用途映射至参考图或显式首尾帧字段。
- 发送付费请求前持久化提交标记，仅保存正文中的公共 `id/task_id`，不使用内部响应头 `X-Task-Id`。
- 查询 `GET /v1/video/generations/{task_id}`，默认间隔 10 秒，临时错误延长至 15 秒。只有任务成功状态触发下载，HTTP 200 或进度 100% 不代表完成。
- 通过固定本站地址 `GET /v1/videos/{task_id}/content` 鉴权下载，验证 MP4 和视频时长后保存本地。不会向外部 `result_url` 发送本站密钥。
- 网络中断、无公共任务号等不明确提交转为「待核实」，重启后不自动重新付费提交。下载失败只重试保存。任务全程使用接单时的凭据版本。

## Token01 账户余额修正（2026-11-03）

真实账户的额度概览返回 `remaining.amount` 为十进制字符串（例如 `"1.000000"`），币种字段是 `currency.display_type`（例如 `"CNY"`）。原代码只接受数字金额并漏读 display_type，因而回退显示 `remaining.quota=500000`。现解析有限十进制金额字符串并读取显示币种，直接使用平台已换算的 amount，不再重复套用 exchange_rate 或 quota_per_unit。只有原始 quota 或金额无效时显示核对提示。
