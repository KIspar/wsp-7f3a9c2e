# 选品之神全流程测试

目标：资料输入 → 同行采集 → 证据分析 → 标签选择 → 三套方案 → 费用确认 → 套图／A+／图文／视频 → 当前成品与任务记录 → 下载，并覆盖失败、重启和重复操作。

## 重复执行

在项目根目录运行，使用 Node 24 或更新版本：

```sh
npm run test:research
npm test
npm run test:research:e2e
```

第一条运行研究专项服务测试，第二条运行所有自动化回归，第三条重新构建并启动独立临时应用，执行实际 Chrome 界面和扩展测试，结束时关闭测试服务并删除临时数据库及测试凭据。不会读取或修改日常使用的 `data/`。

浏览器测试使用 Python Playwright：

```sh
python3 -m pip install -r scripts/research-test-requirements.txt
python3 -m playwright install chromium
```

也可指定已经安装的 Chrome 和 Python：`RESEARCH_CHROME` 为浏览器可执行文件路径，`RESEARCH_PYTHON` 为 Python 路径。项目的 `.runtime/video/bin/python` 存在时优先使用；macOS 默认识别 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`。Windows 设置环境变量时使用 PowerShell 的 `$env:RESEARCH_CHROME`、`$env:RESEARCH_PYTHON`。浏览器版本需要支持 CDP `Extensions.loadUnpacked`。缺少该能力时测试会明确失败，不会跳过插件验收冒充通过。

已有生产构建时，单独执行 `node scripts/research-flow-e2e.mjs`。证据默认保存在 `output/research-flow/`，可通过 `RESEARCH_TEST_OUTPUT` 改变目录。失败会保存截图、页面文字和 Playwright trace；成功会保存各阶段截图、下载包、浏览器与插件检查记录、受控供应商提交次数。

## 测试边界

自动化调用真实应用路由、SQLite、分析服务、报价、接单、工作队列、素材校验、结果落盘及 ZIP 下载；只将外部模型传输与结果文件下载替换为受控响应。测试会断言调用次数与引用图，拒绝任何意外供应商目标；真实 API 密钥不进入测试。生成图片和视频是固定测试素材，不能用来评价模型创意质量或宣称供应商真实生成成功。

扩展测试真正加载项目插件，通过 popup → Service Worker → 本地 HTTP 完成配对、读取队列、注入采集脚本、保存内容和二级评论。抖音页面使用拦截后的受控 DOM；它验证插件和本地服务能否衔接，不证明线上抖音选择器、账号登录、媒体下载或商品面板可用。

## 真实抖音验收（待在已登录浏览器执行）

准备同款同行的真实视频和图文链接，Chrome／Edge 安装当前 `extensions/douyin-research` 并配对。在同一浏览器登录抖音，先验证插件能读取任务队列。

1. 未登录检查必须提示登录，不采集；登录或安全验证过期时暂停并保留已取得内容。
2. 视频页、图文页各采集一条，核对标题、原始文案、来源 URL、实际下载的原图／完整视频。无媒体时明确部分完成，不能用封面冒充视频。
3. 核对一级评论及二级回复的父子关系、点赞／时间／排序；不递归第三级，一级最多 100 条，连续无新增与到底条件有停止原因。
4. 暂停后继续、刷新工作台、重启本地服务，既有评论和媒体不重复导入。网络断开后恢复，任务不能永久被“正在采集”锁住。
5. 有商品入口时核对商品资料与实际首屏截图；未取得面板、无权限、反爬或媒体下载失败时保留具体警告，允许补采或上传。
6. 另一素材页不能误用于当前任务；补采截图只对当前目标前台标签页；授权撤销后插件不能继续读取或写入。
7. 返回选品之神主动分析，采集完成本身不触发付费。

本轮不具备真实同行链接和已登录插件浏览器，因此不得将上述项目标为已通过。

## 真实供应商及内容质量验收（需另行确认报价）

1. 配置真实密钥，检查余额、可用模型、TT 视觉验证与报价；先保存报价及允许费用，确认后才发送付费请求。
2. 同一份最小资料分别使用 GEM、TT、双模型；核对可见事实、来源声明、意见与假设是否分开。存在不确定信息时不得升级为承诺。
3. 仅选择两个可用标签形成三套不同策略，逐项检查七张套图、3–10 详情屏、6–12 图文页、一条完整视频的独立叙事与可执行提示词。
4. 四类制作确认前后核对供应商任务号、真实返回文件、画面商品一致性、文字开关、宽高比例、视频时长和可播放性；核对本地任务与供应商账单，费用不超过确认规则，退款可核查。
5. 测试一次供应商失败／延迟／未知结果，查供应商任务后恢复；禁止通过反复点击重发未知付费请求。

自动化受控响应不能替代本节，也不能证明真实模型输出质量。

## Windows 文件夹版验收（需 Windows x64）

1. 将整包解压到带空格及中文的可写路径，断网运行“检查运行环境.bat”，应可找到自带 Node、Python、图像库、FFmpeg 与模型。
2. 双击 `run.bat`，浏览器打开本机地址，健康页数据库／工作器正常，空数据初次启动不携带原电脑密钥或商品。
3. 再次启动不会生成两个服务；端口占用应给出可处理的提示。关闭网页后任务继续，停止 BAT 后服务端口释放。
4. 完成上传 → 分析 → 方案 → 四类制作 → 下载；停止再启动，原商品、任务与文件仍在。
5. 安装当前采集插件，执行真实抖音验收；检查 Python 视频探测、音频处理与 Windows DLL 实际加载。
6. 备份后在新可写路径恢复，核对商品、任务及文件；凭据不出现在普通备份中，恢复后重新配置。

本机为 macOS，静态文件／PE 架构检查无法替代 Windows 实机验收。仓库旧 `npm run test:e2e` 中的 `scripts/smoke.mjs` 仍引用已移除的“参数矩阵”按钮，本专项使用新的连续旅程，不宣称旧命令通过。
