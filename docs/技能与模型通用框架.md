# 技能、智能体与模型参数通用框架

日期：2026-10-28  
状态：设计规范与技能文件初稿；加载器、动态表单、执行引擎和新增模型页面尚未开发。

本文补充[产品与技术方案](抖音男装AI创作工作台方案.md)，以本轮确认范围为准：**图片生成、模特换装、场景复刻、视频生成、一键对标**。没有灵感池；一键对标是图片智能体，不分析视频。

## 1. 分层定义，一套执行框架

| 层 | 负责内容 | 修改方式 |
| --- | --- | --- |
| 技能定义 | 收什么素材、数量如何展开、提示词、业务固定参数、步骤依赖 | 每技能一份 Markdown，或设置页编辑后写入文件 |
| 模型定义 | API 模型 ID、类别、画幅、时长、参考数量、专有参数与价格 | 设置页新增/编辑模型，后端保存版本 |
| 算力规则 | 每模型点数、参数覆盖规则、计费修订 | 设置页“算力与计费”，统一账本，独立于供应商金额 |
| 执行引擎 | 校验、编译计划、创建持久化任务、调用、查询、保存与恢复 | 通用后端代码，新的处理原语/协议才扩展代码 |

普通技能是一个生成步骤；智能体是多个已注册处理器步骤的组合，首版仅用媒体步骤，后续可组合本地分析与 AI 理解。单个和批量不使用不同页面或接口。所有技能共用 `输入 → 计划 → 执行 → 结果` 协议，不按照技能名称写独立调用逻辑。

## 2. 技能文件格式与发布

目录统一如下，五个文件已提供初稿：

```text
skills/
├─ image-generate/技能提示词.md
├─ model-outfit/技能提示词.md
├─ scene-recreate/技能提示词.md
├─ video-generate/技能提示词.md
└─ benchmark-agent/技能提示词.md
```

每个文件上半部分为 YAML frontmatter，下半部分为提示词。配置格式拟采用 `schemaVersion: 1`，本轮尚未实现解析器。

主要字段：

| 字段 | 语义 |
| --- | --- |
| `id` / `name` / `category` | 稳定 ID、中文名称、image/video/agent 分类 |
| `description` | 侧栏一句话介绍 |
| `executor` | 普通媒体 `media`，声明式智能体 `workflow` |
| `inputs` | 素材角色、类型、是否必填、单组/多目标，不把多角度商品图误判成多商品 |
| `fields` | 技能业务参数，类型、中文名称、枚举、默认、可选上下限 |
| `batch` | `repeat` 或 `per-target`，决定单个与多个如何展开 |
| `model` | 模型类别、默认模型、需要哪些能力；不是固定可用模型列表 |
| `fixedParameters` | 少量明确锁定的业务或模型参数，标明作用域和理由 |
| `steps` | 智能体的有向无环依赖、单步/逐目标展开、前序结果引用 |

Markdown 部分按固定标题分段，例如 `## prompt.main`、`## prompt.white-background`、`## prompt.replace`。解析器按标题提取，禁止依赖模糊的自然语言判断哪段该执行。

`batch.selectionField` 指向提交的已选目标 ID 清单，`perTargetOverrides` 声明允许逐图覆盖的字段。未选项目只留在素材中；执行计划以已选清单为准，不以全部上传目标为准。

模板仅支持白名单占位变量，如 `{{user.requirements}}`、`{{item.index}}`、`{{target.label}}`、`{{fields.replacementMode}}`。运行时参数、素材角色、前序结果也可以作为结构化输入绑定。禁止 `eval`、任意 Shell/Python/JavaScript 代码和文件外部包含；这是应用内部技能定义，不是 Codex 技能安装格式。

`user.requirements` 是通用补充要求；`target.label` 是后端提供的目标编号/名称；`target.description` 按逐图设置优先、技能公共替换对象其次解析。用户勾选需替换的目标并明确对象；系统校验对象字段是否齐备，不声称自动识别多人或商品遮挡。未选图片不进入执行计划。图片生成至少提供提示词或参考图，视频生成需要有效提示词，不能把空白请求提交上游。

首版执行原语使用媒体生成和已有素材/外部任务结果绑定。单独白底生成是 media 动作；替换动作引用可选 whiteTaskId 或 whiteAsset，不在替换提交时暗中创建白底调用。`single` 展开一次，`batch` 按通用批量计划展开。`referenceRoles` 绑定原始素材，`stepReferences` 绑定内部前序结果，`optionalTaskReferences` 绑定本次动作明确选择的外部任务结果，`optionalReferenceRoles` 绑定可选已有素材，`targetRole` 在当前项只绑定一张目标图；这些角色由后端组装并在执行稿中说明，不依赖文件名猜测。

生成步骤中的商品原图、当前目标与可选白底结果按素材 ID 去重后计入引用数量。跳过白底时不占一张引用。所有引用顺序、角色说明及前序产物修订均进入快照。每步骤使用可选独立模型/参数设置，未覆盖时继承本次图片或视频选择，不能从某一步固定值污染其他步骤。

模板引擎采用明确的变量查找与渲染，不递归执行用户输入中的 `{{...}}`。未声明变量、重复 ID、未知执行器、依赖成环、错误模型类别或无法解析的步骤绑定应阻止发布，并显示文件和字段位置。

发布流程：编辑 → 校验 → 预览表单/提示词与数量计划 → 发布。预览覆盖输入角色、单项/多项展开、最终提示词、模型兼容性、固定参数及预计点数，使用本地渲染，不额外调用文本模型。缺失必填、超引用等示例须准确显示错误。文件为编辑来源，数据库保存每次发布的正文、配置、内容哈希与修订。文件修改不会自动替换已发布版本；界面提示“有未发布修改”。失败校验不影响上个可用修订。

新技能使用现有执行器、字段和步骤组合时，发布后自动进入分类并使用通用页面。若需要视频切镜等全新运算，新增 `.md` 还不足以执行，必须先开发对应步骤处理器。

首版不创建视频复刻、提示词反推或收藏库的空技能入口。后续通过新增处理器、文本/视觉模型类别与产物展示器接入；产物引用应允许结构化 JSON/Markdown，而非强制每项输出媒体。导入验证等待、未来流水线与 UI 验收见 [首版框架优化与后续扩展](首版框架优化与后续扩展.md)。

## 3. 单个、多图、多视频与配对

| 技能 | 单个 | 多个 | 数量依据 |
| --- | --- | --- | --- |
| 图片生成 | 共享输入生成 1 张 | 共享输入独立生成 N 张 | `count` |
| 视频生成 | 共享输入生成 1 段 | 共享输入独立生成 N 段 | `count`；不是 N 镜连续故事 |
| 模特换装 | 一件商品 × 1 张模特图 | 一件商品 × M 张模特图 × V 个版本 | `targets.length × variantsPerTarget` |
| 场景复刻 | 一件商品 × 1 张场景图 | 一件商品 × M 张场景图 × V 个版本 | 同上 |
| 一键对标 | 原商品图直接替换 1 张已选目标 | 原商品图对应 M 张已选目标、每图 V 版；可选白底 | 是否需白底调用 + `M × V` |

商品组可包含多张角度图，但表示同一款/同一 SKU。若批量输入多件商品，必须通过显式行配对声明每个目标使用哪个商品组，不默认全组合。

目标图列表展示选择框、顺序、缩略图、替换对象和版本数。M 是勾选数而非上传总数；统一对象可逐图覆盖，未勾选项不生成、不计点。部分图存在多个人或多个服装时，可逐图填写“左侧黑夹克人物的上衣”等目标，必要时增加区域选择；不能默认为所有人物都换。

上游当前采用单媒体请求：成品 N 张/段由服务端建立 N 个独立子任务。每个子任务固化自己的参考图、角色顺序、差异预设和最终参数。不串行使用其他子任务的结果；例外仅是智能体明确声明的前置步骤引用。

单次生成数量、每目标变体数和供应商单次出图数是不同概念。本地全局数量上限、文件上限与并发可配置，与模型引用数量限制共同校验；超限报错，不静默截断。

## 4. 一键对标：分离白底操作和替换队列

用户勾选目标图，统一对象可逐图覆盖；默认使用原商品图。若需要白底图，点击独立“生成白底图”按钮，不会因此自动生成整批替换。

用户在白底生成期间可点击“一键替换”，后端立刻保存每个 item 与所选白底任务依赖；该白底成功保存后自动调度，不增加审查开关。白底失败或待核实时显示“等待白底图处理”，允许用户重做或主动改用上传图/原图，不自动更换引用。

每张同行图一个三列 item：左为原图，中间为参数、参考缩略图及提示词编辑入口，右为生成结果。默认提示词集成在系统，用户可以只打开编辑器按项修改；默认带上商品原图和本次所选白底，允许额外添加辅助参考。未提交可编辑，提交后修改用于新尝试。

多个 item 就绪后独立并发，图片队列默认全局 20 并发，可配置；等待白底不占槽。详细交互、外部依赖、修订与调度规范见 [逐图工作台与队列](一键对标逐图工作台与队列.md)。

例：勾选 5 张、每张 2 版，替换操作创建 10 次请求；原图直用或已有白底不增加请求。单独新生成白底是另外 1 次；之后每个 item 只引用其结果，不重复提交或计点。

## 5. 通用执行协议

建议请求包含 `skillId`、`skillRevision`、`inputRoles`、`fields`、`batch`、`modelSelections`、`modelParameters`、`expectedDraftRevision`、`idempotencyKey`。

建议补充 `POST /api/creations/preview`：完成草稿保存后，后端校验并生成计划摘要，包含步骤、各步模型、预计调用数、参数和费用依据，返回 `planHash`。用户提交时带该哈希和幂等标识，后端重新校验；技能/模型/输入有变化就提示更新计划，不按过期估算默默执行。

预览同时返回预计算力及规则修订；仅作统计与提醒，不预占或冻结，额度不足仍可提交。规则未配置显示点数未知而非免费；保存成功计点、明确失败不计、未确认单列，详细规则见 [算力额度与消耗统计](算力额度与消耗统计.md)。技能文件不写死某个模型的点数。

后端统一流程：

1. 读取已发布技能；解析并固定技能与模型配置修订。
2. 校验素材存在、角色、文件类型和模型约束。
3. 合并参数，编译单项或 DAG，计算计划与依赖。
4. 事务保存创作记录、输入快照、子任务和事件，快速返回任务 ID。
5. Worker 只执行依赖满足且允许启动的项，经适配器提交并保存上游 ID。
6. Worker 持续查询、下载与保存；SSE 通知状态，不依赖网页。
7. 新尝试保留旧图、旧费用和旧完成度；未知提交不自动重发。

最终结果统一包含批次摘要、每项源素材/目标 ID、步骤、模型、参数快照、提示词快照、生成资产、状态、耗时和费用。智能体只增加步骤关系，不另外建立一套日志/结果系统。

## 6. 参数分层与冲突处理

| 参数层 | 例子 | 归属 |
| --- | --- | --- |
| 业务参数 | 整件换装/图案替换、文案策略、保留场景 | 技能定义与中文表单 |
| 批量参数 | 数量、逐图版本数、参考配对 | 本地编排，不随意透传供应商 |
| 公共生成参数 | 画幅、视频时长、参考素材 | 通用输入，经适配器转换 API 字段 |
| 模型专有参数 | TT 版本/质量；Omni 增强/超分 | 模型参数定义动态显示 |
| 运行参数 | 并发、轮询、超时、重试策略 | 后端设置，不混入图像提示词 |

未锁定字段按“模型默认 → 技能默认 → 用户本次选择”覆盖；固定字段是约束，不是静默覆盖用户选择。用户与固定字段冲突时说明原因并要求修正。最后始终经过模型枚举、范围、依赖组合与类型校验。

`false`、`0` 是有效值，不能用真假判断丢掉；未填写、显式设空与供应商默认须按字段规则区分。白底步骤可以把 `background=opaque` 作为该步骤固定值，但不影响用户对其他步骤的独立选择。

同一参数只有一个控件与一个最终字段。例如画幅通用字段映射到 `params.aspect_ratio`；`resolution` 不在“分辨率列表”和高级 JSON 中分别保存两个值。切换模型后只迁移交集合法值，保留其他模型自己的草稿；不支持的字段从执行参数移除并提示。

普通技能的底部输入台由执行器类型派生；工作流智能体使用自身流程页面，不挂载通用输入台。上传控件按 `inputs` 的角色/类型/单多张规则与当前模型能力交集生成，不从提示词正文推测参考视频支持。当前 Omni 只开放已确认的参考图片能力。

参数矩阵弹窗绑定技能 `fields`，模型专有参数另分区；常用参数快捷控制与弹窗共用一份草稿。成功接单后按当前技能/默认模型初始化所有本次输入并消费对应后端草稿，任务使用已保存快照，不能因输入清空丢失提示词、引用或再生成依据。失败/受理未知保留草稿直至确认。详见 [结果流与输入区](工作台结果流与输入区交互规范.md)。

## 7. 原项目模型专有参数核查

依据现有 `server/presets.ts`、`shared/types.ts`、`server/adapters.ts` 与 `src/Settings.vue`。以下为 **2026-10-28 代码预设**，不代表本轮重新验证了供应商合同或实际效果。

### 7.1 TT Image 2.5

| API/能力字段 | 中文展示 | 可选值 / 预设 |
| --- | --- | --- |
| `model` | 模型 | `tt-image-2.5` |
| `aspect_ratio` | 画幅 | 9:16、16:9、1:1、4:3、3:4、2:3、3:2 |
| `images` | 参考图片 | 0–16 张；实际最小值由技能再约束 |
| `version` | 模型版本 | `flare`（默认）、`sunburst`；保留原值，效果差异待实测 |
| `resolution` | 输出分辨率 | 自动 `auto`、1K（默认）、2K、4K |
| `quality` | 质量档位 | 自动 `auto`（默认）、低 `low`、中 `medium`、高 `high`、更高 `xhigh`、最高 `max` |
| `background` | 背景模式 | 不透明 `opaque`（默认）、透明 `transparent`、自动 `auto` |

背景模式“不透明”本身不等于白底，白底仍由技能提示词明确。透明模式是否得到带 Alpha 的有效结果应实际验证，不能仅根据文件格式或 UI 选择判定完成。质量/分辨率的耗时和费用影响在得到供应商依据后展示，不杜撰倍数。

### 7.2 Omni Flash

| API/能力字段 | 中文展示 | 可选值 / 预设 |
| --- | --- | --- |
| `model` | 模型 | `omni-flash` |
| `aspect_ratio` | 画幅 | 9:16、16:9 |
| `duration` | 视频时长 | 4、6、8、10 秒；适配器按当前协议传字符串 |
| `images` | 参考图片 | 0–3 张；角色限制需结合技能和合同验证 |
| `enhance_prompt` | 提示词增强 | 关（默认）/ 开 |
| `enable_upsample` | 超分处理 | 关（默认）/ 开 |
| `nativeAudio` | 原生音频能力说明 | 代码预设为 true；属于能力标志，不直接当作用户可传开关 |

当前预设没有分辨率档位，不给 Omni 硬塞 TT 的 1K/2K/4K。没有明确的首尾帧控制映射时不显示该能力。原生音频预设不等于支持指定中文口播或背景音乐。

### 7.3 原有结构可复用与需要补齐的地方

原项目模型定义已有 `providerId`、`modelId`、`category`、`capabilities`、`defaults`、`price`。能力包含参考数量、画幅、时长列表/范围、分辨率、异步、原生音频及参数类型/枚举/默认。

新系统在此基础上补充参数 UI 元数据：`labelZh`、`descriptionZh`、`group`、`advanced`、`enumLabels`、数值上下限、步长、必填与条件约束。原来设置页可编辑的能力 JSON 作为高级入口，常用新增/编辑流程改为中文表单。

`imageShape`（字符串或数组）、`contractVerified`、`frameControl` 的参数映射是适配层合同信息，不应让普通运营每次生成都填写。图片引用总大小目前适配器有 30MB 校验，迁入时保留并与上传、角色及数量限制统一验证。

## 8. 新增模型与自动适配

图片和视频各预置一个默认模型；列表由数据库读取，不写死两个选项。设置页支持“新增图片模型”“新增视频模型”：

1. 选择已有供应商或配置 API 基址、鉴权和适配器类型。
2. 填写名称与真实上游模型 ID。
3. 定义画幅、参考数量、合法时长、分辨率及模型专有参数。
4. 配置价格依据、默认项与验证状态，完成不消耗媒体额度的静态合同检查。
5. 保存后出现在兼容技能选择器，参数表单随模型自动更新。生成测试单独展示调用与预计费用，不能伪装成免费连接测试。

新模型的算力规则可补充配置，未配置不阻止生成，但显示“点数待配置”，不能当成 0。统计规则版本随任务锁定，后续修改不静默影响旧任务。

若供应商确有模型发现接口，可实现“一键同步模型列表”；该接口通常不足以得出全部参数及实际能力，未取得的字段显示待补充，不能猜。首期可以先手动新增，同协议下无需修改页面代码。

已有 `chuhe` 协议可复用原提交/查询链路；不同模型只要请求和响应仍符合合同，新增配置即可。全新协议、鉴权、文件上传或状态结构需要新增后端适配器。无法映射的模型保持“待配置/不可执行”，不冒充已接通。

模型选择器按类别、启用、引用数量和技能硬性需求过滤；不满足要求的项解释原因。价格调整、默认模型变更或禁用不会改写已提交任务的快照。凭证通过受保护的后端引用读取，快照中不保存密钥明文。

## 9. 参数界面与验收补充

输入区露出素材角色、核心换装范围与替换对象；目标缩略图清单直接勾选和逐图覆盖。普通生成叫“成品数量”，目标配对叫“每图版本数”，旁边显示已选目标数和成品总数；视频另有时长。参数矩阵弹窗收纳低频技能选项和模型专有参数，固定值展示锁定原因，高级字段折叠。界面全中文，原枚举与请求字段可在高级信息查看。

提交前展示实际生效参数及计划摘要；错误定位到具体字段。校验必须前后端一致，绕过前端的非法请求不能消耗生成额度。

重点测试：同一技能 1/N 转换、M×V 配对、白底依赖及缓存、超引用限制、切换模型不残留非法参数、新增同协议模型自动出表单、技能热编辑发布隔离、重启恢复、待核实隔离、单项再生成不破坏已交付结果。


## 10. 兼容性与分支校验补齐

有效引用容量取模型声明和适配器实际支持的交集。旧适配器的 imageShape=string 只能接收一张，不能用 refs[0] 静默丢掉其他图；要求商品与目标多角色的技能需禁止使用不满足容量的模型。固定模型专有参数必须存在且值合法，否则不兼容。

直用原图/已有白底/白底任务结果三种绑定显式互斥：复用要求有效单图，外部依赖校验类型和归属，直接原图不携带白底；仅当前动作实际参数参与校验。选择目标清单去重、不可为空、必须属于输入集合；对象按组默认与逐图覆盖解析，全部在服务器再次校验。外部白底依赖绑定具体任务和产物修订，不用“最新图”静默换引用；不提供首版白底审核开关。


## 11. 多操作技能与默认并发

`actions` 声明同一技能的明确用户动作，避免把“生成白底”隐含在“一键替换”中。动作可以引用同一模板分段、模型与执行器，点击后才建立其任务。`dependencyBinding` 按模式只绑定原图、whiteAsset 或 whiteTaskId；引用其他任务时验证归属、输出类型与无环性。

`batch.perTargetOverrides` 支持 item 级替换对象、提示词覆盖稿、模型选择、参数和参考组，均须通过各自 Schema。默认值由系统模板渲染，不将逐图编辑写回全局技能；只在用户明确保存和批量应用时改动选中未提交条目。

图片全局并发默认 20，可配置；不是每批 20，也不是每个 item 有 20 次请求。供应商实际限制共同生效，排队和等待依赖不占活动生成数。就绪批次间轮转、批内按创建顺序调度，上传/查询/下载/打包另设资源池。未提交项编辑与提交领取需原子修订校验，详见逐图规范。

历史设置回填必须创建新草稿，校验当前技能与模型合同；原修订或模型失效不能静默升级、切换供应商。显式再生成绕过旧成品缓存，下载恢复不新建媒体提交，完整规则见 [可靠性与运营效率补充](首版可靠性与运营效率补充.md)。
