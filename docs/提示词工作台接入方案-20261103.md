# 提示词工作台接入方案

版本：评审稿 v1 · 2026-11-03  
参考项目：[binghe1980/ecommerce-video-prompts](https://github.com/binghe1980/ecommerce-video-prompts)  
当前状态：首版产品代码已实现并完成隔离验收，详见 [实现与验证记录](提示词工作台实现与验证-20261103.md)。未进行真实模型付费验收；现有开发服务需重启后加载新增后端路由。

## 1. 建议采用的方向

在现有左侧导航的「智能体」分组增加 **「提示词工作台」**，与「一键对标」并列，使用独立工作区。

它的核心价值是：**把真实商品资料，转成有购买理由、可检查、可局部修改的视频脚本和提示词。**

整体流程沿用参考项目：

```mermaid
flowchart LR
    A[商品与素材] --> B[商品卖点]
    B --> C[选择方向]
    C --> D[脚本与分镜]
    D --> E[提示词与解释]
    E --> F[检查与导出]
    F --> G[带入视频生成草稿]
```

前六步是参考项目已有的创作闭环；最后的「带入视频生成」是结合本系统增加的衔接。

默认提供「一键生成脚本方案」：在用户确认方案数量、模型和预算后，自动完成卖点分析、方向策划和脚本生成。用户审阅、选用脚本，再生成详细提示词。需要精细控制时，可切到「逐步策划」。

建议第一版就交付完整的六步流程，以及局部修改、历史版本和检查导出能力。只做一个能保存和复制文本的页面，无法复现这个项目的核心价值。

## 2. 对参考项目的理解

### 2.1 真正需要复刻的思路

| 核心思路 | 实际含义 | 本系统的呈现方式 |
| --- | --- | --- |
| 从商品事实出发 | 参数、材质、功效、优惠等表达必须能对应资料，不从创意稿反推事实 | 卖点卡片可展开查看资料原文；未知和冲突单独标记 |
| 从购买理由出发 | 先明确「谁在什么场景下为什么需要它」，再写镜头 | 每套方向显示目标人群、购买理由、开头钩子和演示方式 |
| 多方案有实质差别 | 不能只换标题、背景和形容词 | 一个主推方案，其他方案用于不同角度测试，显示差异点 |
| 先脚本，后提示词 | 先把口播、动作、分镜和时间安排写通，再细化执行指令 | 脚本确认后，提示词阶段保留台词、镜头和时间 |
| 素材按用途引用 | 人物图只参考人物，不能把其手中的商品当成主商品 | 每张图有角色、用途和逐镜引用关系 |
| 只改需要改的部分 | 可以改某个方向、某段脚本或某段提示词 | 提供「调整这套」「调整本段」及修改前后对比 |
| 成果与检查绑定版本 | 修改后，旧检查结论不能代表新内容已通过 | 标记待更新范围，对当前版本重新检查后正式导出 |

### 2.2 原项目的实际流程

原项目展示六个步骤，后台主要执行五个阶段：`analysis → directions → scripts → prompts → audit`，另有局部修正 `repair`。

1. **商品与素材**：商品名称、规格、介绍、可选链接和图片，以及创作偏好。
2. **商品卖点**：提炼功能、效果、情绪、信任、差异化五个维度，保留原文依据和资料缺口。
3. **选择方向**：按照真实条件组织痛点、剧情、场景、种草、促销、证据等方向，而非每类机械生成一套。
4. **脚本与分镜**：完整自然口播、分镜、动作、时间与创作意图；可独立检查和导出脚本。
5. **提示词与解释**：按生成段补齐六模块、参考图、逐镜安排和连续性要求，同时解释策划意图。
6. **检查与导出**：检查事实、时间、动作、素材和版本，定位问题、局部修正，导出整片或分段文字。

原项目默认规划四套方案，允许只做一套。资料少也可开始；不知道材质、没有优惠、缺人物图，都不必阻断整条创作。无法确认卖的是哪款商品时，才先补商品身份。

### 2.3 原项目与本系统的适配差异

| 项目 | 参考项目 | 本系统建议 |
| --- | --- | --- |
| 运行方式 | Codex 桌面插件，借用当前 Codex 任务模型 | 独立页面与服务，复用本系统 AI 辅助任务和模型配置 |
| 商品资料 | 插件内维护商品项目 | 可从商品工坊导入快照，也允许独立创建 |
| 图片 | 最多 9 张参考图 | 项目可管理多图；分析调用遵守现有单次最多 4 张的限制，必要时分批 |
| 生成调度 | 支持按方向并行生成 | 首版遵守现有 AI 辅助并发 1，阶段及方向顺序执行 |
| 视频分段 | 默认每个生成段不超过 15 秒 | 通用文稿可沿用此规划；选定视频模型后，按实际时长档位和输入能力重新检查 |
| 整片时长 | 通常不超过 60 秒，明确开启长片时可更长 | 首版规划不超过 60 秒；长片模式放二期 |
| 编辑保存 | 显式保存，保留未提交的编辑草稿 | 草稿自动保存，显式应用为成果版本，避免 AI 覆盖手动修改 |
| 输出 | 文字脚本、分镜、提示词和解释 | 保留文字交付，增加存入模板、带入视频生成草稿及任务关联 |

## 3. 入口、页面和布局

### 3.1 导航与职责

建议路由为 `/agents/prompt-workbench`，项目和创作记录使用子路由，例如 `/agents/prompt-workbench/:projectId/:creationId`。

现有系统的智能体导航从技能列表生成，实施时需要让该分组支持独立页面入口；工作台使用自己的页面组件和任务编排，不直接套用通用媒体生成表单。

| 功能 | 负责什么 |
| --- | --- |
| 商品工坊 | 管理真实商品、规格和素材，是可复用的数据来源 |
| 一键对标 / 商品研究 | 研究参考内容及创作方向，可作为有来源的补充资料 |
| **提示词工作台** | 从资料到方向、脚本、提示词、检查和交付的完整策划项目 |
| 模板中心 | 保存可复用的已选提示词或分镜结构 |
| 视频生成 | 按选定模型、密钥配置和渠道分组提交媒体任务 |

保留现有「模板中心」，新增工作台与它互通。

### 3.2 项目列表

进入后先显示项目卡片，每张卡片仅展示：商品缩略图、项目名、最近创作、当前阶段、更新时间。顶部提供搜索、最近使用排序、「从商品工坊创建」「新建项目」。

一个项目对应一个商品背景，一个项目可有多次创作，例如「通勤方向第一轮」「剧情方向第二轮」。历史创作各自保留方向、脚本、提示词和检查结果。

新建时只要求明确商品身份。商品介绍、图片、风格、时长和方案数量放在同一张简洁表单中；高级偏好折叠。

### 3.3 工作区示意

```text
现有全局侧栏 │ 提示词工作台 / 商品名 / 本次创作      [历史版本] [帮助]
             │ ① 商品与素材 → ② 商品卖点 → ③ 选择方向
             │             → ④ 脚本与分镜 → ⑤ 提示词 → ⑥ 检查导出
             │──────────────────────────────────────────────
             │ [主推方案] [备选方案一] [备选方案二] [备选方案三]
             │────────────────────────────┬─────────────────
             │                            │ 资料与素材       
             │ 当前步骤的主要内容          │ 商品 / 人物 / 场景
             │ 方向卡 / 分镜表 / 提示词     │ 依据 / 待补内容   
             │                            │ 可折叠           
             │────────────────────────────┴─────────────────
             │ 已自动保存 · 当前版本 / 任务状态        [下一步主操作]
```

布局约定：

- 沿用系统现有字体、色彩、按钮、下拉框、素材选择器和侧栏宽度；工作区不另造一套全局导航。
- 步骤导航表示进度，可回看已完成步骤。切换方案、分段或视图只改变查看内容。
- 每一步保留一个明显的主操作，其余放在次级按钮或更多菜单中。
- 默认展示成果；依据、解释、六模块高级编辑按需展开。长教程集中到帮助中心。
- 宽屏采用主内容加可折叠资料栏；较窄桌面改为资料抽屉，不挤压分镜编辑区。
- 不依赖大幅插画说明流程。空状态用简短说明和可操作按钮即可。

## 4. 用户如何完成一次创作

### 第一步：商品与素材

**输入**：从商品工坊选择商品，或输入商品名称、规格和介绍；可添加商品链接、商品图、人物图、场景图。每张图可填写「只参考什么」。

**创作设置**：自动 / 剧情 / 吸睛 / 直接带货 / UGC，时长自动或指定，方案数量 1–6 套，默认 4 套。比例默认 9:16，可按目标用途调整。

**主操作**：「一键生成脚本方案」。确认面板显示使用的聊天模型、账户、可用渠道分组、分析图片数量、预计任务组成和预算上限。确认后自动推进第二至第四步。

「逐步策划」模式则先执行「分析商品卖点」，用户可在每一步审阅后继续。

链接读取应复用现有采集机制；读取失败时保留链接并提供粘贴正文入口，不能把未读取的网页当成已分析资料。竞品资料与本商品事实分开记录。

### 第二步：商品卖点

**输出**：商品一句话定位，以及五维卖点。卡片可展开看到资料名称、对应原文和限定条件。

卖点状态使用「资料支持」「待补充」「存在冲突」。只有选中的、资料支持的事实进入后续肯定式商品表达；普通使用场景可以作为创意建议呈现。

**可操作**：勾选卖点、排除不想用的表达、补充事实、更正型号、查看依据。手动补充也作为来源保存，不能通过一个「确认真实」按钮将模型猜测升级为事实。

没有优惠就不编促销；不知道材质就不用材质做卖点。仅有明确品类时，可以生成场景草稿，不虚构独有优势。

### 第三步：选择方向

每套方向显示：

- 目标人群与使用场景。
- 核心购买理由。
- 前三秒钩子，以及商品如何被识别。
- 表现形式、内容大纲和主要演示。
- 与其他方案的差异、采用的商品依据。

主推方案解释推荐理由，其他方案提供不同的测试角度。剧情需要有冲突或选择变化；UGC表达不能伪造真实客户经历；证据方向只能使用已有真实证据。

**可操作**：选用方案、设为主推、手动编辑、「重新策划这套」。智能模式会继续生成设定数量的脚本；逐步模式只为选用的方向生成脚本。

保存方向修改只更新方向；另提供「按此方向更新这套脚本」，清楚说明范围和调用费用。

### 第四步：脚本与分镜

每套方案包含完整口播、全片时长、分段与逐镜分镜表。

| 字段 | 用户看到的内容 |
| --- | --- |
| 时间 | 全片位置、本段长度、镜头起止 |
| 画面 | 谁、什么商品、在哪里、可见状态 |
| 动作 | 一轮主要操作及起止状态 |
| 镜头 | 景别、机位和必要运镜 |
| 台词 | 自然口语，允许无口播 |
| 策划解释 | 这段针对谁、解决什么顾虑、为什么这样安排，可折叠 |

不固定四镜；先把口播和动作写通，再安排镜头和时长。完整口播由逐镜台词汇总，避免维护两份内容而产生差异。

**可操作**：改台词、调整镜头或时间、调整这一段、调整这套、检查并导出脚本。用户可只交付脚本，不必先生成六模块提示词。

**主操作**：「为选用脚本生成提示词」。确认后，以当前应用版本为基线进入第五步。

### 第五步：提示词与解释

顶部切换方案；方案内切换「整片」「分段」，并可按时间选择段落。

每个生成段的提示词包含六个模块：人物形象、商品真实属性、场景与视角、镜头运动与动作、台词对应、边界限定；另有逐镜安排、参考图清单和跨段连续性。

默认呈现编译好的完整文本，素材引用可点击预览。策划解释与交给视频模型的正文分开展示，复制时可选是否包含解释。

**可操作**：编辑模块、调整本段、绑定或补充参考图、调整参考用途。默认的本段细化保留已确认的台词、镜头数量与时间；需要改这些内容时回到脚本步骤，再更新受影响提示词。

缺图可以保留「待补同款商品图」等明确占位，继续交付文字；实际带入视频生成时，再根据模型必需输入进行检查。

**主操作**：「检查并准备导出」。

### 第六步：检查与导出

先做本地确定性检查，再使用 AI 检查表达和事实对应关系。

| 检查范围 | 示例 | 处理方式 |
| --- | --- | --- |
| 商品事实 | 无依据功效、型号错用、虚构优惠或亲身体验 | 阻止当前版本作为正式交付 |
| 时间结构 | 镜头重叠、空档、段长合计错误 | 定位具体段或镜头修正 |
| 内容一致 | 台词与提示词不一致、动作起终状态矛盾 | 修正受影响内容后复查 |
| 素材引用 | 绑定错商品、角色错用、引用不存在 | 明确指出图和镜头；缺图占位本身可作为提醒 |
| 创意建议 | 钩子弱、方案区分不明显、表达可更自然 | 提醒用户，不用主观评分卡住导出 |
| 版本 | 当前内容修改后仍使用旧检查结果 | 标记待检查，不能展示为本版已通过 |

问题可点击跳到准确字段，提供「手动修改」与「只修正这条」；修正后进行受影响方案的复查。

交付操作：复制本段、复制整片、下载 Markdown / 纯文本、下载结构化项目 JSON、保存选中内容到模板中心、带入视频生成草稿。

正式交付需对应当前应用版本和有效检查结果。需要保留未完成内容时，可另行「导出草稿」，明确标注待检查及问题，不自动带入生成任务。

## 5. 素材、时长和模型如何对接

### 5.1 素材引用保持稳定

内部使用稳定的 `assetId + refKey + role + scope`，正文存引用占位。展示或导出时，再按当前整片或本段的上传顺序编译成可读标签。

这样换图、调整顺序、合并整片时，不会把「图片 1」错误指向另一张素材。

- 角色包含商品、人物、场景、其他；同一素材的工作台用途单独记录，不修改全局素材属性。
- 换商品图、删图、改变参考范围，会标记受影响段落待检查。
- 改素材显示名称只更新显示映射；改变其用途说明则影响内容检查。
- 同款商品不同颜色、型号与角度需要明确身份，不能被模型自动混用。
- 删除仍被引用的素材先显示影响范围，提供替换或解除绑定，不静默删除对应镜头。

`@图片1` 只是某类模型的提示词表达。真正调用时还需由适配器传入文件或链接；不能仅凭文本标签就认定模型支持多图、人物参考或逐镜绑定。

### 5.2 聊天模型与视频模型分开

策划使用「模型配置」中勾选的默认 AI 辅助聊天模型，继续复用既有密钥配置；本页面不再填写 API Key。首版限定在现有辅助服务已支持的模型范围内，新增模型仍需能力适配。

含图分析只使用已通过现有识图能力验证的模型。不支持图片时允许仅用文字资料策划，图片保持参考素材；不能假装已经识别图片内容。

现有辅助服务单次最多 4 张图、输入文字最多 16000 字符。项目资料超过限制时：

1. 明确选择本次分析的图片和资料范围。
2. 必要时分批提取原文及可见信息，保留来源、图片身份、限定条件和冲突。
3. 汇总事实账本后再策划；各次调用均记录预算和费用。
4. 不能静默截断资料，也不能用模型摘要取代原始依据。

### 5.3 从提示词到视频生成

「带入视频生成」弹出兼容性面板，选择：

- 使用哪套方案、哪个生成段。
- 视频模型、已有密钥配置及其可用渠道分组。
- 模型实际支持的时长、比例、清晰度和参考图方式。

沿用模型配置中已设置的绑定及分组规则；中转站不能切换分组时，只能使用该密钥现有可用分组或用户自行配置的模型，工作台不增加绕过规则的调用。

面板逐项显示兼容 / 需调整。通过后只带入草稿，并保留 `projectId / creationId / versionId / directionId / segmentId` 来源关系。用户仍在视频生成页查看报价并确认提交。

**多段整片是一份制作计划。** 当模型只能生成其中一段时，首版让用户选择兼容段，或明确选择重新拆段。不能把整片文字塞进一次短时长请求，不能只改秒数而保留过多内容，也不能静默换模型、分组或丢弃参考图。

若模型只支持首帧，而当前方案依赖多图参考，应提示调整输入方式；需要先生成首帧时，走单独且明确的图片生成步骤。

视频媒体任务与策划任务分别记录。文本策划完成不等于视频生成完成；多段批量生成、自动拼接和音轨字幕统一放二期评估，不在首版承诺自动成片。

## 6. 编辑、版本和局部更新

建议使用「编辑草稿 → 应用为成果版本 → 检查当前版本」的关系。输入停止后自动保存编辑草稿，界面显示「保存中 / 已保存 / 保存失败」；应用修改后形成可追溯的成果版本。

| 用户修改 | 需要更新或复查的范围 | 旧内容如何保留 |
| --- | --- | --- |
| 商品型号、事实或所选卖点 | 依赖这些事实的方向、脚本、提示词及检查 | 保留旧版，显示来源变化及待更新范围 |
| 一套方向的购买理由或大纲 | 该方向的脚本、提示词和检查 | 不自动重写，用户点「按此方向更新」 |
| 只改变选用状态 | 导出集合和对应检查范围；新选且无内容的方案待生成 | 其他方案内容保留 |
| 一段脚本台词或时间 | 本段提示词、全片汇总、连续性和检查 | 其余段落保留，必要时提示相邻衔接问题 |
| 一段提示词文字 | 本段及相关连续性检查 | 不反向重写已确认脚本 |
| 绑定参考图或改变图的用途 | 引用该图的镜头和检查 | 未受影响部分保留 |
| 改项目名称、切换查看方案 | 显示信息或视图状态 | 不触发 AI 调用 |

AI 任务开始前固定输入快照、采用版本、目标范围、模型与配置版本。结果回来时若发现基线已改变，保存为候选结果，提示比较；不得覆盖用户后续编辑。

局部任务由服务端验证实际修改范围。AI 返回其他方案、其他段落或未经允许的事实/时长变动时，拒绝应用，保留原稿。

历史版本可查看和恢复；恢复生成一个新版本，保留原记录。脚本阶段和完整提示词阶段分别维护检查结果，其有效性绑定内容指纹与版本。

## 7. 任务、费用和异常体验

### 7.1 开始前看清调用范围

四套脚本通常涉及商品分析、方向策划及逐方向脚本调用；细化提示词、检查、局部修正还会产生后续调用。拆图分析和拆分长内容也会增加次数。

确认面板应列明任务组成、预估范围和预算上限，不用一个虚构的固定价格概括全部流程。报价不可得时明确显示「暂无法预估」，由用户决定是否在可执行的预算控制下继续。

复用现有计费口径：初和与 Token01 分别展示余额，算力与人民币按各自单位记录。提示词策划费用与视频生成费用分开；切换视图、编辑文本和带入草稿不产生模型调用费用。

预算不足时暂停后续阶段，保留已完成结果；提高预算后从未完成阶段继续。费用暂未查到时显示「费用待核实」，不按零费用处理。

预算控制负责限制后续提交，并为已提交但费用未返回的请求预留额度；若上游不提供硬性消费上限，界面不能将本地预算描述为可保证的最终扣费封顶。

### 7.2 执行和恢复

复用现有辅助队列，并发 1。页面显示真实阶段，例如「提取商品依据 → 策划 4 个方向 → 生成脚本 2/4」；不知道整体完成度时不制造百分比。

- 生成中可离开页面，返回后继续查看后台任务。
- 已完成方向独立保存，后续某方向失败不清空前面的成果。
- 服务重启后，未提交阶段可续跑；已提交阶段先核实接单状态。
- 继续沿用幂等键及上游任务 ID 持久化，`unknown` 状态先核实，不自动重发 POST。
- 格式不合法先做本地解析和校验；若需再调用模型修复，明确计入预算，不隐藏循环重试。
- 「取消」只停止尚未提交的步骤；已提交请求不能保证撤销或不计费，应继续核实结果与费用。
- 临时拥挤显示「繁忙，可稍后重试」，权限失效显示重新配置入口；离线仅用于真实连接断开。

交互采用轻量过渡，支持减少动态效果设置；不逐字播放长文拖慢审阅。错误就近显示并定位字段，成功提示不会抢走正在编辑的焦点。

## 8. 实现方案

### 8.1 结构化领域数据

工作台使用独立数据结构，模板中心只接收可复用的交付内容。

| 实体 | 建议关键字段 |
| --- | --- |
| PromptProject | id、name、可选 catalogProductId、商品资料快照及 revision、素材用途绑定 |
| PromptCreation | id、projectId、brief、当前 draftRevision / contentRevision、阶段状态、选用方向 |
| Source / Claim | 来源类型、原文/图片转录、内容哈希；事实文本、状态、限定条件、原文引用 |
| Direction | 人群、场景、购买理由、钩子、表达、大纲、差异、claimIds、selected、primary |
| ScriptPlan / Segment / Shot | 全片与分段时间、画面、动作、机位、台词、创作意图及依据 |
| PromptSegment | 六模块、镜头、refs、continuity、intent、关联脚本版本 |
| CreationVersion | 不可变成果快照、父版本、修改范围、来源、创建时间 |
| StageJob | 阶段、目标方向/段、输入版本及指纹、幂等键、关联 analysisJobId、预算、状态、费用 |
| Review | 脚本/提示词检查范围、版本与内容指纹、检查规则版本、issues |
| Handoff | 输出版本、方向与段、目标模型配置、兼容结果、草稿/媒体任务引用 |

底层可以复用现有 SQLite `documents(kind,id,value)` 存储及事务机制，新增工作台专属 kind。图片继续用现有素材实体；不要复制出第二套媒体库。

### 8.2 服务与 AI 编排

建议新建工作台服务，调用公共 AI 辅助能力，按阶段使用独立提示词和结构化输出 schema。

```text
工作台页面
  → 项目 / 草稿 / 版本服务
  → 阶段编排器
      → 输入快照、能力与预算检查
      → 现有 AI 辅助队列和调用层
      → JSON/schema、事实引用、时间与局部范围校验
      → 保存成果或候选结果
      → 标记依赖、更新任务和费用
  → 编译与交付适配器
      → 整片 / 分段文本
      → 模板中心
      → 视频生成草稿
```

现有 `analysisInputSchema.action` 还没有这五个阶段，应增加工作台专属 action 和输出解析，或提供专属服务调用公共 transport。不能把整个流程伪装成一次「润色」调用，也不借用依赖同行素材数量的商品研究前置条件。

模型提供方未必支持原插件的 `outputSchema` 协议，适配层需要能力检查和服务端 Zod 校验。引用原文是否存在、镜头时间是否连续、目标段是否越界，尽量由确定性规则验证；AI 负责语义检查。

### 8.3 API 草案

以下为建议的新接口，并非当前系统已存在的接口。

| 接口 | 用途 |
| --- | --- |
| `GET /api/prompt-workbench/projects` | 搜索和分页项目列表 |
| `POST /api/prompt-workbench/projects` | 独立新建或从商品工坊快照创建 |
| `GET /api/prompt-workbench/projects/:id` | 项目详情及创作记录 |
| `POST /api/prompt-workbench/projects/:id/creations` | 新建一轮创作 |
| `PATCH /api/prompt-workbench/creations/:id/draft` | 带 expectedRevision 自动保存草稿 |
| `POST /api/prompt-workbench/creations/:id/versions` | 应用修改为成果版本 |
| `POST /api/prompt-workbench/creations/:id/estimate` | 按阶段、方案和素材范围估算调用及预算 |
| `POST /api/prompt-workbench/creations/:id/jobs` | 固定 inputRevision、requestId、stage、target 和预算发起任务 |
| `GET /api/prompt-workbench/jobs/:id` | 阶段状态、部分成果和费用 |
| `POST /api/prompt-workbench/jobs/:id/cancel` | 停止未提交的后续步骤 |
| `POST /api/prompt-workbench/creations/:id/reviews` | 针对当前成果发起脚本或提示词检查 |
| `POST /api/prompt-workbench/creations/:id/export` | 指定版本、选用方向、整片/分段、格式与草稿标识 |
| `POST /api/prompt-workbench/creations/:id/handoff` | 兼容检查后创建生成草稿，返回定位信息 |

冲突返回可识别的 409，保留本地编辑并提供比较/重新加载。模板保存沿用现有接口，由适配器补充来源。

### 8.4 与现有模块连接

| 现有文件或模块 | 建议改动 |
| --- | --- |
| `src/App.tsx` | 智能体导航新增入口、路由、标题和帮助定位 |
| `src/components/prompt-workbench/`（新增） | 项目列表、六步工作区、方向、脚本、提示词、检查、版本比较 |
| `packages/prompt-workbench.ts`（新增） | 领域 schema、依赖与兼容检查、编译结构 |
| `apps/server/prompt-workbench.ts`（新增） | 项目、草稿、版本、任务编排及局部更新 |
| `apps/server/prompt-workbench-routes.ts`（新增） | 接口注册和输入校验 |
| `packages/analysis.ts`、`apps/server/analysis.ts` | 新阶段 action / 输出解析，继续复用模型、预算和调用记录 |
| 商品工坊 | 导入商品快照、可选项目关联及返回商品入口 |
| `packages/prompts.ts`、模板服务及界面 | 新增 workbench 来源及版本引用，接收可复用内容 |
| 视频生成 / 商品内容视频 | 接收兼容草稿和精确来源，保留现有模型报价与提交流程 |
| 全部任务、算力统计 | 展示策划任务入口、阶段详情和关联调用，避免费用重复统计 |
| 帮助中心、备份导出 | 增加工作台指南，验证项目、版本及媒体引用可恢复 |

模板当前限制包括主提示词/脚本各 16000 字符、最多 20 个镜头、单镜头提示词 6000 字符、设置时长最多 60 秒。应通过显式适配保存选中内容；超限时提示按段保存或导出文件，不静默截断完整项目。

保存模板前先编译工作台内部素材引用，区分素材占位与模板变量，避免被现有 `{{变量}}` 解析器误当成需要用户填写的参数；待补素材使用可读说明并保留结构化绑定信息。

商品工坊资料更新后，提示是否建立新的工作台快照，不自动改动已有已检查脚本。备份还需覆盖新增实体关系和素材引用，不能仅因为它们存于同一数据库就视为恢复已验证。

## 9. 实施顺序与验收

### 第一阶段：工作区与项目基础

完成独立入口、项目/创作记录、商品快照、素材角色、六步页面壳、自动保存与版本基础。此时先验证浏览、编辑和恢复，不对用户展示尚不存在的 AI 成果。

### 第二阶段：完整文字创作闭环

实现五个 AI 阶段、智能/逐步流程、卖点依据、多方案差异、脚本、六模块、整片/分段编译、局部修改、检查与文字导出。复用现有队列、能力验证及费用核实。

### 第三阶段：系统交付衔接

接模板中心、视频生成草稿、全部任务和算力统计，完善帮助、备份、兼容和异常测试。完成这一阶段，才作为第一版正式能力交付。

二期再考虑长片、多语言/平台适配、多段批量视频任务、拼接与字幕配音，以及真实投放表现回流。

### 首版验收重点

| 场景 | 应达到的结果 |
| --- | --- |
| 只有商品名、没有材质和优惠 | 可生成场景草稿，不杜撰属性，不强迫补满表单 |
| 商品资料相互冲突 | 标出冲突，后续不将该事实当成肯定式卖点 |
| 四套方向 | 至少在人群困扰、人物关系、钩子或叙事中有实质区别 |
| 9 张参考素材、单次分析上限 4 张 | 展示选择范围或分批调用，素材身份、来源及费用可追溯 |
| 只改第二套方案的一个段落 | 其他段与方案不被覆盖，相关提示词和检查正确失效 |
| AI 返回时用户已经改稿 | 保存为候选结果，用户可比较后应用 |
| 脚本已确认后细化提示词 | 台词、镜头和时间保持一致；越界结果被拒绝应用 |
| 修改后导出 | 旧检查不被复用为新版本通过；草稿导出有准确标识 |
| 只有缺图占位 | 可交付文字；实际视频生成按必需输入阻止不完整提交 |
| 模型不支持多图或整片时长 | 明确指出不兼容项，用户调整后才带入兼容草稿 |
| 重复点击、断网、服务重启 | 幂等与状态核实有效，不重复提交产生费用 |
| 第三套生成失败 | 前两套已完成内容保留，可从失败处继续 |
| 费用尚未返回、余额不足或分组失效 | 状态准确，保留成果，停止未经确认的后续调用 |
| 存模板、生成视频、备份恢复 | 来源和版本可回溯，不混淆策划成果与媒体任务 |
| 键盘与窄屏操作 | 步骤、方案和分段可用键盘切换，焦点可见，无主要控件遮挡 |

界面及端到端验收遵循用户规则：通过 BrowserOS neo 的可见界面模拟真实点击、输入、上传、滚动和返回，核对保存结果、版本与任务反馈。单元测试补充验证时间轴、引用编译、局部更新、依赖失效和幂等；不以直接接口请求替代界面操作验收。

## 10. 一个使用示例

用户从商品工坊导入「蓝色连帽外套」，资料只提供蓝色、连帽、前拉链及商品图片，没有材质、保暖等级、价格和促销。

1. 工作台提取已知外观与结构，把材质、价格等留作未知，不生成「防水」「零下保暖」「今日五折」。
2. 方向主推可为「早晨出门前的穿搭选择」；备选尝试出门准备剧情、日常搭配场景和细节观察，分别解释购买动机与展示依据。
3. 用户选择其中一套，检查口播与分镜。镜头展示真实可见结构，虚构日常人物不承担真实客户或专业身份背书。
4. 确认脚本后，生成每段的六模块提示词，绑定商品图；人物图缺失时保留明确占位或使用不依赖人物参考的表达。
5. 用户要求「把第二段的动作简化」，只修订这一段，更新相关提示词、连续性检查与版本。
6. 检查通过后导出，或选择兼容视频模型与已配置分组，将选中段带入生成草稿，再单独确认视频费用。
