# 商品套图、A+详情与爆款复刻统一方案

日期：2026-10-30  
状态：主体功能已实现，商品套图、A+详情与图片复刻已完成真实生成调用。视觉策划的真实结果未通过结构校验，仍待补齐验收。商品工坊产品编辑 UI 以基础信息页为准。

## 一、目标与命名

将商品内容制作分为三项能力：**商品套图、A+详情、爆款复刻**。外层图片创作与商品工坊使用相同的配置、生成计划和任务服务，区别在于商品资料的获取方式。

| 位置 | 当前入口 | 调整后 | 功能定位 |
| --- | --- | --- | --- |
| 外层 → 图片创作 | 当前名为“爆款复刻”的入口 | 商品套图 | 根据商品资料和套图结构制作一整组图片 |
| 外层 → 图片创作 | 详情图设计 | A+详情 | 按模块编排一套连贯的商品详情 |
| 外层 → 图片创作 | 单图／逐图对标能力 | 爆款复刻 | 上传同行图，按选定类型和复刻程度逐图生成 |
| 商品工坊 → 产品编辑 | 主图／主图制作 | 商品套图 | 自动带入当前商品资料，制作并管理套图 |
| 商品工坊 → 产品编辑 | 详情页／详情页制作 | A+详情 | 自动带入当前商品资料，制作并管理详情 |
| 商品工坊 → 内容创作 → 图文 | 逐图复刻 | 爆款复刻 | 保留整组图文的标题、正文和页序，使用统一复刻能力 |

**命名解释：**原“爆款复刻”改为“商品套图”之后，外层仍须保留一个真正的“爆款复刻”入口，复用现有单图／一键对标能力。不能把旧复刻任务直接解释成商品套图任务。

商品工坊的顶层结构继续为“产品编辑｜内容创作｜爆款复刻”。其中顶层“爆款复刻”仍承担视频逐镜头制作；页面标题和任务标签注明“视频”，与本次“图片爆款复刻”区分。本轮不将图片功能混入视频流水线。

## 二、两种入口，共用一套制作能力

### 2.1 资料来源

| 项目 | 外层图片创作 | 商品工坊 |
| --- | --- | --- |
| 商品原图 | 用户上传、粘贴或从素材库选择 | 自动读取当前商品原图，默认不要求重新上传 |
| 名称与类目 | 手动填写，可主动 AI 辅助 | 带入商品名称、类目和已有资料 |
| 卖点与参数 | 用户填写，未知项不补造 | 带入已保存卖点、参数及来源状态 |
| 颜色、尺码与 SKU | 按需手动补充与绑定 | 读取真实颜色、尺码、SKU 及图片关系 |
| 售价与品牌资料 | 按需填写 | 按需引用；批发成本不能自动当销售价格 |
| 成品使用 | 保存任务、下载、存为模板 | 保存候选，明确采用后进入商品预览 |

商品工坊提供可折叠的“已带入商品资料”：展示采用了哪些原图、参数与 SKU，可选择本次使用范围、修正要求或补充资料。生成前保留完整商品修订快照，不能在后台执行时读取已变化的商品值。

“自动带入”不表示把全部图片、全部 SKU 都发送给模型。按照当前输出项选择相符的图片和参数，显示实际参与生成的素材；超出模型限制时要求用户调整，不静默漏图。

来源参数、用户填写内容和用户核实事实需要区分。来源写明的面料、工艺和功能可以供核对，不能因被采集就标为“已核实”。商品原图、历史生成图和已采用图保留各自身份。

### 2.2 公共工作台

两种入口统一为**中间任务／结果列表＋右侧操作区**。商品工坊产品编辑保留按需打开的商品效果预览，避免同时常驻两条右栏。

- 右栏在 1280／1440／1920px 桌面宽度下分别沿用 480／520／560px；窄桌面收起全局导航。
- 原图上下分组、组内横排，提供编号、移除和末尾添加；图片组不分成拥挤的两列。
- 生成参数直接展示，常用参数不再藏入额外弹窗。
- 右栏底部固定显示总图片数、报价状态与制作按钮；长表单内部滚动。
- 任务卡按整套展示，内部按类别／模块／原图展开；保留单张候选、失败状态和补做入口。
- 新结果不自动覆盖原图、已采用图片或已确认作品。

## 三、商品套图

### 3.1 右栏配置顺序

1. 商品原图与本次商品／SKU 范围。
2. 生成设置。
3. 商品卖点与生成要求。
4. 套图结构与卖点图版式。
5. 可选爆款风格分析、商品上架文案。
6. 输出清单、实际参考算力与制作入口。

### 3.2 商品原图与生成设置

外层建议上传同一商品不同角度的 1–6 张原图；如实际模型可接收的数量更少，应明确显示限制。商品工坊保存的原图不受此选择器限制，但单次生成仍受模型限制。

| 设置 | 默认值／规则 |
| --- | --- |
| 平台 | 抖音电商；其他平台通过可维护的规则配置开放 |
| 目标市场 | 中国；用于表达与场景适配 |
| 图片文字语言 | 简体中文；支持的其他语言以中文名称显示 |
| 比例 | 建议默认 1:1，提供模型支持的 1:1、3:4、4:3、9:16、16:9 等 |
| 分辨率 | 建议默认 2K；只有实际模型支持时可选，支持 1K／2K／4K 的模型展示对应档位 |
| 图片模型 | 复用现有已配置、已启用的真实图片模型 |
| 制作组数 | 默认一组；首版可仅开放一组，避免与结构内张数混淆 |

平台规则必须有版本，不凭页面文案承诺“符合全部平台规范”。未维护某个平台的精确限制时，界面只能称“面向该平台设计”，并提供导出前检查。

“商品卖点与生成要求”可以填写名称、核心卖点、适用人群、使用场景、风格、人物与文案要求。AI 帮写使用小图标，点击即执行，保留失败原文、修改记录和撤销，不追加二次确认弹窗。

### 3.3 套图结构与数量

以下是本次确定的最小数量，不允许减到下限以下：

| 类别 | 最少张数 | 默认张数 | 内容 |
| --- | ---: | ---: | --- |
| 白底图 | 0 | 0 | 干净背景的商品展示，是否无字由平台规则和用户要求决定 |
| 卖点图 | 3 | 3 | 一个主卖点一张图，可应用选定版式 |
| 场景图 | 2 | 2 | 使用、穿搭、生活或消费场景 |
| 其他 | 2 | 2 | 按商品资料匹配细节、角度、规格、搭配、包装等 |
| 合计 | **7** | **7** | 白底图为零时仍至少输出 7 张 |

合计公式：`白底图 + 卖点图 + 场景图 + 其他`。增加组数后再乘组数。所有数量共同受系统单批上限限制，后端与前端执行相同校验；不得静默减张或截断。

“其他”不能是不可解释的随机图。报价前显示两张及以上的具体用途，例如“领口细节”“背面版型”；可按已有类目规则推荐，用户可调整。没有尺码数据时不能自动安排一张虚构尺码表。

每个输出位置有稳定 ID，保存类别、用途、资料依据、商品／SKU 范围、版式、局部要求与排序。调整数量不能使已保存候选错绑到另一张图。

### 3.4 卖点图版式参考库

将参考页面的“选择卖点图版式”整理为系统内的版式选择器，并作为模板中心的兼容图片子类型供管理。

**选择器布局：**固定大小弹窗，左侧版式预览网格、右侧已选列表与剩余名额，底部“应用 N 个版式”。弹窗外框在图片载入后不改变大小；内容区域独立滚动。

- 支持多选，选择数上限为当前卖点图张数，每种选中版式默认生成一张。
- 例如卖点图 3 张、已选 1 个版式：一张使用该版式，其余两张按整组风格和卖点分配；界面明确显示补齐数量。
- 未选择版式也能生成，按公共设计要求组织；不强制额外调用分析模型。
- 减少卖点图张数导致已选数超限时，提示用户调整选择，不能偷偷移除版式。
- 点击卡片勾选，独立预览入口查看大图；保留键盘操作和可辨识选中状态。

每个版式保存：中文名称、预览图、适用类目、布局结构、标题／副标题／卖点区域、商品展示位置、文字密度、可变字段、兼容比例和版本。

版式选择后展示“将如何使用”：默认提取结构、布局和表达规则；若原图作为视觉参考真正发送给模型，须标明其角色并计入附件配额。效果示例不能在用户无感知时变成商品外观依据。

**导入要求：**后续开发阶段核验参考页完整清单，下载可获取的有效预览，重建可编辑的版式描述，完成去重、版本和分类验证。不得把截图中可见的几张当作全部版式，也不得声称获取了对方未公开的原始提示词或模板工程。

本系统面向用户的模板名称、描述、标签和预览说明使用自己的中文命名，不加入第三方网站名、URL 或来源宣传文字；内部导入审计独立保存。素材图如含第三方网站水印或品牌宣传，不能直接作为本系统默认展示图，应更换或重新制作示意。

### 3.5 爆款风格分析 Skill

新增应用内技能建议命名：**商品视觉策划**，入口仍使用用户熟悉的“爆款风格分析”。它是应用分析能力，不依赖用户安装 Codex Skill；实施时以版本化 Skill 文档与结构化输出协议保存。

#### 输入

- 当前商品原图、商品名称、类目。
- 已有卖点、参数、目标市场、人群和平台。
- 有则传入当前 SKU、已绑定规格图及用户确认事实。
- 用户选定的版式及可选同行风格参考。
- 本次套图结构与用户补充要求。

图片分析沿用现有每次至多四图的限制与预览合成规则；更多原图先由用户选定分析范围，不能静默遗漏。文字商品资料按来源和字段一并传入。

#### 分析与输出

以“电商运营＋商品视觉设计”的视角形成可编辑策划：

1. 商品可见特征、资料中的明确事实及待补充项。
2. 用户购买动机与建议表达，标为策略建议。
3. 建议的主风格，以及可选替代方向；说明适合当前商品的理由。
4. 场景、人物可见造型、姿态、光线、配色、构图、文字层级与避免事项。
5. 卖点图逐张主题及证据、场景图方案、“其他”图片的明确用途。
6. 商品颜色／SKU 的适用范围，以及缺失资料提示。
7. 可选的上架标题、卖点短句和简介。

“爆款”表示创作方向，不表示系统掌握销量或流量结论。没有真实表现数据时，不输出“已验证爆款风格”“预计转化率”等结论。

#### 调用与应用

- 默认关闭，只在用户点击“分析风格”时调用；启用开关本身不收费。
- 沿用系统辅助模型设置，默认 TT-6.1 sol，可在设置中切换 GEM；不增加必选模型下拉。
- 显示本次资料范围、当前模型、进行状态和独立费用；识图验证不通过则明确拦截。
- 完成后在侧栏内展示策划摘要，用户点击“应用到本套方案”后写入风格和逐图要求，不再弹出确认框；支持撤销。
- 运行期间的新输入不能被覆盖；切换商品后结果保留在原草稿分析记录，不写到新商品。
- 一次结果只应用一次，不触发图片生成，不自动重试付费分析。

**与 AI 帮写分工：**帮写负责润色现有要求；风格分析负责整套视觉策略和逐图分工，两个入口不合并。

### 3.6 商品上架文案

将截图中的附加功能保留为可选项，默认关闭。生成标题、卖点和简介时仅使用已有事实，不自动发布商品。用户开启后，提交摘要单独列出文字分析任务及费用；不能因制作图片而隐含调用。

## 四、A+详情

### 4.1 统一配置

外层“详情图设计”和商品工坊“详情页”均更名为“A+详情”。沿用同一套详情模块和排序逻辑，商品工坊只增加自动带入的商品资料。

操作区必须包含：

1. **商品原图**：外层上传，商品工坊自动带入并允许选择。
2. **生成设置**：平台、市场、语言、图片模型、比例、分辨率、详情模式。
3. **商品卖点与生成要求**：统一主要求，AI 帮写小图标。
4. **包含模块（多选）**：选择后进入有序屏列表，可重复添加同类型屏并填写局部要求。
5. **整套风格与输出摘要**：展示屏数、顺序、费用和制作入口。

首版建议仅提供“标准详情”模式；其他平台专用 A+ 规格只有在明确其模块尺寸与限制后开放。不能把“普通 A+”名称直接当作所有平台适用的规范。

### 4.2 模块

| 模块 | 作用 | 特别需要的资料 |
| --- | --- | --- |
| 首屏主视觉 | 交代商品和核心购买理由 | 商品名称、核心卖点 |
| 核心卖点图 | 一屏讲清一个价值 | 对应卖点与依据 |
| 使用场景图 | 展示实际使用／穿搭 | 场景与人物要求 |
| 多角度图 | 展示外形和结构 | 对应角度原图 |
| 场景氛围图 | 建立整套风格 | 场景和视觉要求 |
| 商品细节图 | 展示面料外观、缝线和结构 | 清晰细节原图 |
| 品牌故事图 | 表达品牌理念 | 用户提供的品牌资料 |
| 尺寸／容量／尺码图 | 精确说明规格 | 对应数值、单位、SKU 范围 |
| 效果对比图 | 表达有依据的差异 | 对比素材与条件 |
| 详细规格／参数表 | 展示参数 | 结构化商品参数 |
| 工艺制作图 | 说明制作或工艺 | 实际工艺资料 |
| 配件／赠品图 | 展示包含内容 | 实际配件和赠品清单 |
| 售后保障图 | 说明服务 | 实际服务政策 |
| 系列展示图 | 展示多色／多款关系 | 真实规格与图片绑定 |
| 商品成分图 | 说明成分 | 明确成分资料 |
| 使用建议图 | 使用、搭配、保养建议 | 适用方式与注意事项 |

建议初始选中截图中的六项：首屏主视觉、核心卖点图、使用场景图、多角度图、场景氛围图、商品细节图。缺少原图或明确资料的屏显示“待补充”，报价前校验；不能为凑齐默认屏数补造商品事实。

每个模块实例对应一张独立图片。多选决定初始屏集合，之后允许拖拽排序、重复类型、删除与单屏修改。总输出为“屏数 × 组数”，不再出现含糊的“数量 1”。

### 4.3 连贯设计与导出

- 整套共用配色、版式表达、商品识别和文字语言，各屏有自己的内容职责。
- SKU 参数屏明确适用颜色或规格，不能将某一规格的数据推广到全部商品。
- 精确尺寸、参数和成分优先采用结构化内容与确定性排版，避免依赖图像模型拼写数值。
- 每屏独立保存候选和采用状态；补做失败屏不重跑整套。
- 可下载独立图片，也可按用户确认顺序排成长图；导出前提示长图尺寸和文件大小。
- 商品工坊只将明确采用的详情屏同步至商品详情预览，长图导出不删除独立屏。

## 五、图片爆款复刻

### 5.1 统一能力

外层图片爆款复刻与商品工坊图文中的原“逐图复刻”使用同一套参考图编排、类型和程度规则。商品工坊保留图文作品特有的标题、正文、页序与版本；外层可只输出独立图片组。

输入顺序：商品图片 → 对标原图 → 复刻类型 → 复刻程度 → 替换对象与整组要求 → 逐图设置 → 生成参数。

同行图可多张、可勾选；一张勾选图对应一个稳定输出位置。沿用当前最多 20 张及系统批次限制。每项只发送对应同行图和有效商品图，不将整组同行图发送给每个请求。

### 5.2 新增复刻类型

| 类型 | 主要设计关注 |
| --- | --- |
| 电商商品图 | 商品展示、卖点、细节和购买信息 |
| 服饰电商图 | 穿搭、人物姿态、衣服版型、面料可见纹理与颜色 |
| 营销海报 | 活动主题、主次信息和促销层级，金额与日期须用户提供 |
| 社媒图文 | 封面吸引力、内容页节奏和信息可读性 |
| 创意海报 | 视觉概念、场景与情绪表达 |
| 其他 | 以用户输入的用途和替换要求为准 |

建议默认“电商商品图”；商品工坊已明确为服饰类目时可预选“服饰电商图”，允许修改。不得为了识别类型自动调用分析模型。

### 5.3 新增复刻程度

| 选项 | 面向用户的说明 | 生成约束 |
| --- | --- | --- |
| 参考风格 | 参考整体风格和结构，自动调整色彩和重构场景。 | 保留表达方向，允许构图、色彩、场景和细节重新设计 |
| 高度复刻 | 参照参考图视觉结构替换产品和文案，场景细节略有差异。 | 优先保留主体位置、机位、人物姿态、布局与光影关系，按自有商品和指定文案替换 |

建议默认“高度复刻”，与原逐图替换目标一致；两项用可直接点击的说明卡展示，不再隐藏说明。

无论选择哪一档，商品外观、颜色、标识和结构均以自有商品图为准；原图的价格、功效、销量、认证与品牌承诺不自动继承。未提供新文案时默认移除旧宣传文案，允许明确选择新文案处理方式。

“高度复刻”不承诺人物身份、尾部细节或像素完全一致，实际结果由用户预览决定。复刻类型和程度都是图片请求的明确约束，不强制先分析再出图。

### 5.4 逐图设置

继承现有逐图折叠行，每项保留原图编号、是否参与、本图商品参考、替换对象和局部要求。公共类型与程度整组生效，首版不增加逐图覆盖，减少操作复杂度。

报价前替换对象必填，例如“模特身上的上衣”“右下角包袋”“领口细节”。修改勾选、商品绑定、复刻程度、类型或文字要求均使旧报价失效。

## 六、商品工坊的资料适配与采用

商品资料是制作依据，不应仅被拼成一段长提示词。建议新增统一商品创作上下文，按用途投影：

| 输出用途 | 应使用资料 | 保护规则 |
| --- | --- | --- |
| 通用卖点图 | 商品图、名称、已确认卖点 | 不把成本、未核实功效写入文案 |
| 服饰场景图 | 对应颜色图、穿搭方向、可见版型 | 不混合不同颜色或款式 |
| 尺码／规格屏 | 当前选中规格及准确数值 | 保留单位与适用范围 |
| 系列展示图 | 真实颜色与各自原图 | 缺图规格标明待补充 |
| SKU 图 | 颜色／SKU 绑定及本图要求 | 不改变 SKU 编号、价格与规格事实 |

默认先为当前选定商品／颜色制作一套，不自动为全部 SKU 做笛卡尔积。选择“按颜色分别制作”时，先显示明确的套数、输出数和报价，再由用户提交；共用同颜色图片的尺码不重复出图。

商品套图的白底图、卖点图、场景图和其他图，不应全部自动挤入原主图位置。候选保存自己的类别，用户选择主图展示顺序；SKU 绑定和详情采用分别处理。

## 七、技术落点与历史兼容

以下是建议的契约方向，正式开发需与现有类型和数据迁移方案核对。

### 7.1 复用边界

- `packages/contracts/index.ts`：扩展图片草稿、计划项及快照，保留现有 ID 和字段兼容。
- `packages/catalog.ts`：将商品用途 `main`、`detail` 的展示名调整为商品套图、A+详情；存储用途码不必随名称变化。
- `packages/prompts.ts`：扩展兼容的图片用途／版式信息，不将卖点版式伪装成完整图文作品。
- `apps/server/image-design.ts`：增加套图结构校验、逐图计划及详情模块计划的共用实现。
- 现有推广、分析、报价和真实媒体 worker：继续承担作品、AI 辅助和付费执行，不新建重复队列。

### 7.2 建议新增配置

| 配置 | 主要内容 |
| --- | --- |
| `productKit` | 分类张数、稳定输出槽位、逐图用途、卖点版式版本、风格策划引用 |
| `detailDesign` | 有序模块实例、事实依据、局部要求、整套风格、输出设置 |
| `replication` | 复刻类型、程度、文案处理、逐图原图与商品绑定 |
| `productContext` | 商品修订、选中颜色／SKU、事实状态、实际使用资料 |
| `layoutTemplate` | 兼容用途、预览、布局规则、变量和不可变版本 |
| 分析 Skill 配置 | 版本、输入契约、提示词、结构化输出校验和应用策略 |

草稿按“入口＋商品＋用途／模式”隔离。外层与商品工坊共用组件和计划逻辑，但不能共用同一份草稿。

### 7.3 历史处理

- UI 名称可更新，旧任务保留原技能、用途与输入快照，不改写执行语义。
- 原复刻草稿仍作为复刻草稿保留，不能直接按 7 张套图消费；提供“转入爆款复刻”入口。
- A+详情沿用旧详情屏 ID、顺序、事实字段和候选；仅补齐新设置默认值。
- 商品工坊原主图采用关系继续可读，不能强行分类成白底图或卖点图。
- 原 `replicate` 模式内部值可保留，展示名改为“爆款复刻”；旧模板仍能选用。
- 版本升级和模板导入幂等执行；不产生多余模板版本，不触发付费调用。

## 八、交互、加载与可靠性

- 页面初次载入用与真实布局一致的占位；状态说明水平居中，整区等待态完全居中，不能出现空白工作区。
- 上传卡片保持固定尺寸，展示居中的进度或错误与重试入口；失败不丢其他图片。
- 报价中在固定底栏显示居中的“正在查询报价”，保留总张数；无法报价时显示原因，禁止伪造数值。
- 分析期间只锁定重复分析操作，允许继续编辑；图片制作期间可准备下一套草稿。
- 下拉互斥，弹窗焦点可恢复；预览外框固定，支持滚轮缩放、拖拽和复位。
- 既有动效令牌沿用下拉约 240ms、抽屉约 320ms；任务状态原位更新，卡片悬停不整卡跳动，支持减少动态效果。
- AI 帮写直接执行、可撤销；风格策划内联查看后应用；付费图片提交仍保留明确报价和用户提交动作。
- 生成前、实际调度前检查真实余额与待结算占用，账户不足禁止继续提交。
- 单项失败保留成功图片；补做只针对用户选择项，新结果仍为候选。
- 付费请求幂等持久化；提交未知或重启不自动重复发送，不自动切模型。
- 显示真实任务状态与最终费用，不能以模拟图、估价或静态占位冒充已完成结果。

## 九、实施顺序与验收

### 第一阶段：统一配置与兼容

完成名称、两入口共用配置、商品资料投影、草稿隔离、套图数量校验、A+模块和复刻类型／程度。验证旧任务、模板和采用关系可读。

### 第二阶段：卖点版式库与视觉策划

核验并导入版式清单，提供选择器和版本化模板；实现商品视觉策划 Skill、内联结果应用和可选上架文案。效果示例与生成参考分别管理。

### 第三阶段：真实生成与交付

接通三个功能的真实计划、逐张费用、候选采用、补做与导出，完成桌面验收。

| 验收项 | 通过标准 |
| --- | --- |
| 最小套图 | 默认 0＋3＋2＋2＝7 张，下限前后端一致；超批次明确拦截 |
| 版式应用 | 选中数与卖点数一致校验，未选位置按约定补齐，实际附件角色可查 |
| 风格分析 | 仅主动调用，分析依据明确，无虚构流量结论，迟到结果不覆盖输入 |
| 商品适配 | 无需重传原图，使用正确颜色／SKU 和修订，未知资料不编造 |
| A+详情 | 多选、重复模块、排序、事实校验、单屏补做和长图顺序正确 |
| 爆款复刻 | 六类、两档生效，图与结果一一绑定，不误用他款事实 |
| 价格与安全 | 真实报价、余额拦截、报价失效、重复点击与提交未知可恢复 |
| 候选与采用 | 生成不自动替换主图、详情、SKU 或确认作品 |
| 历史兼容 | 旧复刻不转套图，旧详情与主图不丢失，导入重复执行不新增重复项 |
| 桌面体验 | 1280／1440／1920px 无横向溢出，固定入口、居中状态、下拉互斥及图片预览正常 |
| 最终验证 | 自动化和生产构建通过；真实商品分别完成套图、A+与复刻，保留文件、任务号与费用记录 |
