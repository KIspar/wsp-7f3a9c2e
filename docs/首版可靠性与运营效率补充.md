# AI 创作工作台：首版可靠性与运营效率补充

日期：2026-10-28  
状态：依据用户“优化方案”要求纳入首版设计；仅完善文档，未开发程序或调用真实生成。本文细化既有五个入口，不增加新的业务入口。

## 1. 优先级与范围

首版继续为图片生成、模特换装、场景复刻、视频生成、一键对标。普通技能保留紧凑结果流和发送后初始化，智能体保留独立流程；无灵感库、视频解析智能体或多人系统。

| 优先级 | 补齐内容 | 完成依据 |
| --- | --- | --- |
| P0 | 接单与草稿消费、失败分类、提交核实、结果保存、统计幂等 | 断线、崩溃、重复请求不会静默丢输入或重复付费提交 |
| P0 | 素材引用保护、磁盘不足处理、备份恢复、Windows 启动升级 | 历史媒体能恢复，已受理任务不会因升级和恢复重新生成 |
| P1（首版内） | 使用本次设置、技能发布预览、批次公平调度、结果查找 | 连续操作不用重复整理素材，小批次可获得新空闲槽 |
| 后续 | 链接导入、视频分析、收藏与灵感库 | 本轮不增加接口实现、依赖或页面 |

P0 先通过模拟供应商和故障测试，再进行付费生成验证；P1 随首版完整闭环交付，不能用新增入口代替可靠性建设。

## 2. 输入复用与发送后清空并存

普通技能成功接单后仍全量初始化底部输入区。任务详情提供“使用本次设置”，将某次历史尝试的商品图、补充要求、技能字段、引用角色、模型参数与提示词覆盖填入该技能的新草稿；此操作不生成、不计点。

- 当前已有未提交编辑时，先保留该草稿，并要求用户明确替换，不能静默覆盖。
- 恢复后显示来源任务；引用缺失、技能已归档、模型已不可用时逐项提示，用户修正后才能发送。
- 旧模板未改变时可直接回填；模板修订不同则展示原执行稿和新版差异，由用户明确采用当前技能，必要时将旧稿用作本次覆盖。不自动把旧变量套进新 Schema。
- 模型切换只迁移合法交集参数；回填不保证随机生成能逐像素重现旧结果。
- 发送时重新校验、估算并创建新任务；历史尝试、费用与结果不修改。

“使用本次设置”放在任务详情，普通卡片默认仍只显示用户确定的状态、步骤、缩略图、打包下载和 item 三项操作。

## 3. 三种恢复语义，避免重复调用

| 动作/情况 | 后端处理 | 本机点数 |
| --- | --- | --- |
| 重新生成 | 用户明确要求新成品，为指定 item 新建尝试，保留历史；不重跑其他 item | 新结果可靠保存后按本次规则统计 |
| 明确未受理/生成明确失败后的重试 | 确认可重试后为失败项建立关联的新提交尝试，独立幂等标识；不覆盖失败记录 | 成功保存后统计；原明确失败不计 |
| 上游成功但下载、校验或落盘失败 | 恢复原尝试的下载/保存检查点；必要时重新查询结果链接 | 不创建新生成费用；同一尝试保存成功只计一次 |
| 受理结果未知 | 核实原请求，补上游 ID、导入对应产物或记录未受理依据后解锁 | 单列待核实；不因超时直接再次付费提交 |

恢复下载可自动退避重试；新的付费生成首版只在用户明确启动后提交。供应商明确表示未受理的限流响应可按合同重试同一提交，模糊的超时/连接中断不能当作未受理。

再次生成必须绕过成品缓存，不能用旧图冒充新结果。若模型支持 seed，提供明确的“沿用/更换种子”选择；沿用可能产生相似结果，系统不保证新尝试一定有视觉差异。未验证 seed 能力时不添加虚假控制。

白底缓存仅在独立白底操作中按商品输入、提示词/技能修订、模型配置和最终参数准确匹配，可提示复用已有结果；用户明确重做时绕过缓存。查询、下载、打包和历史引用不属于新的生成。

## 4. 服装商品与替换对象

一批默认一件自有商品；款式、颜色/SKU 标识可以简填或自动生成批次内编号，不强制先创建商品档案。同款不同角度属于一组，不同颜色/SKU 不自动混用；多款组合后续提供明确配对，不做隐式全组合。

每批/每项保存：商品素材 ID 与角色顺序、替换部位（上衣/裤子/整套或其他明确对象）、整件/图案颜色模式、人物目标说明、新文案策略及逐项覆盖。必要字段从技能 Schema 展示，不依赖模型从文件名或上传顺序猜测。

原商品图为款式依据，白底仅辅助；不可见的背面、尺码、面料性能不由系统补成事实。多人物或多商品时由用户说明对象，首版不增加 AI 视觉预检。执行快照保存实际映射，错误可追溯到具体输入。

## 5. 队列公平性与资源分离

图片全局活动生成默认 20，可修改并受已知供应商/模型上限约束；视频独立配置。将原先“就绪项全局按创建时间”细化为：**在兼容当前空闲槽的就绪批次之间轮流派发，每轮每批领取一项，批内按创建顺序**。仅一批就绪时可用满全部可用槽，不为公平性留空。

- 新批次进入下一轮调度，不插入或取消已提交上游的尝试；20 个在途项占满时仍需等待真实空闲。
- 等待白底、待用户处理和待核实项不阻塞后面的就绪项；未知项的供应商实际活动数单列风险，不宣称能保证上游绝无超限。
- 同一批次拆成多个 item 不产生多个独立 20 并发池；白底操作仍共享图片上限。
- 上传、封面/缩略图处理、上游查询、结果下载与打包分别采用有界资源池；生成满槽不能导致查询停止或结果无人保存。
- 结果保存优先于低优先级封面和导出作业。下载采用流式、受限缓存，ZIP 不一次读入全部媒体。
- 下调并发不取消在途任务；退避与临时不可调度的模型不阻塞其他供应商。单机 Worker 重启仍按持久化状态恢复。

验收例：A 已有 100 项，B 新增 1 项；空闲槽出现后 B 能在轮转中获得调度，不必等 A 的未提交项全部完成。该规则替代单纯全局 FIFO。

## 6. 文件可靠性与磁盘不足

任务快照只引用已完成上传的本地素材 ID，不引用浏览器临时 URL 或下载目录中的原路径。上传后复制/保存到应用数据目录，记录哈希、类型、大小及媒体基本信息；原文件移动不破坏任务。

新付费提交前检查数据目录可写和剩余空间。软预警只提醒；明确不可写或低于可配置安全底线时暂停新的付费提交，提示清理空间后继续，不取消已受理任务。这是结果保存条件，不是算力余额门禁；预检不能保证生成期间不会被其他程序占满磁盘。

上游成功但本地保存失败时保留上游编号、可用结果链接和失败检查点，显示“待保存”。链接过期先重新查询供应商；不可恢复时显示需要人工处理，不擅自重新生成。只有原始产物校验并可靠落盘后才完成和计点，缩略图/封面制作失败可独立恢复，不应重新生成媒体。

结果文件写临时路径、完整性与可解码性检查、原子落盘，再事务关联任务/产物/消耗/事件。存在文件已落盘而事务未完成的窗口，重启按稳定产物 ID 和哈希核对，避免孤儿文件、重复导入及重复计点。基础检查验证类型、可读取性、尺寸/时长等合同要求，不冒充商品质量审核。

删除行为分开：

| 操作 | 范围 |
| --- | --- |
| 输入区移除缩略图 | 仅取消本次草稿选择，不删除文件或任务引用 |
| 清理缓存 | 可重建缩略图、过期 ZIP、无引用临时文件；排除在用文件和上传中的数据 |
| 删除历史产物 | 明确列出影响，先检查任务、白底依赖与历史引用；被引用的不物理删除 |

首版不自动清除原始素材与历史成品。清理先给出范围与空间预估，保留账本和尝试记录；物理清理由后端执行，不用前端直接删路径。

## 7. 技能与模型配置发布

技能设置保留“编辑 → 校验 → 预览 → 发布”，预览必须展示：用户表单、输入角色与数量、批量展开数、最终提示词示例、模型兼容性、固定参数和预计点数。预览使用本地模板渲染，不额外调用文本模型。

固定示例覆盖单项、多项、可选白底、缺失必填和超引用场景。模板变量不存在、配置成环、参数冲突时定位文件与字段；发布失败不影响上一修订。业务确定规则与模型合同分别检查，不把配置能解析等同于接口已经验证。

技能或模型更新不改运行中快照。历史再生成若原模型已禁用/上游能力失效，要求显式选兼容模型并显示输入变化，不自动换成别的供应商或更贵型号；凭证可更新受保护的引用，不把旧明文密钥塞入历史。

## 8. 完整备份、升级与恢复

数据库一致性备份只是完整备份的一部分。完整备份包括数据库、被引用的原素材与成品、技能发布快照和编辑文件、模型/算力配置、程序与迁移版本清单、文件校验清单。可重建缓存和诊断日志可排除，界面说明范围。备份目录不能被递归打包进自己。

首版以明确的维护窗口实现完整备份：停止领取新的付费提交和应用写操作，等待正在进行的上传/落盘/事务到稳定检查点；在途上游生成可继续，保留已持久化 ID，备份后恢复查询。未知提交不强行宣布已停止。期间不允许删除引用素材。数据库与媒体按同一检查点封存，并验证文件清单；未达到稳定状态则报告备份未完成，不能给出“成功”。

Windows 升级前建立可校验备份，程序与 data 分离；迁移可重复执行且版本明确。回退到不兼容旧程序时使用配套备份，不用旧程序直接打开新 Schema。

恢复在独立目录、Worker 暂不提交的状态下完成：验证数据库和媒体清单，再根据任务快照核对上游。恢复点以前的“排队”任务可能在备份之后已被原实例提交，不能直接自动重放；原实例须停止使用同一数据，恢复实例展示恢复时间并先核对这些不确定尝试，避免两份数据同时生成或重复扣费。

跨机器恢复时密钥需要重新配置/授权；受操作系统保护的凭证不保证可移植，备份中不放明文密钥。校验恢复成功至少包含历史可读、图片/视频可打开、点数一致和在途任务无重复提交。

## 9. 状态、诊断与结果查找

默认卡片维持简洁；任务详情统一呈现批次/item/尝试编号、实际模型、输入修订、排队/提交/上游等待/下载/保存耗时、请求次数、供应商 ID、点数和脱敏错误。后台状态区分 API 可访问、Worker 存活、实际可调度及上游连通，不用一个绿点代表所有环节。

普通技能结果流按游标分页，可用状态和日期筛选，按任务编号定位；不新增独立素材库或项目导航。查看历史、筛选和预览都不创建任务。诊断导出不包含密钥、鉴权头或带凭证的 URL。

## 10. 实施和验收顺序

1. **任务与数据底座**：技能/模型修订、素材落盘、草稿修订、接单幂等、后台执行与状态事件、尝试和点数事务。
2. **普通技能闭环**：四个普通技能输入、结果卡、媒体预览、参数矩阵、发送初始化、使用本次设置与单项再生成。
3. **智能体与调度**：一键对标三栏、白底独立动作、依赖重绑、轮转派发和资源池隔离。
4. **本地交付**：磁盘保护、清理、完整备份恢复、Windows 启动/停止/升级与诊断。
5. **验证**：Node 24 类型检查、构建、接口/恢复测试、桌面浏览器及真实 Windows 验收；真实付费测试另列调用预算与结果报告。

核心场景及预期：

| 场景 | 预期结果 |
| --- | --- |
| 后端接单成功、响应丢失，随后重发 | 原幂等标识核实并返回同任务，不丢草稿或重复创建 |
| 成功发送后延迟到达的自动保存 | 不能恢复已消费草稿，也不能覆盖下一条输入 |
| 图片完成，下载/磁盘失败 | 恢复原结果保存，无新增生成；成功后只计点一次 |
| 点击同项重新生成 | 新尝试、不命中旧成品缓存，原图和原完成度保留 |
| A 大批次与 B 单图批次 | 新空闲槽按轮转派发，B 不等待 A 所有排队项完成 |
| 白底失败、改用原商品图 | 只恢复所选未提交 item，其余任务不中断 |
| 模型禁用后使用历史设置 | 保留输入，要求明确选择兼容模型，无静默切换 |
| 缓存清理与生成同时发生 | 原始素材、历史及任务依赖不被误删 |
| 独立目录恢复旧备份 | 媒体可读、点数一致，备份后可能已提交的任务先核实 |
| Windows 中文/空格路径和重复启动 | 单实例后台可用，浏览器关闭任务继续，升级不丢 data |

质量样本包含纯色/复杂印花、不同版型、多人/遮挡等条件；记录商品/人物/场景/文字问题及人工可用率。性能记录操作次数、上传/排队/上游/保存耗时、请求数和成功保存数，不将供应商等待全部算为本机性能问题，不编造时间或质量通过率。

当前无运行程序，上述均为待实现、待测试要求。方案文档校验不能记为接口、浏览器、Windows 或生成质量已通过。
