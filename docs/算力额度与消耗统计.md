# 算力额度与消耗统计方案

> 历史方案：2026-10-29 用户已要求真实接口报价及余额不足禁止生成。当前生成准入以 [生成前真实算力报价](生成前真实算力报价-20261029.md) 为准；本文中的手工点数与非阻断提醒不再作为当前生成实现要求。

日期：2026-10-28  
状态：Q1/Q4 已确认：仅统计提醒，保存成功计点，明确失败不计点，未确认单列。尚未开发程序。

## 1. 已确认范围

后台设置统一的算力额度参考值及各图片/视频模型的点数规则，按模型、技能、日期与任务统计。**额度仅用于统计和余额提醒，不是强制预算，不因不足或超额禁止生成，也不停止后台任务。**

不实施冻结、预占、补足余额解锁、充值支付或可信商业扣费。当前文档替代此前的硬预算设计；删除冻结流程不是删除任务幂等、上游提交未知处理与用量核对。

本机算力点是后台规则计算的内部统计单位，与供应商人民币费用、上游余额、Token、GPU 利用率分开保存。重启、刷新和修改规则不能重置历史。

## 2. 设置与提醒

设置页“算力与统计”包括总参考额度、额度调整记录、各模型规则、统计筛选和待核实明细。额度调整是新的记录，不覆盖消耗流水；允许调整后出现负参考余额。

额度未设置时显示“未设置参考额度”；模型点数规则未配置时显示“该模型点数待配置”，保留次数、时长、关键参数与真实费用，**不按 0 点统计，也不因点数缺失拦截生成**。明确配置 0 点与未配置不同。

参考余额不足显示非阻断提醒，不重复弹强制确认框；正常生成按钮可用。实际供应商额度不足或 API 拒绝仍按真实上游错误处理，不能用本机余额替代上游状态。

## 3. 模型规则

首期支持按次与按视频生成秒统计。按秒基准是实际提交的合法时长，不是后期裁剪时长；每个尝试层向上取整为整数点。可配置唯一匹配的分辨率/时长等参数覆盖规则，否则使用基础规则。

规则保存时拒绝含糊重叠，规则缺失保留为未知统计，不猜单价。每次调整建立修订，尝试保留当时规则和最终参数；后来补规则只能通过明确的“补算”操作生成关联调整记录，不能静默重写历史。

统计示例而非真实价格：某模型每张 10 点，5 张已勾选目标、每图 2 版，默认原图直接替换为 10 次、100 点；使用已有白底图同样为 10 次；主动生成白底图且无缓存时为 11 次、110 点。未勾选目标不调用、不计点。

## 4. 预计消耗与任务记录

预览返回步骤、生成数量、模型与点数规则修订及计划哈希。正式提交重新校验输入、技能、模型与参数，事务保存任务、快照和事件；不读取余额作为执行门槛，不写冻结记录。

任务在后台持续执行。重复提交带幂等标识返回同一任务；同一生成尝试不会因查询、下载或回调重复计数。再次生成、新的真实重试分别保留尝试记录及额外预计消耗。

尚未确认点数规则的尝试记录用量事实和“点数未知”标记；汇总必须显示有多少项未计价，不能把已知点数小计冒充完整总消耗。预计消耗与已计消耗分别展示，不重复累加；进行中估算不是冻结。

## 5. 已确认：保存成功计点

结果可靠保存后，按该尝试锁定的模型规则计入本机点数；明确失败不计点。提交未知单列“待核实”，上游成功但下载/保存未完成列“待保存”，恢复完成后只计一次。供应商实际费用另存，不宣称失败不计本机点数等于上游退款。

调用生成白底图和点击一键替换是两个操作，各自有任务和预计点数。白底任务已在执行时，替换队列只统计后续替换请求，不能重复计算白底点数。整个创作记录汇总关联的白底任务一次，加上实际成功的替换尝试；跨批次复用同一白底任务不重复产生全局消耗。

依赖尚未满足的 item 只有预计消耗，不计已确认消耗，也不占生成并发。默认全局并发 20 下，账本仍以尝试唯一 ID 幂等写入，不能因多项同时完成漏计或重复。

质量沿用已确认原则：保存成功即生成完成，人工判断质量；不满意后再次生成是新尝试，保留原结果，不自动补生成。

## 6. 数据与幂等

必要记录：额度调整、模型规则修订、每个尝试的用量事实、已确认点数及关联调整流水。可使用 credit_accounts、credit_pricing_revisions、credit_usage、credit_ledger；首期无需 credit_reservations 或冻结账户。

流水关联任务、尝试、技能/模型/规则修订和上游编号，记录唯一操作标识。统计更新与任务/结果状态在同一数据库事务提交；重复查询、通知和重启不能增加相同消耗。

```text
参考额度 = 初始设置 + 后续调整净额
参考余额 = 参考额度 - 已确认净消耗
```

参考余额允许负值，代表超出参考额度，继续提醒且不阻止调用。进行中预计点数、待核实预计点数、未计价项目单列，不扣成冻结，不在总额中重复计算。

有争议的消耗记录用补算/冲正流水关联原记录，说明依据，原记录不删除。没有点数规则、已知失败、提交未知是不同情况，不能都显示为 0。

## 7. 页面与统计口径

首页显示参考余额、已确认消耗，点击打开统计。生成按钮旁显示预计点数；不足仍可提交。任务详情分开显示预计、已计、待核实/待保存，默认紧凑任务卡只显示状态、当前步骤、缩略图和结果操作；无冻结字段或补足余额操作。

设置页按模型、技能、日期、任务查看调用次数、成功/失败/未知、生成时长、已计点数、未计价数、供应商费用。智能体父任务聚合子尝试，不重复累加。历史查看、素材复用、有效缓存、下载和查询不是新的生成。

UTC 存时间，默认 Asia/Shanghai 查询。消耗按结果可靠保存并完成计点事务的时间归属日期；统计条件与 CSV 导出使用同一口径。模型或技能归档保留历史名称、ID 与快照。

## 8. 现有系统复用与建议接口

复用原系统 Model.price 和任务 estimate/actual 采集供应商费用，但不将人民币字段改成点数。供应商余额查询也不替代内部统计。

```text
GET  /api/credits/account              参考额度、余额、已确认消耗、未计价概况
POST /api/credits/adjustments          额度调整及原因、幂等标识
GET  /api/credits/pricing              模型点数规则
PUT  /api/credits/pricing/:modelId     带修订发布新规则
GET  /api/credits/statistics           筛选汇总
GET  /api/credits/ledger               分页明细和导出
```

统计由后端更新，不接受前端任意报“已消耗 X 点”。SSE 推送账户与统计修订，丢事件后重新读取快照。

## 9. 验收

- 额度为 0、参考余额为负、未设置额度或点数规则，均不因本机统计阻止生成。
- 缺失规则显示未知，显式 0 点可区分；补算必须留痕。
- 数量、时长与参数改变后更新估算，任务沿用提交快照；重启不重置历史。
- 并发任务和重复通知不重复记录；统计与流水相符。
- 对标仅计已选择目标；白底原图直用、已有/缓存、额外生成各自反映真实计划。
- 未知提交不自动重发；下载失败只恢复下载；真实生成重试记录新尝试。
- 保存成功只计一次；明确失败不计；待核实和待保存分别显示，不将它们默认为成功或失败。
- 单独白底任务被替换批次引用时不重复计点；20 并发完成时流水与模型汇总一致。
